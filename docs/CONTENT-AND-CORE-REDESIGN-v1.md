# 콘텐츠 확장·슬롯 실행·오브 성장 개편안

작성: 2026-10-28. **조사·설계 결과이며 게임에 적용한 내용이 아니다.**

사용자의 이번 요청과 응축 설명(“느리지만 크고 강한 한 발”)을 기준으로 작성했다. 현재 실행 기준은 `VS-SURVIVAL-RUN-v1.md`다. 본 문서의 제안이 승인·구현되기 전에는 기존 AGENTS.md의 실제 구현 상태를 바꾸지 않는다. DuckGame/MageGame 수정, 게임 실행, 새 그림 생성, 구매, 전체 검사, 실행파일 갱신은 하지 않았다.

## 1. 이번 결론

- 먼저 **고정 슬롯·부분 실행·오브별 데이터**를 고친다. 그 결과를 이용해 획득 UI를 만든 뒤 콘텐츠를 늘린다. UI 시안과 데이터 계약은 가장 먼저 확정한다.
- 첫 출시 콘텐츠 목표: **기본 마법 30종(공격 15/보조 11/연결 4), 완성 합성 24종(공격 12/보조 9/연결 3), 유물 24종, 일반 적 외형 12종**. 현재부터 추가할 것은 기본 12/합성 6/유물 12/일반 적 외형 9다. 보스 외형은 일반 12에 섞어 세지 않는다.
- 마법은 종류별 실물 하나, 중복 획득 시 +1, 최대 +3, 합성 완성형 무강화·종류별 한 판 1회, 부모 재획득을 유지한다. 종류 제한과 강화 보상 횟수는 다르다.
- 오브는 **1개로 시작해 최대 4개**, 각 기본 6칸·강화로 최대 8칸, 오브당 성장 선택 총 5회. 슬롯을 늘리는 선택은 최대 두 번이다.
- 조합의 잘못된 부분만 정지한다. 보조 범위는 연결 전후의 주문 묶음으로 명시하는 안을 권고한다. **마법공예의 완전 복제라고 주장하지 않는다.**
- 종료/휴식 일괄 회수는 돈만 준다. 평소 걸어서 주운 마석의 돈+XP는 유지한다.
- 마법 종류·몬스터 종류·4오브를 한 번에 늘리지 않는다. 후반 현재 성능부터 확인해야 한다.

### 문서/표시와 실제가 다른 부분

- 초기 +4/두 오브 고정/자동강화 없음/전투 보상 비정지 문서는 과거 기록이다. 현재 최신 성장 규칙을 기준으로 한다.
- `Relics.definition()`은 전부 `craft_pool=false`를 반환하지만, 현재 제작 로직은 유물을 판매한다. 입수처 표시는 실제 후보 생성과 같은 자료를 읽어야 한다.
- 공구함 설명에 이미 폐기한 수동 합치기/유료 합성 비용 문장이 남아 있다. 무료 상자 합성과 혼동되지 않게 고친다.
- 도망쟁이 구두는 피격 후 이동 가속이다. **무적 유물이 아니다.** 현재 피격 후 약 0.85초 무적은 플레이어 기본 동작이다.
- 적 외형은 현재 잎 슬라임·박쥐 임프·갑주 딱정벌레의 **3종**이다. 역할 변형과 딱정벌레 확대 보스를 새로운 원화로 세지 않는다.

## 3. 참고 규칙: 확인한 것과 미확인

### 마법공예

공개 커뮤니티의 [보조 순서 답변](https://steamcommunity.com/app/2103140/discussions/0/3937895062997699349/)은 툴팁 기준으로 오른쪽 공격에 적용되며 중간 빈칸/다른 칸이 있어도 된다고 설명한다. 2023년의 사용자 답변이므로 최신 전체 주문의 공식 규칙으로 확대하지 않는다.

[주문 동작 가이드](https://steamcommunity.com/sharedfiles/filedetails/?id=3477176826)는 방향성 강화, 오브 전체 성질, 후속 시전 종류를 구분한다. 작성자도 훈련장 관찰에 기반한 불완전한 설명임을 밝힌다. 따라서 “모든 보조가 자식에게 상속된다/절대 적용되지 않는다” 중 어느 쪽도 보편 법칙으로 확정하지 않는다. 페이지의 호환/삭제 경고도 있어 보조 자료로만 사용한다.

이번 조사만으로는 사용자가 기억한 한국어 **응축탄**의 정확한 영문/중문 ID와 모든 강화 수치를 확정하지 못했다. [개발자 로그의 Condensed Water Bubble](https://steamdb.info/patchnotes/13739030/)은 확인했지만, 이를 사용자가 말한 느리고 크고 강한 한 발과 동일시하지 않는다. 아래 응축안은 **사용자가 설명한 체감에 맞춘 우리 게임의 제안**이다.

### 뱀파이어 서바이벌 장신구

[장신구 목록](https://vampire.survivors.wiki/w/Passive_items)은 공격과 별도로 피해·이동·방어·성장·회수 같은 능력 축을 제공한다. 이를 참고해 기본 능력 계열을 보강하되, 원작의 장신구 6칸/최대 레벨/정확한 배율까지 가져오지는 않는다. 우리 유물은 일단 고유 1회 획득·추가 강화 없음이다.

## 4. 고정 슬롯과 부분 실행 설계

### 4.1 빈칸은 위치이며, 문법상 벽이 아니다

- 오브 자료: `uid, capacity, slots, upgrade_rank, upgrades`. `slots`는 capacity와 같은 길이이며 빈칸은 null. 토큰은 종류/단계와 별도의 인스턴스 식별자를 갖는다.
- 빈칸을 건너뛰고 왼쪽→오른쪽으로 해석한다. 빈칸은 추가 시전 지연이나 연결 끊기를 만들지 않는다. 경계는 연결 구체로만 만든다.
- 6번 칸에 별빛탄 하나를 두면 그 자리에서 정상 발사한다. 2/5번에 공격을 두면 두 공격이 순차 발사한다.
- 빈 곳에 드롭하면 정확히 그 칸에 이동한다. 다른 주문 위에 드롭하면 교환한다. 가방에서 드롭할 때 기존 주문은 가방으로 돌아간다. 다른 칸은 밀리지 않는다.
- 우클릭 해제는 해당 칸만 null로 만든다. 보상·제작·합성·되돌리기·저장도 같은 배열을 사용한다.
- 슬롯 수/구체 실물 소유/중복 참조를 검사하는 무결성 검증은 계속 필요하다. 문법 경고를 허용한다고 복제·수량 오류까지 허용하지 않는다.

### 4.2 컴파일 결과

`roots, nodes, edges, diagnostics, affected_slots, runnable_count`를 반환한다. 진단에는 `slot_uid/index, edge, code, reason, severity`를 넣는다. 문법 경고가 있어도 유효 roots를 반환한다.

UI는 “오브 2: 4번 연결 뒤에 공격이 없어 발동하지 않아요”처럼 **문제 위치+실행 결과**를 표시한다. 빨강은 잘못된 연결/주문, 회색은 실행되지 않는 보조, 정상 주문은 기존 밝기로 유지한다. 색 외에도 경고 표식과 문장을 쓴다.

| 배치 예 | 실행 | 경고 |
|---|---|---|
| `[빈][빈][빈][빈][빈][별빛탄]` | 별빛탄 | 없음 |
| `[별빛탄][빈][꽃폭탄][빈][빈][빈]` | 별빛탄→꽃폭탄 순차 | 없음 |
| `[별빛탄][명중 후][빈][꽃폭탄][빈][빈]` | 별빛탄 명중→꽃폭탄 | 없음 |
| `[별빛탄][명중 후][빈][빈][빈][빈]` | 별빛탄만 | 연결 뒤 공격 없음 |
| `[별빛탄][빈][갈래][빈][빈][빈]` | 별빛탄만 | 갈래의 대상 없음 |
| `[명중 후][별빛탄][빈][꽃폭탄][빈][빈]` | 별빛탄→꽃폭탄 | 선두 연결은 발동 주체 없음 |
| `[별빛탄][명중 후][소멸 후][꽃폭탄][벼락][빈]` | 별빛탄→벼락 순차 | 연속 연결 둘과 꽃폭탄 비활성. 잘못 연결한 꽃폭탄을 몰래 독립 발사하지 않음 |
| `[별빛탄][명중 후][갈래][꽃폭탄][소멸 후][벼락]` | 별빛탄→갈래 꽃폭탄→벼락 | 정상 다단계 |

연속 연결은 가장 가까운 후속 공격 하나를 오류 구역으로 묶고 그 다음 연결 없는 공격에서 다시 해석한다. 알 수 없는 구체는 해당 구역만 비활성화하고 원본 ID를 보존한다. 삭제/부품 교체로 자동 복구하지 않는다.

오브가 전부 비어도 게임 진행은 허용한다. 모든 공격이 실행 불가이면 “현재 발사되는 마법이 없어요” 경고와 편집 버튼을 주고, **계속 진행을 막지는 않는다**. 시험장에서는 무발사 사유를 바로 표시한다.

### 4.3 보조 범위 권고안: 연결로 묶음을 나눈다

**아직 구현하지 않은 규칙 변경 제안이다.** 현재의 전역 오른쪽 범위를 무조건 원작과 다르다고 판정하지 않는다. 다만 우리 게임에서는 한 구체의 적용 범위를 눈으로 보여주기 위해 아래 하나로 통일하는 안을 권고한다.

1. 보조는 **자신 오른쪽부터 다음 연결 구체 직전까지**의 공격에 적용한다.
2. 연결 뒤는 새 묶음이다. 후속을 바꾸려면 그 연결 뒤·후속 앞에 보조를 놓는다.
3. 빈칸은 묶음을 끊지 않는다. 연결 구체 자체는 보조의 공격 대상이 아니다.
4. 모든 일반 보조와 보조 합성에 같은 범위를 쓴다. “거대화만 다름” 같은 예외를 만들지 않는다.

예:

- `[거대화][별빛탄][꽃폭탄]`: 두 독립 공격이 커진다.
- `[거대화][별빛탄][명중 후][꽃폭탄]`: 큰 별빛탄→보통 꽃폭탄.
- `[별빛탄][명중 후][거대화][꽃폭탄]`: 보통 별빛탄→큰 꽃폭탄.
- `[갈래][별빛탄][명중 후][꽃폭탄]`: 갈래 별빛탄의 각 유효 명중에서 꽃폭탄. 꽃폭탄 자체가 다시 갈라지지는 않는다.
- `[메아리][별빛탄][명중 후][꽃폭탄]`: 시간차 별빛탄도 실제 주문이므로 자신의 첫 명중에서 꽃폭탄을 발동한다. 메아리 복제본이 자기 메아리를 다시 생성하지는 않는다.

**트레이드오프:** 보조 실물이 하나뿐이므로 부모와 자식 모두에 같은 보조를 놓을 수 없다. 이것은 현재보다 적용 범위가 좁아지는 설계다. 대신 어느 쪽에 둘지 선택이 생긴다. 전체 오브에 적용되는 유물은 별도로 부모/자식 모두에 작동한다. 이 차이를 숨긴 채 “기존과 동일”이라고 구현하면 안 된다. 사용자가 전역 오른쪽 범위를 선호하면 이 절만 승인 전에 변경해야 하며, 빈칸/부분 실행은 어느 안에서도 그대로 구현 가능하다.

### 4.4 사건·복제·계산 불변 조건

- 연결된 공격은 독립 순차 목록에서 제외한다. 원본 인스턴스별 첫 유효 명중 1회, 정상 종료 1회를 유지한다.
- 후속 위력 50/65/80/100%는 해당 연결의 **직접 자식**에 한 번 적용한다. 갈래/메아리/설치의 분배 예산은 후손까지 보존한다. 이를 없애면 기존 폭증 문제가 재발한다.
- 거대화·응축 등의 원본 값을 자식에 복사한 후 자식의 직접 보조를 다시 곱하지 않는다. 자식은 자기 묶음의 보조와 공통 시전자 스냅샷으로 계산한다.
- `_echo_copy` 같은 후손 전체 금지 플래그 대신 복제를 만든 `stage_uid`를 기록한다. 같은 단계의 복제 재복제는 금지하지만 다른 단계의 정상 사건을 통째로 막지 않는다.
- 강제 삭제, 시험 초기화, 웨이브/판 종료, 조합 재편집에 의한 청소는 소멸 사건이 아니다.
- 정적 그래프는 오른쪽 방향만 허용하므로 순환이 없다. 개별 공격·연결의 실제 인스턴스 증가량을 미리 계산/기록하고, 기존 안전 예산 초과는 측정 기록에 남긴다. 안전 상한으로 밸런스를 대신하지 않는다.
- 독립 순차 간격/오브 순환 대기/후속 지연을 별도 필드로 나눈다. 후속의 느린 공격은 그 후속에 비용을 배정한다. 부모 오브 순환에 추가 부하가 필요하면 숨기지 말고 연결의 “추가 순환 대기”로 명시한다. 이번 첫 구현에서는 기존 간격과의 비교 측정 없이 일괄 가속하지 않는다.

## 5. 응축 개편안

현재 응축은 기본부터 피해 ×3이지만 **비행 속도는 느려지지 않고 +0 크기는 그대로**여서 사용자가 말한 한 발의 인상이 약하다. 별개 새 공격을 늘리는 대신 기존 보조를 고친다.

플레이어 문장: **“공격이 느리게 펼쳐지지만, 더 크고 강해져요.”**

| 응축 단계 | 피해 | 크기/영역 반경 | 투사체 진행 속도 | 이 공격의 재시전 시간 | 첫 직접 밀침 |
|---|---:|---:|---:|---:|---:|
| 기본 | ×2.4 | ×1.30 | ×0.65 | ×2.0 | +20 |
| +1 | ×2.6 | ×1.45 | ×0.65 | ×2.0 | +30 |
| +2 | ×2.8 | ×1.60 | ×0.60 | ×2.0 | +45 |
| +3 | ×3.0 | ×1.80 | ×0.60 | ×2.0 | +60 |

수치는 초기 비교안이며 확정 밸런스가 아니다. 크기는 지름과 반경에 같은 선형 배율이며 면적은 제곱으로 커진다. ×2 피해만 보고 DPS라고 부르지 않는다.

- 직진/왕복/이동 씨앗: 진행이 느려지고 커진다. 부메랑의 **귀환**은 느리게 만들지 않아 회수 답답함을 줄인다.
- 즉발/낙뢰/장판: 이동 속도 대신 발동 전개에 짧은 예고를 주고 커진다. 공격 위치가 고정되는 시점도 표시한다. 기본 전개 지연 +0.18초, +3 +0.25초부터 시험한다.
- 위성: 몸체와 접촉 타격이 커지고 회전 속도 ×0.75. 개수는 그대로다. 잔불: 방출 주기만 응축, 이미 놓인 장판의 틱 간격/지속은 그대로다.
- 갈래와 함께 쓰면 여러 개의 무거운 공격이 나간다. 모든 탄을 무조건 1발로 합치지는 않는다. 강화 별빛탄의 고유 방향 패턴을 몰래 없애지 않는다.
- 합성 압축거성도 같은 응축 프로필을 참조한다. 중복 적용 대신 구성 효과를 한 번 해석한다.
- 연쇄/관통/메아리는 기존 분배 규칙을 유지한다. 느린 발동의 손해, 광역 증가, 후속 지연을 함께 측정한다.

## 6. 마법 콘텐츠 목표와 성장량

### 6.1 현재 18개가 선택지 18번이라는 뜻은 아니다

기본 18종마다 최초 1회+강화 3회로 **최대 72회**의 마법 획득 기회가 있다. 시작 지급·제작·상자 강화가 이 기회를 나눠 쓴다. 유물 12개까지 단순 합하면 84회지만, 합성 후 부모 재등장과 +3 제외 때문에 실제 확률은 시간에 따라 달라진다.

현재 XP는 마석값×2, 다음 레벨 요구량 `6+3×(레벨-1)`. 레벨업 n회에 누적 `1.5n²+4.5n` XP가 필요하다.

| 레벨업 횟수 | 누적 XP | 평소 주운 마석값 필요량 |
|---:|---:|---:|
| 20 | 690 | 345 |
| 40 | 2,580 | 1,290 |
| 60 | 5,670 | 2,835 |
| 80 | 9,960 | 4,980 |

이 표는 수식 계산이지 30분 실측이 아니다. 휴식 회수 XP를 없애면 걸어서 회수하는 비중에 따라 성장 속도가 줄어든다. 따라서 마법 개수만 늘려서는 해결되지 않는다.

**권고하는 30분 성장 목표:** 보통 플레이 레벨업 45~60회, 상자 약 8~14회(정예를 잡아야 얻음), 제작 마법 8~16회. 초반 첫 선택 15~25초, 이후 평균 25~40초 정도를 시작 목표로 삼되 사람 플레이로 조정한다. 한 판에서 30종을 전부 얻고 전부 만강하는 것을 목표로 하지 않는다. 기본 30종은 120회분, 유물 24종은 24회분으로 풀 소진 여유가 있다. 이론 총량만으로 특정 빌드 완성을 보장하지는 않는다.

보유 가중 3은 우선 유지한다. 새 풀에서 3장의 평균 구성이 계속 보유 강화로만 채워지면, 신규 최소 1후보 보장을 별도 작은 실험으로 검토한다. 이번 설계에서 몰래 고정 보상을 추가하지 않는다.

관통/연쇄가 설치형에서 정확히 무엇을 나누는지와 새 공격6개에의 대응은 새 기능 구현의 선행 명세다. 기존의 어색한 처리까지 무비판적으로 확대하지 않는다. 공격별 적용 설명/대상 강조가 없으면 출시 풀에 추가하지 않는다.

| 새 공격 제안 | 발사/역할 | +1/+2/+3의 행동 방향 |
|---|---|---|

이는 신규 행동 명세의 방향이며 세부 0~3 수치는 해당 추가 단계에서 작성/시험한다. 합성·보조 적용이 되지 않는 공격을 출시 숫자만 채우려고 넣지 않는다. 소환은 없다.

새 보조 4개: **가속**(진행/전개를 빠르게), **장수**(유효 유지·이동 예산 연장), **밀어내기**(첫 유효 타격의 밀침), **회수**(공격의 정상 종료 뒤 오브 쪽으로 짧은 회수 타격). 회수는 부메랑의 기본 행동을 모든 주문에 복사하지 않고, 끝 위치→시전자 방향의 공통 짧은 타격으로 정의한다. 이미 귀환하는 공격은 귀환 완료에서 한 번만 판정한다. 강제 제거에는 반응하지 않는다. 세부 적용 표가 어색하면 회수는 보류하고 **종류 수를 줄인다.** 무의미한 대체를 채워 넣지 않는다.

새 연결 2개: **지연 후**(선행 주문 시전 위치에서 일정 시간 뒤 후속 1회), **관통 끝**(마지막 유효 관통/도탄 종료 지점에 후속 1회; 해당 여유가 없는 공격은 첫 명중에서 실행). 후자는 일반 명중 연결과 충분히 다른지 먼저 시제품으로 확인한다. 파생 공격의 첫/마지막 사건을 엔진이 구분하지 못하면 출시 풀에 넣지 않는다. 모든 새 기본 구체에 +0~3 명세가 있어야 하며, 연결은 발동 횟수 대신 직접 후속 위력 50/65/80/100%를 공통 강화로 쓴다.

**추가 경계:** ‘관통 끝’이 없는 공격을 조용히 무효화하지 않는다. 설명과 적용 미리보기에 “이 공격은 첫 명중이 마지막 명중입니다”를 표시한다. 불필요한 특정 공격 전용 제한을 만드는 후보는 채택하지 않는다.

## 8. 오브 1→4개·5회 강화

### 8.1 획득과 가격의 첫 가설

- 시작은 오브1/6칸. 시작 조합 지급은 이 오브에만 배치하며 아직 없는 오브에 장착한 상태를 만들지 않는다.
- 휴식6/12/18분부터 추가 오브 제작안이 순서대로 확정 해금된다. 한 번에 건너뛰어4개를 사지 못한다. 가격100/160/240마석부터 시험한다. 한 번 해금하면 다음 휴식에도 살 수 있다.
- +1~+5 비용은 선택 오브별30/50/75/105/140. 5회 전부400, 4개 전부1600. 추가 오브500까지 모두 구매하면2100이므로 한 판에 전부 만강을 보장하지 않는다.
- 돈의 실측 전에는 가격을 확정하지 않는다. 초반6분에 두 번째 오브 또는 첫 오브 1~2회 강화 중 하나는 가능한 경제를 목표로 한다. 구매 불가능한 가격의 해금은 성장 이벤트가 아니다.

### 8.2 3후보 선택, 다섯 번의 결정

‘+5’는 강화 선택을 다섯 번 했다는 뜻이며 후보 하나의 단계가+5라는 뜻이 아니다. 효과는 해당 오브만 바꾼다. 후보는 중복 없이3개, 이미 최대 횟수를 고른 후보는 제외한다. 다음 일반 후보 재고가 충분하므로 전용 후보가 없어도 마지막 선택까지3개를 제시한다.

총금액은 `필드 직접회수 + 휴식 일괄회수 + 고정지급 - 제작 - 재구성 - 마법강화 - 오브구매/강화`로 기록한다. 6/12/18/24/종료 시점에 오브 수, 각 성장 단계, +3 수, 합성 수, 미사용 마석을 저장한다. 적300명 목표는 동시에 살아 있는 수이지 총 처치/드롭 수가 아니므로 이 숫자에서 수입을 역산하지 않는다.

## 9. 돈/XP/피해 숫자/자동 장착

### 회수 원인을 먼저 분리

`walk_pickup`: 돈+XP, 평소 줍기 유물 작동.
`break_sweep`, `victory_sweep`, `defeat_sweep`: 남은 마석값만 돈, XP0, 줍기 유물 미발동. 이미 돈으로 바꾼 마석은 다시 회수하지 않는다. 회수 애니메이션과 지급 원장은 별개이며 종료 중 중복 호출에도 idempotent하게 처리한다.

단위 테스트는 같은 마석값으로 평소2XP/일괄0XP, 레벨업 대기열 변화0, 보너스 돈·브로치 변화0을 검증한다. 패배 회수는 현재와 다른 보상 추가이므로 새 결과 화면에서 명시한다. 계속 저장은 여전히 준비 시간만 허용한다.

멀티는 후속이다. 설계 메모만 남긴다: N인에게 `floor(C/N)`, 나머지를 저장된 순환 커서 순으로1씩. 41원을2인 분배한 다음 홀수 보상은 다른 플레이어가 먼저 받는다. 실제 ID/합류/이탈 정책과 XP 공유는 네트워크 작업 때 결정한다. 이번에 멀티 코드를 만들지 않는다.

### 피해 숫자

- 숫자 값은 `max(0, HP_before-HP_after)`의 실제 감소값. 남은HP5에100공격이면5. 원래 공격 위력/초과 피해는 측정기에 별도로 남긴다.
- 같은 대상/같은 공격 계열의100ms 이내 틱은 합쳐 `12×3` 또는 합계36으로 표시. 개별 피격 기록은 모두 측정기에 유지한다. 빠른 타격이 피해 누락처럼 보이지 않게 작은 누적 갱신을 사용한다.
- 공유 CanvasLayer/그리기 큐, 폰트 재사용, 화면 밖 표시 제외, 동시 숫자96개를 첫 예산으로 시험한다. 객체96개 제한이 피해 처리 제한은 아니다. 혼잡하면 작은 일반 틱부터 합산한다.
- 보통 밝은 작은 숫자/큰 단발 강조, 보호막은 별도 표식. 현재 치명타 시스템을 만들기 위해 숫자부터 가짜 치명타를 추가하지 않는다.
- 숫자 표시 켜기/간략/끄기, 화면 흔들림과 독립. 300적+4오브에서 CPU/GPU 프레임 측정 후 확정한다.

### 자동 장착

현재는 신규 획득 자동 장착이 없다. 다음 순서로 넣는다.

1. 새 획득 후보에 **예상 장착 오브·칸** 표시. 기존 구체 위치를 밀거나 교체하지 않는 빈 자리만 후보로 삼는다.
2. 공격은 빈 오브 우선, 다음은 이미 활성인 오브의 오른쪽 빈 자리. 보조는 적용 공격이 있는 왼쪽 빈 자리, 연결은 앞/뒤 공격이 모두 성립하는 빈 자리만 허용한다.
3. 빈칸을 메워 기존 연결 대상을 바꾸거나 기존 보조 범위를 예상 밖으로 바꾸는 배치는 자동 선택하지 않는다. 파서 결과를 전후 비교해 기존 노드/연결이 보존되는지 확인한다.
4. 가능한 자리가 없으면 가방에 보관, “장착할 자리가 없어 가방에 보관했어요”와 편집 버튼. 명시적으로 고른 위치에는 수동 배치할 수 있다.
5. 전역 자동 장착 설정은 기본 켜기, 미리보기에서 ‘가방에만’ 선택 가능. 강화는 기존 위치에서 단계만 바뀌며 다시 자동 배치하지 않는다.
6. 합성 부모를 제거한 두 자리 중 **부모 공격이 있던 앞 자리**에 결과를 우선 놓되, 연결 문법이 깨지면 미리보기로 보여주고 사용자가 이동한다. 나머지 칸은 빈칸. 자동 왼쪽 정렬 금지.

## 10. 구현 순서와 완료 기준

| 순서 | 작업/주요 파일 | 이 단계에서 확인할 것 |
|---|---|---|
| 0 | 이 문서·획득 UI 명세·몬스터 제작 명세 검토 | 특히 보조 범위 변경을 구현 규칙으로 확정. 색상/구매 GUI는 별개 |
| 1 | 슬롯 모델/컴파일러: `spells.gd`, `game.gd`, `prep_slot.gd`, `prep_board.gd`, `spell_workbench.gd`, checkpoint 관련 코드 | 빈칸·교환·부분 실행·정확한 진단·되돌리기·저장 이관 |
| 2 | 오브 공통 데이터·성장/경제: `game.gd`, `economy.gd`, 체크포인트·HUD·결과 | 초기1/최대4/6~8칸/5회3택, 선택 오브만 변화, 후보 고갈 없음 |
| 3 | 획득 공통 UI+자동 장착: `combat_rewards.gd`, `prep_board.gd`, 실제 UI 구성 파일 | 신규/강화/합성/유물/오브 한눈 구분, 선택중정지/평소가방비정지, 기존배치 보존 |
| 4 | 보조/응축·복제/후속: `modifier_effects.gd`, `spell_runtime.gd`, `spell_behaviors.gd`, `fusion_effects.gd` | 위 모든 대표식, 분배예산·복제수·정상종료, 실제 느리고 큰 응축 |
| 5 | 회수·피해 숫자·기본 유물 | XP 분리, 중복회수방지, 피격 실수치, 숫자 혼잡/성능 |
| 6 | 마법 6개→6개 추가, 유물6개→6개 추가, 합성 단계 추가 | 한 묶음마다 +0~3/모든기존보조/연결 의미/입수·도감·저장 연결 |

실제 획득 UI의 정적 배치 검토를 0단계에 하되, 코드 반영은 데이터가 안정된 3단계에서 한다. UI를 중요하지 않아서 미루는 순서가 아니다. 콘텐츠를 새 저장 구조보다 먼저 양산하면 이관/검사 비용이 커진다.

### 관련 검사 계약

- 본 문서 4.2의 모든 배치와 빈칸 이동·해제·교환·서로 다른 오브 간 이동. 정상 노드 순서·실행 개수 비교.
- 4개 오브의 표적 순위/용량/단계/예약 독립. 장착·인벤 전체 실물수 보존, 잘못된 save는 원본 백업.
- 모든 초기 상태·업그레이드 선택5회에서 후보3개 보장. 슬롯 감소 없음. 오브2/3 저장을 읽어 삭제/초기화하지 않고 기존 구체·골드·성장을 보존한다.
- 옛 오브속도+1/+2/+3은 빠른 순환 선택 이력으로 이관하되 새 상한을 넘는 기존 성능은 그 판에 legacy 보정으로 보존하고, 오브 성장 선택을 중복 지급하지 않는다. 신규 판부터 새 수치 적용. 선택5회를 이미 초과하는 비정상 데이터는 경고/복원 경로를 쓰고 아이템을 조용히 버리지 않는다.
- 신규 기본은 +0~3 전부, 완성 합성은 한칸/부모소모/재획득/재합성차단. 오브8칸/4개까지 실제 화면에서 잘림 없음.
- 선택창 대기 중 전투/자동발사/추적/회피시간 정지, 평소 인벤은 시간 진행. 시험에 실제보상·돈·레벨업·성장 발생 없음.
- 대표 조합만 단일강적/밀집/일렬/이동4조건 비교. 새 규칙 전후 발사·명중·실피해·후속·복제·차단/생성량과 프레임을 기록한다.
- 기존 300적/3오브 렌더 기록은 평균18.21ms/p95 24.54ms로60FPS 안정 미달이었다. 4오브까지 무료로 안전하다고 간주하지 않는다. 성능 악화 시 관련 병목부터 해결하고 콘텐츠 수를 줄여 숨기지 않는다.

### 이번 산출물의 한계

현재 코드 감사와 공개 UI 화면 비교는 완료했다. 제안 수치의 밸런스, 30분 수입/레벨업 횟수, 새 공격의 실제 재미, 완성 GUI 아트, 새 몬스터 애니메이션은 **미검증/미구현**이다. 원작의 응축탄 이름/정확한 수치는 미확인이다. 그 불확실성 때문에 사용자 설명을 다른 주문으로 대체하지 않는다.
