# 이동·추격·돌진 템포 조정

2026-10-29. 사용자 피드백 ‘몬스터가 아직 너무 빠르다, 뱀서와 비슷한 이동감’에 대한 구현이다. 원작의 엔진 단위를 그대로 복제한 수치가 아니라 우리 월드에서 걸어서 공간을 벌릴 수 있도록 정한 초기값이다. 다른 게임을 실행하거나 새 자료조사를 넓히지 않았다.

## 변경 수치

단위는 월드 거리/초, 기본 이동 유물 없음. 범위는 1~5웨이브다.

| 항목 | 이전 | 변경 |
|---|---:|---:|
| 플레이어 걷기 | 240 | 200 |
| 일반 추격 | 145~157 | 92~100 |
| 약한 무리 | 110~118 | 73~77 |
| 일렬 진입 추격 | 153~165 | 98~106 |
| 원거리 걷기 | 93~105 | 66~70 |
| 돌진 적 평상시 | 123~135 | 83~87 |

일반 추격은 플레이어의 약46~50%, 정예는66~70%다. 적 수/리필/혼성 비중/체력/보상/사거리/카메라는 그대로다. 느린 적이 수와 배치로 공간을 줄이는 방향이며 정지 플레이의 재미나 전체 난도를 입증한 것은 아니다.

기존에는 군중 분리 벡터를 추격에 더해 정예의 실제 이동이 최대267까지 올라갈 수 있었다. 이제 합성 속도를 기본 이동(또는 명시된 돌진/보스 공격)의 속도 안으로 제한한다. 이웃을 피하는 방향 전환은 남기고, 앞으로 미는 군중 때문에 빨라지지는 않는다. 냉기 감속/동결은 그 뒤에 적용한다.

## 돌진과 회피

- 플레이어: 750×0.19초(142.5거리) → 520×0.20초(104거리). 재사용1.7초/무적0.28초 유지. 전투와 시험 발사가 같은 `_move_player`를 사용한다. 큰 delta가 들어와도 돌진 남은 시간까지만 이동하고 나머지 시간은 걷기로 처리한다.
- 일반 돌진 적: 345×0.95초(327.75거리) → 280×1.1초(308거리). 예고0.8→1.05초, 회복0.65→0.9초, 공격 재사용3.8→4.4초. 긴 직선 돌진과 조준 방향 고정은 유지한다.
- 보스: 돌진360→300, 예고0.95→1.1초, 지속0.65초로195거리. 마지막 프레임의 남은 시간만 이동하도록 한다. 보스 기본 걷기/공격 종류와 주기는 유지한다.
- 플레이어가 느려진 만큼 적 탄환도 낮춰 기존 회피 속도 비율을 대체로 유지한다. 플레이어만 느려져 원거리 공격이 상대적으로 강화되는 것을 피했다.

## 검증

- `movement_tempo_test`: **54검사/0실패**. 역할별 속도비, 실제 직선·대각선200, 전투/시험 일치, 회피104와 큰 delta 처리, 실제 일반100/정예140, 군중 추가 가속 방지, 냉기/동결, 돌진308/방향고정/회복, 보스195·탄환160, 후반 리필 확인.
- 고정 조건 후반 리필은3초에86마리 생성해 기존 생성 경로가 살아 있음을 확인했다. 전체30분/300마리 프레임 성능이나 사람이 느끼는 압박 측정은 아니다.
- 별도 실제 Godot 렌더링 프로세스: 일반16+정예1, 입력으로1초 걷기199.995, 뒤쪽 일반 적과 간격99.990 증가. `artifacts/movement-tempo-before.png`, `movement-tempo-after.png`, `movement-tempo-visual.json`; 테스트 프로필/record_runs=false 사용 후 종료했다. 파란 데스크톱 조작 없음.
- `scroll_arena_test`도 시도했으나 옛 화면폭/무리 크기/준비시간 없는 시험 진입/측정기 초기화 가정에서 실패하여 통과수에 넣지 않았다. 이동 예상거리만 최신1000/5초로 갱신했으며 관련 없는 옛 검사 전체를 수리하지 않았다. 실패 로그는 `artifacts/movement-tempo-legacy-scroll-results.txt`에 따로 보존하고 원래 추적된 생성 로그는 복구했다. 이번 전용 검사에서 전투·시험·대각선과 카메라 이동을 확인했다.
- Windows 빌드 성공, 기존 `project.godot` 변경 보존/커밋 제외. `artifacts/builds/lumi-run/WitchlingsMayhem.exe` 갱신. 빌드·캡처는 로컬, 소스와 문서는 정상 GitHub 체크포인트 업로드.
- 단순 수치/이동 경로 수정이므로 총괄 단독 구현·검증. 추가 직원/회의/원작 플레이 없음. 자동 검사 통과를 재미/최종 밸런스 통과라고 판단하지 않는다.

## 남은 작업

사람이 한 판을 플레이하며 너무 느슨해졌는지, 정예와 장거리 돌진의 압박이 적당한지 확인할 필요가 있다. 응축 개편·휴식 마석 회수 돈만 지급·피해 숫자·콘텐츠 확대는 아직 미시작이다.
