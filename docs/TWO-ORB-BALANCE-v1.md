# 두 오브 조합 측정과 밸런스 조정 v1

2026-10-26 · Godot 4.6.2 · 실제 전투 런타임 · `two-orb-v1`

현재 수치와 측정에 대한 최신 기록이다. 역할/강화 문서의 이전 단계 수치보다 이 기록과 `modifier_effects.gd`가 우선한다. 전투·경제·웨이브 전체를 재설계한 작업은 아니다.

## 확인한 문제

1. 측정기가 오브 하나만 실행하고 조합을 보고 이동 경로를 달리 추측했다. 실제 두 오브의 서로 다른 원점·순차 시전·시계와 다른 비교였다.
2. 갈래의 직접 피해 감쇠가 후속 주문에는 전달되지 않았다. 부모의 각 갈래가 새 후속 예산을 받고, 자식의 갈래/메아리로 다시 증식했다.
3. 장판 24개 제한으로 통상 조합의 피해가 잘렸다. 주력 조합에 두 오브를 투자해도 피해가 떨어졌다. 변경 전 282건 중 66건이 제한 영향을 받았다. 이 구간의 옛 피해는 무제한 상태의 본래 화력으로 해석할 수 없다.
4. 장판 생존 확인에 `Array.has(Dictionary)`를 사용해 중첩된 주문 딕셔너리를 매번 값 비교했다. 장판을 늘려 원래 화력을 확인하자 zones 처리 p95가 약 24.6ms까지 증가했다.
5. 잔불/위성 구성은 이동 압박에서도 투자 대비 기여가 낮았다. 이동 경로와 궤도라는 제약을 유지하고 기본 피해만 소폭 올렸다.

## 적용한 조정

| 항목 | 이전 | 현재 |
|---|---|---|
| 갈래 기본/+1/+2/+3/+4 각 위력 | 65/70/75/80/85% | 40/45/50/55/60% |
| 메아리 기본/+1/+2/+3/+4 반복 위력 | 55/60/65/70/75% | 35/40/45/50/55% |
| 후속 유입 지분 | incoming × 0.65 | incoming × 자기 갈래 위력 × 0.65 |
| 잔불 기본 틱 피해 | 4 | 5.5 |
| 위성 접촉 피해 | 14 | 18 |
| 장판 안전 용량 | 24 | 256 |

갈래 수(1+2n), 메아리 개수·0.18초 간격, 나머지 보조의 강화 수치, 공격 강화, 가격·수입, 적·웨이브는 유지했다. 새 마나나 적용 금지 조건을 추가하지 않았다. 위성/잔불의 기존 관통 추가타에도 같은 기본 피해를 사용한다. 합성 내부 위성도 동일한 기준을 따른다.

갈래 각 위력은 `∏(0.40+0.05r_i)`, 메아리는 각 복사마다 `0.35+0.05r_i`다. 기본 1개/기본 2개/+2 하나/+1 두 개/+4+기본의 갈래 각 위력은 40/16/50/20.25/24%, 분기는 3/5/3/5/5개다. 메아리는 각각 [35], [35,35], [45], [40,40], [55,35]%다. 강화 하나로 분기/반복 수까지 늘리지 않는다.

후속은 자신의 컴파일된 보조를 한 번 적용한다. 부모의 응축·공격 rank·각인 직접 감쇠는 자식에게 복사하지 않는다. 예: `[갈래][별빛탄][명중 후][꽃폭탄]`의 부모 각 탄은 22×0.4=8.8, 자식 유입은 0.4×0.65=0.26, 각 꽃폭탄은 20×0.26×0.4=2.08이다. 부모에서 분산된 지분을 전달하는 것과 자식 보조를 이중 등록하는 것은 다르다.

용량 확대 자체는 밸런스 하향이 아니다. 잘리던 화력을 복구하므로 일부 조합의 최종 실측 피해는 오히려 상승했다. 용량 영향을 제거한 상태에서 따로 피해 지분과 보조 수치를 조정했다. 피해가 큰 결과를 제한으로 잘라서 균형이라고 판정하지 않았다.

## 비교 방법

- `tools/two_orb_balance.py`: 11개 대표 두 오브 구성 × 7환경 × 시드 731/1151/2026 =231건. 보조 제거/중복/다단계 연결 30건, 공통 근접 원형 이동 21건을 추가해 전후 282건씩 비교.
- 일반 대표 구성의 추가 투자액은 12~68G. 가격이 전부 같지는 않다. 미사용 돈을 억지 구체로 채우지 않았다. 46G 구성끼리, 48G 구성끼리 및 보조 제거 사례를 별도로 비교했다. `double_meta` 120G는 일반 가격대의 순위 후보가 아니라 중복 스트레스 사례다.
- 같은 환경/시드끼리 조합과 무관한 플레이어 이동·마우스 경로·사전 생성 적 도착 계획을 공유한다. 변경 전후 공통 구간의 입력 trace와 전체 도착 계획 일치도 검사했다. 가까운 적 자동 조준은 보조 측정용이며 본 비교의 주 기준은 replay다.
- 실제 `_tick_orbs()`를 STEP=1/120초로 실행한다. 두 오브의 위치·시계·커서·후속 주문을 별도로 실행한다. 첫 시전은 t=0, 위력/공속 ×1, 창 길이 15초다.
- 비용은 실제 Economy 구매/합성/강화 API를 실행해 계산한다. 시작 무료 지급은 두 오브를 통틀어 한 번만 공제한다. 기본 구체 합성 경로와 화폐 강화 경로를 구분한다. 원하는 상품을 확보할 수 있다고 가정한 비용이며 랜덤 상점에서 실제 얻을 확률을 증명하지 않는다.
- 단일 표적의 15초 DPS는 초동 포함이다. 비교 CSV에는 3초 이후 지속 DPS도 별도로 남겼다. 유한 표적은 처치 수·완료율·완료 시간을 먼저 본다. 전멸해서 일찍 끝난 결과의 `effective_dps`와 15초 전체 창으로 나눈 `window_dps`를 혼동하지 않는다.
- pressure/relocation은 실제 적 AI를 사용하되 측정자 체력은 100만이다. 피격량은 압박/방어의 대리지표이며 실제 생존 난이도 통과를 뜻하지 않는다.
- 정지 표적에서 근거리 구성의 0피해를 곧바로 약하다는 근거로 삼지 않았다. 별도의 공통 근접 이동도 비교했다. 정지·일렬 fixture는 조준·배치 가정의 영향을 크게 받는다.

주요 조합의 읽는 법:

- `meta_both`: 위 구성에 메아리도 추가.
- `focus`: 관통·응축·별빛탄 / 서리→벼락.
- `mobility`: 거대화·잔불 / 각인·위성.

현재 일렬 표적은 focus 4.96초, ranked 관통/갈래 구성 4.93초로 완료했다. meta_both는 6.29초다. 밀집 표적은 meta_both 2.36초, control 2.43초, scatter 2.81초다. 범위·끌림/연쇄의 가치는 남았지만 일렬 관통까지 항상 이기지는 않는다.

meta_both가 이동 강적 3명을 평균 10.93초에 처리한 것은, 이전보다 많이 낮춘 지분에도 장판이 더 이상 조기 삭제되지 않기 때문이다. 이 조합은 여전히 강력한 상위 후보다. 모든 상황의 정답이 제거됐거나 최종 밸런스가 완성됐다고 단정하지 않는다.

## 처리량과 프레임

- 장판에 고유 ID/생존 집합을 두고 포함·제거를 식별자로 처리했다. 같은 외형의 두 장판도 독립적으로 유지한다. 정리할 때 ID 집합도 비운다.
- 군집 등록 시 매 후보마다 전체 필터를 반복하지 않고 한 번 집계한다. 같은 투사체 갱신 묶음의 성장 갱신은 한 번으로 묶는다. 직접 설치 API의 즉시 갱신은 유지한다.
- 용량/수치가 같은 두 집중 사례에서 ID 최적화 전후 `totals`와 시간별 피해 timeline이 모두 일치했다. pressure step CPU p95 약 25.15→3.63ms, zones 구간 p95 약 24.63→3.04ms였다. CPU 측정 자체도 계측 오버헤드와 실행 환경 영향을 받는다.
- 일반 비교 282건 중 최종 제한 영향은 0건. 최대 step CPU p95 4.04ms/p99 4.38ms. 최대 214장판이 필요한 1건만 용량 192→256 후 다시 측정했다. 나머지 281건은 기존 용량에 닿지 않았으므로 불필요하게 전부 반복하지 않았다.
- 실제 실행 측정실: relocation의 약 7~10초 구간, 두 오브 동시 시전, 180프레임. 12프레임 준비 후 wall frame p50 16.667ms/p95 16.696ms/p99 16.765ms, 최댓값 16.819ms, 표시 FPS60. 첫 준비 없는 관측에는 약57.8ms p99 스파이크가 있었다. 따뜻한 반복 결과만으로 첫 실행 끊김이 없다고 말할 수 없다. 에디터 연결 상태의 관측이며 배포 빌드/다른 하드웨어 성능 보장은 아니다.

### 별도 고비용 중복 스트레스: 남은 한계

두 오브 모두 `[추적,갈래,메아리,꽃폭탄,명중 후,소용돌이]`를 넣은 구성은 15초 pressure에서 장판 217회 교체, step p95 5.24ms였다. 두 갈래+메아리로 더 중복한 구성은 507회 교체, p95 8.78ms/p99 10.28ms였다. 이것은 일반 68G 이하 비교의 균형 근거에 섞지 않았다. 이 구간은 생성 제한으로 결과가 잘려 순수 밸런스 우열을 판정할 수 없다.

생성량을 계속 늘려 제한으로 누르는 방식은 해결책이 아니다. 다음에 이 고비용 중복까지 다룰 때에는 동일 계통 후속/장판 기여를 묶어 처리하면서 사건·수명·피해 지분을 보존하는 구조가 필요하다. 이번에는 이 구조 변경을 완료했다고 보고하지 않는다.

## 측정실과 로컬 실행

측정실에 두 개의 6칸 행, 편집할 오브 선택, 기본~+4 추가를 제공한다. 피해 기여는 오브/슬롯/원본·연결·메아리·각인·연쇄·파쇄·내부 합성으로 구분한다. 두 오브의 실제 간격·추가 투자액·CPU step·상한 영향도 볼 수 있다. 기존 시작 화면의 마법 측정실로 들어가면 된다.

```powershell
python tools/two_orb_balance.py
python tools/measure_spells.py --input artifacts/measurements/two-orb-cohort.json --output artifacts/measurements/two-orb-repeat
python tools/compare_two_orbs.py artifacts/measurements/two-orb-before.json artifacts/measurements/two-orb-repeat.json --output artifacts/measurements/two-orb-repeat-comparison
```

JSON jobs에서 `bank: [[...],[...]]`, `options.motion: scenario/stationary/orbit`, `options.economy_route: merge/paid`를 사용할 수 있다. 기존 한 배열 recipe는 두 번째 오브를 비운 형태로 호환한다. CLI `--bank`도 같은 두 행 JSON을 받는다. `--all-valid`는 옛 단일 오브 부분집합이며 현행 전수 생성기가 아니라는 경고를 붙였다. 이번 비교는 전수조사가 아니다.

## 관련 검증과 남은 플레이 판단

두 오브 측정 41개, 보조 강화 292개, 역할 89개, 슬롯 프로그램 83개 검사(총505개)를 통과했다. 검사에는 실제 두 시계·다단계 사건·감쇠 상속·중복/강화·비용·수량·동일 seed 재현·정리·독립 장판 ID·편집/시험이 포함된다. 관련 없는 웨이브/무기/맵 전체 검사는 돌리지 않았다.

실제 화면에서는 두 오브 행·강화 선택·배치와 시전이 보이는지 확인했다. 반복 실험은 조합의 상황별 성능 차이와 오류를 확인한 것이지 재미의 증명은 아니다. 직접 플레이로 확인할 것은 갈래 기본의 40%가 너무 약하게 느껴지는지, 메아리 35%를 살 동기가 남는지, 잔불/위성은 근접 위험을 감수할 만큼 체감되는지, 여전히 추적·갈래·메아리를 무조건 먼저 집게 되는지다.

기존 미커밋 파일은 유지했고 Git 저장소가 없어 `artifacts/two-orb-balance-before-20261026-041038`에 변경 전 파일을 백업했다. DuckGame과 MageGame은 수정하지 않았다.
