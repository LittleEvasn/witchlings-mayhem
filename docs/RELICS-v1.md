## 범위와 설정

웨이브 종료의 위력/공속/최대 체력 패시브 선택을 미보유 유물 3개 중 1개 선택으로 교체했다. 후보가 적으면 남은 수만 표시하고, 모두 보유했다면 곧바로 준비로 넘어간다. 같은 유물을 반복 지급하지 않으며 기존 패시브 수치도 함께 지급하지 않는다. 완료 보너스 20G, 흩어진 마석 회수, 체력 15 회복은 기존대로다.

플레이어용 상점/구매/재진열 표현을 제작대/제작/제작안 재구성으로 바꿨다. 실패작의 마석으로 다음 웨이브를 준비하며 실험이 끝나면 만든 장비도 소멸한다. 내부 shop 메서드 이름은 유지한다. 현재 준비 화면에는 원래부터 실제 카운트다운이 없고 준비 완료로만 출발한다. 기존 SHOP_SECONDS=60은 상태 유효성 값으로 보존했으며 새 제한 시간을 추가하지 않았다.

유물은 슬롯을 차지하지 않고 두 오브에 공통 적용된다. 다음 실험 시작 시 전부 초기화한다. 이번 12개는 모두 웨이브 보상 후보이며 유물 제작 상품/가격/상하급 배정은 추가하지 않았다. 정의 조회 데이터에 reward_pool=true, craft_pool=false, tier=unassigned를 둬 추후 상급 보상용/하급 제작용으로 나눌 수 있다.

## 계산과 사건 처리

### 피해·크기·시간

- 새로운 직접 주문의 위력 스냅샷 = 기존 power × 왕관1.3 × 모래시계0.85 × (1+저금통 보너스). 미보유 항은1이다.
- 현재 마석은 시전할 때 조회한다. 제작/강화/회수 후 다음 시전에 바로 반영한다. 이미 나온 탄/장판/메아리/후속 주문은 원래 스냅샷을 유지한다. 지연 후속에서 돈을 다시 읽지 않는다.
- 복제는 원래 계통의 power 스냅샷에 ×0.4를 한 번 적용한다. 후속마다0.4가 또 곱해지지 않는다. 각 단계의 갈래·연결0.65·각인 직접 피해 감소 등 기존 규칙은 별도로 한 번씩 적용한다. 상태 축적 횟수 자체를40%로 줄이지 않는다.
- 각인 혼합 폭발은 하나의 실제 타격으로 유지한다. 원본/복제 각인이 기여한 위력만 나누어 측정하므로 처치 수가 부풀지 않는다. 냉기 껍질도 피해를 만든 냉기 쪽에 원본/복제 기여를 귀속시킨다.
- 크기 스냅샷 _relic_scale은 각 단계에서 기본 크기에 한 번 적용한다. 후속·메아리·합성 내장 공격은 값을 전달받는다. 정원 성장의 기존 반경 배율과 함께 쓰되 유물 배율을 다시 곱하지 않는다.
- 실제 스케줄러의 순차 간격과 순환 후 대기에 ×0.8을 적용한다. 편집/강화 후 재계산과 시험 발사에도 같은 cast_delay를 사용한다.

### 복제의 방향과 귀속

- 별도 유물 RNG를 사용해 복제의 무작위 방향이 적 스폰/제작안 RNG를 바꾸지 않도록 했다. 측정에서는 시드로 초기화한다.
- 투사체/서리숨결은 복제 방향을 사용하고, 낙뢰는 같은 지정 거리를 무작위 방향으로 돌린 위치를 사용한다. 이동 경로 잔불과 플레이어 주변 위성은 기존 행동을 유지한다.
- 메아리/후속/합성 내장 공격에도 _relic_copy를 전달한다. 측정 source의 /relic_copy로 원본과 구분한다.
- 복제 위성과 원본 위성은 기존 동시 유지 수를 서로 빼앗지 않도록 별도 집계한다. 기존 위성 유지2개 규칙 자체는 유지하며 아래 한계를 명시한다.
- 웨이브/실험 종료·시험 정리 때 기존 clear_magic으로 탄/장판/메아리/낙뢰/위성을 정리한다. 강제 정리가 소멸 연결을 만들지 않는다.

### 상태와 시험 분리

유물 정의/누적 상태는 relics.gd, 게임 사건 연결은 game.gd 및 런타임, 화면 구성은 relic_ui.gd로 나눴다. 전역 이벤트 버스나 반복 구독은 추가하지 않았다.

시험 시작 시 보유 유물·시전 횟수·마석 잔여 누적·보호막·처치 누적·이동 버프/재사용·유물 RNG 상태, 실제 체력/보유 마석/게임 RNG를 보관한다. 시험에서는 현재 효과가 실행되지만 마석 획득 경로는 차단한다. 종료 시 누적 상태를 복구한다. 편집 변경은 기존 규칙대로 실제 장착에 반영하며 소비한 구체를 되살리지 않는다.

실험 재시작은 보유 유물까지 전부 비운다. 웨이브 종료는 보호막·처치 누적·이동 버프를 비우고, 장갑 횟수와 브로치 나머지는 같은 실험 동안 유지한다. 사망/승리도 예약 공격과 임시 방어 상태를 정리한다. 피격 사망으로 적 탄환 배열이 비워졌을 때 같은 인덱스를 다시 제거하지 않도록 함께 보완했다.

장갑 반복 측정의 totals와 sources는 완전히 일치했다. 방어 유물 비교의 고정 입력 압박에서는5마리만 처치하고 적 탄이 없어서 보호막/감속의 가치를 입증하지 못했다. 구두는2회 발동했지만 고정 좌표 재생은 이동 속도 이득을 반영하지 않으므로 해당 생존 우열을 주장하지 않는다. 각 효과의 발동 자체는 별도의 실제 게임 메서드 검사로 확인했다.

## 성능과 남은 한계

에디터 연결 디버그 실행에서 같은 두 오브 측정기를 사용해 시뮬레이션9~12초 구간을180렌더 프레임 관측했다. 프레임당1/120초 step2회, 준비12프레임 후 wall 시간을 기록했다. 배포 빌드나 모든 하드웨어의60FPS 보장이 아니다.

- 일반 압박 조합+확대경/장갑/모래시계: 렌더 wall p50=16.666ms, p95=16.677ms, p99=16.688ms. 전체 관측 최대 적18/탄33/장판62, 생성 제한 없음.
- 두 오브 모두 추적·갈래·메아리·꽃폭탄→소용돌이+동일3유물: wall p50=34.669ms, p95=43.652ms, p99=50.293ms. 해당 관측 끝 draw calls1500, 2step CPU p95=20.303ms, 장판256. 이 극단 조합은 실제로 느리다.
- 같은 고비용 구성15초 전체 headless: 유물 없음→있음 장판 교체217→731회, step CPU p95=5.344→7.147ms. 두 갈래 중복은507→1399회, p95=8.993→9.473ms. 제한 때문에 결과가 잘려 이 사례를 순수 화력 우열의 근거로 쓰지 않는다.
- 위성/잔불 조합의 유물 추가 조건에서 기존 ‘같은 오브·슬롯·메아리 구분별 위성2개’ 유지 제한이5회 발동했다. 복제와 원본이 서로의 자리를 빼앗는 문제는 분리했지만, 모래시계로 원본 시전이 빨라질 때 기존 유지 제한에 닿는 문제는 남아 있다. 이를 화면/측정 데이터에 표시하며 정상적으로 전부 시전됐다고 보고하지 않는다.
- 이번에 전체 생성 상한을 올리거나 공격을 새로 생략해 해결했다고 하지 않았다. 다음 성능 작업은 중첩 장판/위성의 논리 기여·수명·연결 사건을 보존하며 시뮬레이션과 표시를 묶는 구조가 필요하다. 방어 유물의 수치 판단에는 실제 회피 입력과 원거리 적이 포함된 플레이도 필요하다.

## 실제 화면과 자료

엔진에서 보상 버튼으로 장갑 획득 → 제작 화면의 무료 제작 버튼으로0G 소비 → 유물 목록 → 시험 발사 → 원래 장갑 누적3회 복구 → 준비 완료로2웨이브 진입을 확인했다. 실제 물리 처리를2초 실행해 두 오브 시전과 보호막 HUD도 확인했다. 일부 유물/적 배치는 재현용으로 지급했으며 자연스러운 한 판의 획득·생존 난도 검사는 아니다.

- artifacts/relics-reward.png: 짧은 설명의3개 선택.
- artifacts/relics-crafting.png:5개 제작안, 무료 제작과 준비 버튼.
- artifacts/relics-inventory.png 및 relics-all-inventory.png: 보유 유물 목록/스크롤.
- artifacts/relics-live-combat.png: 실제 전투 시전·보호막 HUD.
- artifacts/relics-combat.png: 제한에 닿는 혼잡 스트레스 화면.
- artifacts/measurements/relics-final.json: 최종21항목, 각 항목 출처 포함.
- relics-v1.json/.csv: 최초 원자료, relics-orbit-final 및 relics-source-final: 해당 수정 재측정.
- relics-render-profile.json / relics-render-normal.json: 실제 렌더 프레임 원자료.
- artifacts/relics-test-results.txt 등: 관련 검사 로그.

수치/성능 확인은 재미의 증명이 아니다. 특히 장갑이 실제로 도움이 되는 장면, 모래시계가 각인·빙결 조합의 정답이 되는지, 4번의 웨이브 보상에서 경제 유물을 선택할 여유가 있는지는 실제 플레이로 판단해야 한다.

공식 API 참고: [Godot4.6 Containers](https://docs.godotengine.org/en/4.6/tutorials/ui/gui_containers.html), [RandomNumberGenerator seed/state](https://docs.godotengine.org/en/4.6/classes/class_randomnumbergenerator.html). 엔진 버전은4.6.2를 유지했다.
