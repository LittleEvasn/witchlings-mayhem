# 슬롯 자유 배치·부분 실행 — 구현 1단계

완료: 2026-10-29. 사용자 승인 범위는 앞선 개편 계획의 1단계다.

## 구현한 규칙

- 각 오브의 여섯 칸은 고정된 위치다. 빈칸은 내부적으로 빈 문자열이며, 가운데와 맨 왼쪽의 빈칸도 유지한다.
- 빈칸으로 드래그하면 그 칸으로 이동한다. 장착된 구체끼리 겹쳐 놓으면 위치를 교환한다. 가방 구체로 교체하면 기존 구체는 가방으로 돌아간다. 가장자리 드롭으로 삽입하거나 자동 왼쪽 정렬하지 않는다.
- 빈칸은 시전 순서에서 건너뛴다. 구체의 원래 슬롯 번호는 진단·보조 적용 표시·장착·되돌리기·저장에서 보존한다.
- 잘못 연결된 부분만 비활성화한다. 오류는 빨강, 적용할 공격이 없는 보조는 회색과 경고로 표시하고 해당 칸의 툴팁에 이유를 표시한다.
- 정상인 다른 주문은 계속 시전한다. 문법 경고만으로 준비 완료나 시험 발사를 막지 않는다. 모든 칸이 비어 있어도 진행할 수 있다.
- 재고 부족, 같은 실물의 중복 장착, 알 수 없는 구체를 실제 장착하는 경우 등 수량·데이터 검사는 계속 차단한다.

## 예시

| 배치 | 실행 |
| --- | --- |
| 빈칸 다섯 개 → 별빛탄 | 여섯 번째 칸의 별빛탄 시전 |
| 별빛탄 → 빈칸 → 꽃폭탄 | 별빛탄과 꽃폭탄 순차 시전 |
| 명중 후 → 별빛탄 | 맨 앞 연결은 경고, 별빛탄은 독립 시전 |
| 별빛탄 → 명중 후 | 끝의 연결은 경고, 별빛탄은 시전 |
| 별빛탄 → 명중 후 → 소멸 후 → 꽃폭탄 → 빈칸 → 벼락 | 연속 연결과 해당 후속 꽃폭탄은 비활성, 별빛탄·벼락은 독립 시전 |

후속 주문이 잘못되었다고 그 후속을 독립 공격으로 몰래 발사하지 않는다. 비활성인 부모의 후속 연결에는 부모가 실행되지 않는다는 이유를 표시한다.

## 보존한 범위

보조는 지금처럼 같은 오브에서 오른쪽에 있는 공격과 연결 후속에 적용한다. 연결 전후로 보조 범위를 초기화하자는 설계안은 미확정이므로 적용하지 않았다. 사건 발동 횟수·후속 위력·마법 행동·경제·레벨업·휴식 흐름을 이번에 개편하지 않았다.

초기 두 오브/기존 최대 세 오브와 여섯 칸을 유지한다. 초기 한 오브→최대 네 오브·오브 강화·자동 장착·응축 개편·회수 경험치·피해 숫자·새 획득 UI·콘텐츠 증설은 이번 구현이 아니다.

## 강화·합성·저장 호환

- 강화 후에도 구체 위치가 유지된다. 합성 재료를 소비한 자리는 빈칸으로 남고 결과 위치를 불필요하게 옮기지 않는다.
- 두 오브 사이의 교환과 되돌리기는 전체 칸 위치를 복원한다.
- 준비 체크포인트와 되돌리기 이력에 빈칸을 저장한다. 예전 짧은 배열은 오른쪽을 빈칸으로 채워 읽는다.
- 정상 저장을 복원할 때 단순 재고 정규화가 되돌리기 이력을 지우지 않도록 수정했다. 실제 구형 데이터 변환이 일어나는 경우만 오래된 이력을 정리한다.

## 검증과 한계

Godot 4.6.2에서 `python tools/run_tests.py fixed_slots_test`: **59개 검사, 실패 0개**. 자유 배치·교환·보조 범위·다단계 오류·수량·강화·합성·시험 복귀·준비 저장 및 이어하기 후 되돌리기·실제 Control 드래그 이벤트를 검증했다. 기존 전체 검사나 전수 조합 측정은 실행하지 않았다.

독립 읽기 검토 1회에서 발견한 다중 미지정 토큰 뒤 후속 오발사, 복원 후 되돌리기 이력 소실, 비활성 부모의 잘못된 진단 문구 세 건을 수정하고 회귀 검사를 포함했다.

실제 게임 카메라에서 오류 칸·회색 보조·정상 시전 요약·활성 준비 버튼을 확인했다. 실제 뷰포트의 마우스 버튼/이동/놓기 이벤트로 1번 칸→5번 칸 이동, 빈칸 유지, 되돌리기까지 확인했다. 시험용 상태는 `record_runs=false`로 격리했고 게임을 중지했다. 파란 데스크톱 컴퓨터 제어는 사용하지 않았다.
