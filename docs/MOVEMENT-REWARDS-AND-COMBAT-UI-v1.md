# 이동 보상 기회와 전장이 보이는 개인 UI

2026-10-27 · 설계안만 작성. 게임 코드·수치·UI는 변경하지 않았다.

## 목적과 현재 근거

제자리 생존과 제작까지의 기다림 사이에 **쫓아가면 이번 전투에서 새 조합을 만들 기회**를 둔다. 맵 확대, 건물 파괴, 새 마법 추가, 멀티 구현은 포함하지 않는다. 보상 기회만으로 기존의 약한 적/정지 생존 문제가 해결됐다고 판단하지 않는다. 전투 압박 조정은 별도 작업이다.

- 현재 월드 4800×3600, 논리 화면 1440×900. 사용자는 맵을 현 상태로 유지하기 원한다.
- `scripts/game.gd:268` Tab은 전투에서 `open_editor()`를 호출한다. `:356`은 combat 외 상태에서 전투 처리를 반환하므로 edit 상태도 멈춘다. `:1001`에서 editor 진입 시 state를 edit으로 바꾼다.
- `scripts/prep_board.gd`의 build는 (32,32)의 1376×836 전체 준비창을 사용하고 HUD를 숨긴다. `scripts/interface.gd`의 new_modal은 화면 전체 입력 차단과 0.75 알파 암막을 만든다. `scripts/relic_ui.gd`의 유물 보유창도 combat을 paused로 바꾼다. 한 창의 투명도만 줄이는 것으로 해결되지 않는다.
- `scripts/game.gd:431`은 매 틱 커서로 조준점을 덮어쓴다. UI를 조작하는 커서를 그대로 조준에 쓰면 옆 창을 향해 공격하게 된다.
- 편집은 이미 `_draft_changed` → `_commit_live_board`로 즉시 반영한다. 문법이 틀린 오브는 정지하고 이전 주문을 몰래 계속 쏘지 않는다. 이 동작을 유지한다.
- 일반 처치 마석은 `scripts/waves.gd`의 reward 예산을 사용하고, 바닥에 남은 마석은 웨이브 종료 때 전량 회수한다. 이 편의 기능을 없애 이동을 강요하지 않는다.
- 실제 전투 시간/예산은 `scripts/run_content.gd`가 덮어쓴 90/105/120/135/150초와 48/64/78/90/24다. 기본 WAVES 표의 옛 45초 값을 기준으로 설계하지 않는다.

이하 시간·범위·보상 예산은 **첫 구현용 가설**이며 측정한 재미나 최종 밸런스가 아니다.

## 1. 이동 보상: 첫 버전은 한 웨이브 한 기회

1~4웨이브에 한 번씩, 보스전에는 만들지 않는다. 종류는 홀수 웨이브의 도주 운반자 / 짝수 웨이브의 배회 무리로 교대한다. 종류는 학습 가능하게, 출현 방향·위치는 무작위로 둔다. 일반 적 생성은 기존 무작위 흐름을 유지한다.

| 기회 | 행동 | 완료 조건과 보상 | 이동할 이유 |
|---|---|---|---|
| 마석 운반 실패작 | 플레이어 근처 외곽에 한 마리. 평소 짧게 배회하고 가까워지면 도망간다. 멀리 순간이동하거나 무적이 되지 않는다. | 처치한 자리에 실험 재료 묶음 하나. 접근 회수하면 기본 구체 3종 중 1개 선택권. | 도주하는 목표를 따라가며 일반 무리를 피하고 사격한다. 회수 지점까지 가야 전투 중 성장을 얻는다. |
| 배회 운반 무리 | 기존 근접 외형 4마리가 느슨하게 이동. 가까워지면 일부는 접촉 공격, 운반자는 다음 지점으로 이동. 전원이 플레이어에게 직행하는 일반 무리와 구분한다. | 해당 이벤트 소속 전원을 처치하면 마지막 처치 지점에 같은 선택권 묶음 하나. 적마다 구체를 주지 않는다. | 지나가는 무리를 요격할 동선을 선택한다. 이동 중인 다수 처리와 단일 추격의 장점이 달라진다. |

- 첫 출현은 웨이브 시작 25~35초, 이후 웨이브는 25~45초 사이. 출현 후 40초 동안 기회가 유지되고, 미완료 시 조용히 이탈한다. 기존 웨이브 종료를 기다리게 하거나 연장하지 않는다. 완료 후 떨어진 묶음은 웨이브 끝까지 유지한다.
- 동시에 이벤트는 1개. 배회 무리 4명도 기존 적 동시 상한에 포함한다. 자리가 없거나 안전 위치를 못 찾으면 짧은 제한 시간 안에서 다시 확인하고 취소한다. 생성 빚을 쌓아 나중에 쏟아내지 않는다.
- 플레이어에서 360~520 거리의 화면 외곽 띠를 후보로 한다. 안전거리 220 이상, 월드 경계와 실제 이동 가능 영역을 검사한다. 조건을 만족하는 방향이 없으면 건너뛴다. 맵 반대편까지 원정을 요구하지 않는다.
- 운반자의 초기 도주 속도는 기본 플레이어 240의 약 85%인 204부터 비교한다. 피해량/체력/둔화·빙결 상성은 현재 빌드 대상으로 처치시간을 측정한 뒤 정한다. 유도나 번개 면역을 만들지 않는다. 이 수치를 참고작 실측이라고 하지 않는다.
- 먼 목표는 작은 방향 표식만, 화면 안에서는 목표 표식만 표시한다. 일반 적의 출현 위치를 미리 알려주는 장치로 확대하지 않는다. 화면 중앙 퀘스트창/목표 문장으로 전투를 덮지 않는다.
- 이벤트 소속 적은 일반 적의 화면 밖 재배치에서 제외한다. 이벤트 이탈/웨이브 정리/재시작은 처치·보상을 발동시키지 않는다. 하나의 이벤트 ID가 완료와 회수를 각각 한 번만 처리한다.
- 묶음은 일반 마석 흡수/웨이브 종료 자동 회수와 분리한다. 가까이 60 이내에서 자동 회수하므로 클릭이나 가만히 서 있는 상호작용은 필요 없다. 멀리서 죽여도 보상을 얻으려면 그 자리까지 이동해야 한다. 이 조건은 HUD에서 알린다. 이미 회수한 선택권은 나중에 골라도 사라지지 않는다.

건물·상자 배치나 맵 장식으로 우회하지 않는다. 첫 구현에서는 기존 적 외형과 UI 표식을 재사용한다. 적의 역할이 구분되지 않으면 이름/표식부터 개선하고 본격 아트는 따로 다룬다.

## 2. 전투 중 마법 3중1택과 성장 예산

회수 → HUD의 `마법 선택 1` 배지 → 원할 때 오른쪽 개인 창에서 세 개를 세로로 표시 → 하나를 가방에 넣는다. 자동 장착·기존 주문 교체·자동 강화는 없다. 같은 구체를 골라 기존 강화 재료로 쓸 수 있다.

- 세 후보는 서로 다른 기본 0단계 구체. 현재 공격·보조·연결 풀을 사용하고, 소환/신규 마법/완성형 합성/+4 직접 지급은 제외한다. 실제 공격 최대 2개 같은 옛 제한을 부활시키지 않는다.
- 받을 수 없는 재고 상한 후보는 생성 시 제외하고 선택 시 다시 확인한다. 그 사이 상한이 찼으면 해당 후보만 같은 보상 ID 안에서 교체한다. 전체 목록을 자유 새로고침하는 수단으로 만들지 않는다.
- 후보는 회수 시 한 번 정해 대기열에 보관한다. 창 닫기/열기나 인벤 편집으로 다시 추첨하지 않는다. 선택은 보상 ID 기준 한 번만 지급한다. 사망/실험 재시작에는 대기열을 정리한다.
- 선택권은 강제로 창을 열지 않고, 미선택 상태는 다음 준비 시간에도 유지한다. 준비창의 작은 배지로도 같은 선택권을 연다. 선택 화면은 새 상점이 아니라 이번 전투에서 확보한 구체 지급이다.
- 최대 네 번의 중간 보상부터 검증한다. 기존 웨이브 종료 유물 3중1택 → 마석 제작 → 다음 웨이브 흐름은 유지한다. 전투 중 강화를 위한 별도 제작 메뉴는 첫 구현에 넣지 않는다.

경제 권고: 구체를 기존 마석 위에 무조건 더하지 않는다. 각 1~4웨이브 처치 예산에서 최대 구체 기본가인 **18G 상당**을 이벤트 몫으로 먼저 확보한다. 이벤트 적에게 일반 처치 마석을 이중 지급하지 않는다. 미회수/실패 시 그 몫을 해당 웨이브의 아직 지급하지 않은 일반 드롭 한도에 돌린다. 이미 생긴 마석을 회수하거나 플레이어 돈을 깎지 않는다.

성공 시 18G는 '이벤트 보상 예산'으로 소비하고, 선택한 기본 구체의 가치는 실제 기본가(8~18G)로 따로 기록한다. 싼 후보를 골랐다고 차액을 별도 환급하지 않는다. 플레이어가 돈을 내는 거래가 아니며 기존 제작가도 바꾸지 않는다. 실패 시 복구한 한도는 남은 전투에서 얻는 것이고 무조건 지급되는 현금이라고 설명하지 않는다.

따라서 보스 전 최대 일반 마석 예산280 + 완료 보너스80 = 360G 중 최대72G 상당을 중간 구체로 옮기는 시작안이다. 네 번 모두 성공하면 일반 처치 최대208G + 완료80G + 기본 구체4개(최대72G 상당). 이론상 총 상한이 늘지 않지만 실제 수급/선택 가치가 동일하다는 뜻은 아니다. 첫 웨이브도 이벤트 성공 시 일반 한도30G와 완료20G가 남으므로 제작을 완전히 대체하지 않는다. 실제 상점 구매 횟수는 별도 비교한다.

**이동의 이득은 더 많은 총돈만이 아니라 전투 중 먼저 구체를 얻어 사용할 기회**다. 실패해도 진행 실패나 특정 빌드 강요가 없어야 한다. 다만 자동 회수 삭제로 억지 이동을 만들거나 보상을 놓치면 빈곤해지는지 반드시 검증한다.

## 3. 전투용 개인 창

논리 화면 1440×900에서 오른쪽 폭 416(약29%)의 서랍. 전장 약71%와 중앙 플레이어는 유지한다. 전장 암막·전체 화면 입력 차단·카메라 자동 이동을 사용하지 않는다. 옆 창 아래 위협은 안쪽 가장자리 방향 표식으로 알리되, 적을 순간이동시키거나 화면 밖 공격으로 즉사시키지 않는다.

```text
┌──────────── 전장 약71% ────────────┬── 개인 창 약29% ──┐
│ 체력 / 웨이브                    │ 조합  보상(1)  유물 │
│                                 │ 오브1              │
│             플레이어            │ [ ][ ][ ][ ][ ][ ] │
│                                 │ 오브2              │
│       이동·회피·자동 발사 유지    │ [ ][ ][ ][ ][ ][ ] │
│                                 │ 가방 6열 / 스크롤   │
│                                 │ 되돌리기 / 상세     │
└─────────────────────────────────┴────────────────────┘
```

- Tab은 조합 서랍 열기/닫기. 보상 배지를 누르면 같은 서랍이 세 후보로 전환된다. 보상과 인벤을 별도 큰 창으로 겹치지 않는다. 탭 이동 시 진행 중 드래그는 취소하고 실제 구체는 복제·소비하지 않는다.
- 오브별 여섯 칸 모두 고정 표시. 시작안은 56칸폭×6 + 간격6×5 = 366. 416폭의 내부 여백과 작은 오브 제목을 확보할 수 있다. 실제 글자/해상도에 맞춰 재검증하며 현재 108폭 슬롯 전체를 단순 축소하지 않는다.
- 구체 칸은 기호·강화·수량 중심. 이름과 짧은 동작은 선택 상세 한 곳에 표시한다. 화면 가득 설명문·순차 문법 원문을 늘어놓지 않는다. 보조를 선택하면 적용 대상은 기존 강조 기능으로 보여준다.
- 새 구체 획득은 가방에서 짧게 강조한다. 바로 드래그하거나 클릭 선택 후 목적 칸을 클릭해 넣을 수 있도록 같은 편집 명령을 쓴다. 장착 중인 개수와 여분 수량은 구분한다.
- 잘못된 임시 조합도 편집 가능하며 오류 위치를 표시한다. 해당 오브는 실제로 침묵하고 다른 오브는 계속 시전한다. 닫기를 막아 전투에서 탈출하지 못하게 하지 않는다. 오류 배지를 전투 HUD에도 남겨 다시 고칠 수 있게 한다. 되돌리기는 편집만 되돌리며 전투·피해·보상 획득을 되돌리지 않는다.
- 준비 시간의 강화·합성·제작·시험은 기존 넓은 준비창에 남긴다. 실시간 창에 모든 기능을 욱여넣지 않는다. 시험 발사는 전투 한가운데 안전지대로 전환하는 버튼으로 제공하지 않는다.
- 전투 중 보유 유물 조회도 같은 서랍에 넣고 일시정지하지 않는다. 준비 단계의 유물 선택은 이미 전투가 끝난 구간이므로 기존 보상 흐름을 유지한다.

## 4. 조작과 실행 상태를 분리

월드 상태(combat / preparation / trial / paused / ended)와 개인 창 상태(closed / inventory / reward / relics)를 별도로 둔다. 이번에 멀티플레이 네트워크를 구현하지 않는다. 개인 창을 열었는지가 세계를 멈추는 조건이 되지 않도록만 분리한다.

| 입력/상황 | 권고 동작 |
|---|---|
| WASD/방향키·Space | 서랍이 열려도 이동·회피. 전투용 버튼은 키보드 포커스/자동 선택을 잡아 Space를 소비하지 않는다. 텍스트 입력칸은 첫 버전에서 제공하지 않는다. |
| 마우스가 전장에 있음 | 현재 마우스 조준 그대로. UI 바깥은 입력을 통과한다. |
| 마우스가 서랍/드래그에 있음 | 마지막 유효한 **플레이어 기준 조준 벡터와 거리**를 보존해 자동 시전. 이동 전 월드 좌표를 고정하거나 화면 구석을 조준하지 않는다. 이동/자동 발사는 계속된다. |
| 클릭·우클릭·휠이 서랍 안 | 구체 선택/드래그/해제/스크롤만 처리한다. 전투 조준 갱신과 겹치지 않는다. 일반 마우스 조준을 근처 적 자동 조준으로 바꾸지 않는다. |
| Esc | 드래그 취소 → 열린 개인 창 닫기 → 창이 없을 때 기존 1인 일시정지 순서. 한 번 눌러 닫기와 정지가 동시에 일어나지 않는다. M은 기존 음소거 유지. |
| 사망/웨이브 종료/타이틀 | 드래그·UI 참조를 닫고, 이미 받은 선택권만 준비 화면으로 옮긴다. 재시작은 전 실험 선택권/이벤트를 전부 버린다. |

현재 `_unhandled_input`만 수정하면 물리 틱의 Input 조회와 버튼 포커스가 따로 동작할 수 있다. 이동 허용과 GUI 소비를 함께 검사한다. 조준 갱신은 `_update_mouse_aim`을 통하는 모든 호출에 동일 규칙을 적용한다.

UI 갱신이 오브 타이머/순차 커서를 초기화하면 안 된다. 실제 구체 변경만 현재 편집 규칙대로 재컴파일하고, 변경 직후 공속 보너스를 만들지 않는다. 보상 지급은 `inventory`와 경제 revision에 반영하고 오래된 드래그 payload를 거부한다. `닫기`는 기존 `board_close()`의 유효 조합 강제 정책과 별도로 처리해야 한다.

무적/감속/적 정지를 개인 창의 기본 혜택으로 주지 않는다. 안전한 긴 고민과 시험은 준비 시간, 짧은 교체와 선택은 전투 창이라는 역할을 둔다. 실제 비정지 편집이 너무 위험하면 보상 대기를 더 편하게 조정하고, 몰래 정지/영구 보호막을 추가하지 않는다.

향후 멀티에서는 이 선택권/인벤의 소유자와 한 번 지급 검증이 필요하다. 지금은 개인 보상 ID/로컬 소유자 경계만 남긴다. 거래·동기화·다른 사람 선택 대기·협동 정지는 후속 설계다.

## 5. 구현 순서와 관련 파일

1. 전투 상태와 개인 창을 분리하고 작은 조합/보유 유물 서랍부터 만든다. `game.gd`, `interface.gd`, `prep_board.gd`, `prep_slot.gd`, `relic_ui.gd`. 기존 편집/되돌리기/두 오브 수량 명령을 재사용한다. Godot 4.6.2 설치 버전 기준 Control/입력 API를 확인한다.
2. 선택권 ID·후보 고정·가방 지급·대기 배지를 추가한다. UI 시험용 고정 보상으로 먼저 재현한다. 기존 유물 reward 상태와 이름이 같다고 한 대기열로 섞지 않는다.
3. 좁은 기회 생성기를 추가해 운반자 한 종류를 연결한 뒤 배회 무리를 붙인다. 설정은 `run_content.gd` 또는 작은 데이터 한 곳에 모은다. `waves.gd` 예산/동시 상한 및 `actor.gd` 이벤트 소속을 연결하고, `game.gd` 재배치·사망·정리 경로를 정리한다. 범용 퀘스트 프레임워크는 만들지 않는다.
4. 전투 압박 작업과 합쳐 첫 두 웨이브만 사람에게 확인받는다. 별도 결론 없이 웨이브 시간을 길게 유지하거나 마법 수를 늘리지 않는다. 이번 문서로 이 구현들을 완료했다고 표시하지 않는다.

## 6. 구현 뒤 필요한 제한 검증

- 고정 시드로 이벤트 출현 시각·안전거리·상한·배회/도주·월드 경계·실패 취소. 멀리 재배치/중복 처치·빙결 중 이탈·마지막 적 동시 사망도 포함.
- 정지 생존 / 적극 추격에서 얻은 구체·실제 마석·첫 성장 시각·준비 때 구매 횟수·이동 거리·피해를 비교. 유도+벼락만이 아니라 단일/광역 대표 조합으로 처치시간과 추격 성공을 확인. 안전 상한 통과는 재미 증거가 아니다.
- 선택권 회수/미회수/대기/선택 시점과 마석 한도 보존. 후보 재추첨·재고 상한·사망 직전 선택·연타·웨이브 경계의 이중 지급 방지.
- 서랍 열어 둔 채 실제 이동·회피·두 오브 발사·적 공격·웨이브 시계가 계속되는지. UI 커서/드래그 중 마지막 상대 조준 유지, 전장 복귀 즉시 마우스 조준 회복.
- 여섯 칸/두 오브/강화 수량/교환/삽입/되돌리기/문법 오류·닫기·다시 열기. 강화 0~4나 연결 동작 자체의 무관한 전체 재검사는 하지 않는다.
- 전장 가시성은 실제 게임 화면에서 별도로 확인. 오른쪽에서 오는 적을 놓치는지, 플레이어와 탄이 가려지는지, 1280×800 실창에서 글자와 드래그 칸이 읽히는지 확인.
- 재미 판단: '기회를 보고 쫓아갈지 고민했는가', '중간 구체를 실제로 써봤는가', '전투 편집이 잠깐 교체인가 불안한 작업인가', '제작까지 기다린다는 느낌이 줄었는가'. 아직 실측하지 않았다.

담당: 총괄(현재 채팅) 설계/코드 열람. 별도 다른 게임 분석자는 코드 가능 범위만 조사했으며 이 설계에 구현/미관 검수를 수행하지 않았다. 문서 작성 관련 실행 검사와 실제 플레이는 하지 않았다.
