## 2. 무엇을 출시할 것인가

**권고하는 상품:** 귀여운 네 견습 마녀가 폭주한 마법 실험을 수습하며, 두 오브의 주문을 설계하고 마석으로 즉석 제작하는 1인 마법 조합 서바이벌. 짧은 실험을 여러 관점으로 반복해 네 실수와 최종 수습을 완결하는 작은 게임.

플레이어에게 약속하는 경험은 ‘내가 바꾼 순서와 연결이 실제 공격 행동을 바꾸고, 막히던 상황을 다른 조합과 판단으로 돌파한다’는 것이다. SD 미소녀와 사고 수습 코미디는 메뉴 장식이 아니라 캐릭터 반응과 결말을 통해 그 경험을 기억하게 만든다.

운영 가정은 Windows PC/키보드·마우스/오프라인 1인/Steam 정식판이다. 한국어가 기준이며 영어 제공은 권고 범위다. 플랫폼·가격·발매일과 상점의 지원 약속은 사용자 최종 결정이며 지금 확정되지 않았다. 현재 1마녀 데모는 제작 중간 검증 구간이고 아래 정식판 범위 전체와 같지 않다.

## 4. 한 판을 어떻게 완성할 것인가

현재 전투 상한5분을 초기 제작 기준으로 유지한다. 준비시간은 별도이며 플레이 압박을 위해 준비 타이머를 다시 넣지 않는다. 실제 전체시간은 초보/숙련/조합별로 측정하고, 시간이 짧거나 길다는 이유만으로 완성도를 판정하지 않는다.

| 도입/첫 웨이브 | 움직임·자동공격·회피와 기본 주문의 장단점을 파악 | 긴 설명 대신 직접 조작하고 안전하게 확인하는 짧은 안내 |

### 마녀의 개성을 실제 플레이로 만들기
루미의 즉흥적 복제, 네라의 세심한 주문 운용, 세라의 적 재배치, 모카의 이동/회피 같은 행동 방향을 이야기 구상에서 가져오되 공용 마법이 모두 의미 있게 쓰이도록 구체화한다. 캐릭터의 대사/표정/엔딩이 그 판단과 이어져야 한다.
네라의 독립 인형 소환은 현재 금지 조건과 충돌한다. 소환체 없이 자기 주문의 시전 위치/방향을 제어하는 범용 행동 등을 우선 설계한다. 정확한 액티브 동작·키·재사용 수치와 원안 변경은 승인 후 정한다. 설정상의 ‘마나 괴물’은 플레이 비용을 추가한다는 뜻이 아니다.

### 진엔딩과 교정 장치: 토론 후 보완안
사용자 이야기 원안은 네 마녀 클리어→교정 설계도4개 해금→한 판에서 장치4개 확보→진보스다. 아스트라는 정답 부품 수집 숙제를 우려해 4개 해금 후 최종 교정 실험 선택을 제안했다. 솔 검토는 메뉴만 바뀌면 사고를 직접 고쳤다는 이야기 보상이 사라질 수 있다고 지적했다.
총괄 권고는 **4설계도 해금 후 최종 교정 실험을 선택하되, 해금된 장치가 전장·보스의 예고/기믹·마지막 연출에서 실제 교정으로 드러나는 구성**이다. 전투6칸이나 유물 선택을 강제로 소비하거나 랜덤 장치4개를 다시 구입하는 숙제를 부과하지 않는다. 별도 수집 시스템도 추가하지 않는다. 원안의 조건을 바꾸는 제안이므로 승인 항목이다.

- 적/보스의 예고·실제 판정·피격/죽음, 아군/적 탄·지속영역·상태·희귀/강화 효과를 구분한다. 글리프를 임시 아이콘으로 쓴 현재 상태에서 오해하기 쉬운 항목을 우선 정리한다.
- 화려함이 적 탄과 바닥 경고를 가리지 않게 크기/불투명도/밀도 기준을 둔다. 현재 맵 전체를 다시 그리는 일은 목표로 삼지 않는다.
- 생성/구매/사용자 제공 아트·폰트·음악의 출처/수정 가능 원본/사용 범위와 크레딧을 자산 목록에 기록한다. 이 계획은 새 이미지를 생성하거나 기존 아트를 수정한 보고가 아니다.

### 음악/효과음/손맛
- 전투·준비·보스·결과 분위기를 나누는 음악, 발사/명중/피격/회피/마석/유물/제작/강화/합성/UI의 구별되는 소리.
- 많은 탄이 나가도 소리가 한 덩어리로 찢어지지 않게 우선순위·동시 재생·음량 기준. 아트·소리·짧은 움직임이 같은 사건을 전달하게 한다.
- 위험과 성공을 소리 하나에만 맡기지 않는다. 음소거/효과 완화에서도 필요한 정보가 남아야 한다. 흔들림/섬광/과도한 정지를 강제하지 않는다. 성우/풀 보이스는 선택.

### UI/첫 진입/접근성
- 두 오브의 독립 시전, 보조 적용 범위, 후속 연결, 강화 결과·소비·초과 차단을 글을 길게 읽지 않고 파악하게 한다. 이미 있는 드래그·되돌리기·시험 발사를 보존.
- 짧은 첫 조작/첫 제작 안내와 반복 시 생략, 필요한 때 보는 도움말. 잘못 넣은 구체나 부족한 마석은 위치와 해결 방법으로 알려준다.
- HUD/제작/강화/합성/유물/캐릭터/결과/기록/설정/크레딧의 용어·정렬·버튼 반응을 통일. 한 판 종료 후 다음 시도까지 불필요한 클릭을 줄임.
- 음량·창/전체화면·키 변경·가독성·색외 모양 표시·효과 강도·흔들림/섬광 완화, 포커스 이동/팝업/일시정지 처리. 지원 해상도·비율에서 잘림과 클릭 위치 확인.
- 한국어 기준 용어표와 문자열 분리. 영어 등 지원 언어는 실제 번역·폰트·줄바꿈 검수 후 상점에 표기. 게임패드/SteamDeck은 미구현 상태에서 지원 약속하지 않음.

## 7. 기술·저장·검증·회복
- 설정/해금/엔딩/발견/기록 프로필을 런의 임시 아이템과 분리. 저장 버전·이전 버전 이전·백업·중단/손상 복구. 중간 저장은 긴 준비/실제 세션 길이 관찰 후 필요 여부 결정.
- Git과 복구 지점, 반복 가능한 내보내기/버전 식별/진단 로그, 개발PC 경로·MCP·측정 도구의 배포 포함 정책. 기존 파일과 원본 자산 보존.
- 보스 생성 실패/수량 소비/강화 초과/연결 중복/강제 정리/두 오브/시험 상태 분리 등 실제 위험에 관련 검사. 모든 편집 때 전체 검사를 반복하지 않는다.
- 일반/보스/최대효과 대표 빌드를 배포판에서 같은 조건으로 측정. CPU/렌더/메모리/장판·탄 수를 기록하고 병목을 해결. 화력/연결을 몰래 생략하는 상한으로 성능을 합격 처리하지 않음.
- Windows 에디터 없는 새 환경에서 설치/시작/종료/해상도/입력/오디오/업데이트/세이브/복구를 확인. 최소사양은 실제 측정 후 표기.
- 내부 검사 통과, 동작 확인, 사람의 재미/이해 관찰, 구매 기대 일치는 서로 다른 증거로 보고.

## 8. 출시 준비와 출시 이후
상점과 유저가 받을 실제 빌드를 함께 관리한다. 대표 완성 구간과 상품 범위가 안정되면 Coming Soon 자료 준비를 콘텐츠 확장과 병행하고 마지막에 몰지 않는다.

| 영역 | 준비할 것 | 완료 증거 |
|---|---|---|
| Steam 등록 | 계약 주체·계정/권한·앱·결제/은행/세금/신원 확인 | 사용자 명의 등록/승인. AI는 초안·체크리스트 지원 |
| 상점 | 한 문장/소개/태그/지원환경·언어·가격안, 로고/캡슐/라이브러리 자산 | 실제 빌드 내용과 일치하는 검토 가능한 상점 초안 |

Steam 공식 문서 기준 상점과 빌드 검토가 모두 필요하며 자동 출시되지 않는다. 광고한 기능은 실제 빌드에 있어야 한다. 실제 플레이 스크린샷 최소5장과 캡슐/로고 규격, Coming Soon 최소2주 등 일정 조건도 준비 범위다. 생성 프로토타입을 배포에 유지하면 실제 생성콘텐츠 사용 내역을 설문에 정확히 반영한다. 계정 초기 등록·대기·검토 조건은 적용 시 다시 확인한다. 근거/직접 링크는 [총괄 운영 자료](meetings/OPS-RELEASE-20261026.md)에 정리했다.

등록·계약·결제·신상/세금·은행 제출·가격 확정·외부 연락·상점 공개·발매는 실제 사용자 명의와 승인이 필요한 단계다. 이번 회의는 이를 대신 실행하지 않았다. 출시 후에는 재현 가능한 버그/세이브 손실/실행 실패를 우선 처리하고 밸런스·내용 업데이트는 별도로 검토한다. 온라인 계정·상시 접속·멀티 서비스는 이번 기본 제품 범위가 아니다.

## 9. 실제 제작 순서와 통과 조건

| 단계 | 주 작업 | 통과 조건 | 역할 |
|---|---|---|---|
| A. 상품 기준 | 이 문서의 범위·세 승인 항목·콘텐츠/아트 제작표 | 무엇을 팔고 언제 완성이라 부를지 한 안으로 고정 | 총괄 취합, Astra 설계, Sol 독립 검토 |
| B. 한 마녀의 완주 경험 | 루미 도입→전투성장→보상/제작→완성조합활용→전용보스→일반엔딩→복기/재시도, 대표 아트/사운드 샘플 | 모든 장면이 이어지는 실제 한 판. 이는 정식판 완료가 아닌 검증용 경로 | 총괄 구현, 필요한 좁은 조사/위험 검토 |
| C. 처음 하는 사람 확인 | 같은 빌드·관찰 질문으로 도움 없이 진행 관찰 | 막힌 지점·완성조합 사용 시간·다음판 동기를 근거로 수정. 재미 없으면 구현량과 무관하게 축소/교체 | 사용자/외부 플레이어, 총괄 분석 |
| D. 정식 콘텐츠 확장 | 검증된 틀로 나머지 마녀/성격반응/엔딩, 적 역할·두번째보스/교정실험·해금 | 네 판이 단순 외형/무기 바꾸기 반복인지 확인. 이야기 결말/기믹과 저장 연결 | 총괄 구현, Astra 좁은 설계자문, Sol 조건부 검토 |
| E. 제품 마감 | UI/음향/애니메이션/접근성·언어/성능·세이브·배포QA | 실제 광고 환경에서 읽힘/조작/실행/복구/진행을 통과, 치명 미해결 없음 | 총괄, Luna 지정조사, Sol 독립 검토 |
| F. 공개와 출시 | 실제 내용 기반 상점/데모/검토·가격/발매·지원 | 자료·배포물 일치, 인간 플레이 근거와 사용자 최종 공개/발매 승인 | 총괄 준비, 사용자 상업/공개 결정 |

버전 관리·독립 빌드·프로필 저장은 B부터 작동시키며 E에서 처음 만들지 않는다. Steam 등록/상점 자료는 대표 품질이 보이는 시점부터 병행한다. 기존 보스 안전장치는 B의 진행 안정성 하위 업무다. 이전 기술5개를 다시 유일한 전체 개발 순서로 삼지 않는다.

시간/토큰·아트 비용은 아직 신뢰할 추정이 없다. B의 실제 제작 속도와 C의 재작업량을 본 뒤 D/E 비용과 일정을 추정한다. 상시4에이전트 회의 대신 총괄이 단계별 좁은 업무를 배정하며 담당·실제모델·결과·미확인을 보드에 기록한다.

## 10. 승인 대상으로 남기는 세 가지
1. **형태/분량 방향:** 5분 전투를 출발점으로 하는 4마녀 소형 완결작. 긴 한 판·큰 맵 대신 성장/완성/결말의 밀도를 우선. 시간은 플레이 결과로 해당 구간을 조정.
2. **마녀 차이:** 공용 마법을 유지하는 고유 행동과 성격 반응. 네라의 독립 소환 구상을 소환체 없는 주문 운용으로 수정. 구체적인 액티브/키/수치는 다음 설계 작업.
3. **진엔딩 진입:** 원안의 한 판 장치4개 구매를, 4설계도 해금→선택 가능한 최종 교정 실험→전투/기믹/결말로 보이는 실제 교정으로 변경.

이는 제안이지 구현/최종 사용자 합의 기록이 아니다. 모든 세부를 사용자에게 다시 정하도록 넘기지 않으며 이 안을 총괄 권고안으로 제시한다. 가격/스토어 계정/발매일 같은 외부 상업 결정은 위 설계 세 항목과 별개로 실제 준비 때 확정한다.

## 11. 무엇을 이번 최소 범위에서 빼는가
멀티, 새 마나/소환 시스템, 장비100종/마법77종을 옛 프로젝트에서 무조건 가져오기, 거대 절차맵/새 바이옴/탐험 미니맵, 무조건 더 긴 웨이브, 영구 공격력 노가다, 풀 보이스, 별도 캠페인4개, 강제 일일과제·온라인랭킹은 포함하지 않는다. Steam 업적/클라우드·게임패드/SteamDeck·추가언어·준비사건·하드모드/엔드리스는 효과와 비용을 보고 선택한다. 선택 기능을 상점에 약속하면 실제 제공·검증이 필요하다.

## 12. 회의에서 확인한 이견과 취합 결과
- **Luna:** 현재 이미 마법 부품과 유물은 있다. 오래된 문서 숫자를 그대로 늘리는 작업이 해답이라는 근거는 없다. 총괄이 현재값으로 정리.
- **Astra:** 짧은 실험과 네 실수/엔딩을 묶는 작은 완결작, 현재 전투시간과 마법풀 유지 권고. 총괄이 채택할 방향으로 제시.
- **Sol 검토:** ‘3적/2보스/4마녀’라는 수량은 상품 충분성의 증거가 아니며 성장곡선/마녀별 판단/진엔딩의 교정감이 없으면 반복 분량 채우기. 총괄이 단계C의 실제 관찰 기준과 교정기믹 보완으로 반영.
- **총괄:** 준비 사건은 선택, 1마녀 경로는 중간 검증, 저장/배포/상점은 병행 준비. 아트/사운드/사용성·해금/이야기 완성을 정식 범위에 명시. 이전 버그중심계획을 전체 출시계획으로 제시한 오류를 바로잡음.
