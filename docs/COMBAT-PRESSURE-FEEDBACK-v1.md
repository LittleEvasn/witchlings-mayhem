# 전투 압박·이동 목적 · 실플레이 피드백

2026-10-26. 사용자: 적이 너무 약함 / 유도+벼락으로 제자리 생존 / 맵 이동 이유 없음 / 제작까지 대기가 길게 느껴짐. 중간 마법3중1택·전장이 보이는 인벤·향후 멀티 개인창 비정지·마법 확장은 후속 아이디어다. 이번에는 게임 코드/수치/UI를 바꾸지 않았다.

## 확인한 원인
- 현재 일반 전투 길이90/105/120/135초. 첫 세 웨이브 원거리 상한0, 첫 두 웨이브 정예상한0. 초반 일반 생성2~2.8초마다1~2명과 간헐무리. 기본근접속도58+웨이브×3, 플레이어240. 접근 전에 처리하는 화력이면 압박이 사라지는 구조.
- 벼락+추적은 낙뢰 지점 주변160×추적강도의 적 표적을 잡고 예고 일부를 추적. 전역 자동조준은 아니다. 사용자 정지생존은 실제 피드백이며 코드에서 충분한 원인을 확인했지만 이번에 직접 재현/성능측정을 하지는 않았다.
- 위 코드 범위에 위치별 목표·방문 보상이 없고 마석은 웨이브 종료 때 전량 회수. 이동은 회피 외 이득이 적다. 마석 줍기 의무를 늘리는 것만으로 탐험 재미를 대체하지 않는다.
- 이전 97검사·무적봇완주·성능검사는 재미/회피 필요성의 검증이 아니었다. 전투 길이를 늘리면서 압박·중간 보상 빈도를 함께 맞추지 않은 설계상의 부족함이다. 제작시간이 무제한이라 길다는 문제가 아니라, 제작 진입 전 전투가 기다림으로 느껴지는 피드백이다.

## 괴수공주 참고에서 구분할 것

- AprilEnemySpawner 일반 모드 waveTime은 min(20+(wave-1)*5,60)이며 StartWave가 해당 카운트다운을 사용. 일반 생성·이벤트무리·보물생성 타이머가 별개다. 기본 일반적 상한150은 코드초기값으로, 실제 직렬화/실행 상한을 측정한 수치가 아니다.
- ExploreManager와 TreasureEnemyGroup에는 화면밖 탐험목표 등록/방향표시와 배회·도망가는 보물 무리 경로가 있다. 사용자가 원하지 않았던 건물파괴는 우리 제안에서 제외. 정확한 적HP/수/속도를 측정했다고 주장하지 않는다.
- 참고할 것은 많은 적만이 아니라 전투 압박·짧은 성장 간격·이동 보상 결합이다. 공식 소개도 전투와 상점 성장 흐름을 설명하지만 정량 난이도를 입증하지 않는다: https://store.steampowered.com/app/4234750/

## 권고 우선순위
1. 기존 마법을 유지하고 초반부터 소수 원거리/빠른 접근/예고 후 지점 공격을 적절히 섞는다. 무작위 출현은 유지. 모든 방향 동시 예고나 유도면역으로 강제 이동시키지 않는다. 대량의 약한 적을 지우는 쾌감과 가끔 빠져나가야 하는 압박을 함께 만든다. HP만 일괄 증가시키지 않는다.
2. 초반 제작 진입을 짧게 하고 중간 목표 빈도를 조정한다. 첫90초는 재검토 대상. 이전 총12~15분 목표를 채우려고 지루한 전투를 유지하지 않는다. 먼저 첫1~2웨이브에서 지루함/제자리생존을 확인한 다음 전체시간을 재조정한다.
3. 보물 운반 실패작/작은 보상 거점 등 선택적인 이동 목표1~2종. 정예 처치나 접근으로 마법3중1택을 받는 방향은 후속 제안. 일반 적 보상에서 재원을 일부 옮겨 전체 성장량을 통제. 맵 확대/건물파괴/마석 회수 번거로움 강제는 하지 않는다.
4. 전투용 얇은 인벤은 화면 한쪽 약1/3, 나머지 전장과 플레이어를 보이게. 보상은 즉시 전체창 강제가 아니라 대기 후 선택 가능하게. 세계 시뮬레이션과 개인 UI상태를 분리한다. 멀티 구현은 여전히 후속이며 비정지 편집은 아직 적용하지 않는다. 적을 강화하면서 큰 편집창까지 즉시 비정지화하면 편집할 시간이 없다는 문제를 별도로 해결해야 한다.
5. 새 마법은 적은 행동 수로 판단할 이유가 부족한 지점부터 추가. 현재 적·목표 문제가 해결되지 않으면 강한 정답/아무거나 승리 문제는 구체 수 증가로 해결되지 않는다. 탄 색만 다른 확장보다 적탄 대응·밀어내기·위치 활용 등 다른 판단을 주는 역할을 검토.
