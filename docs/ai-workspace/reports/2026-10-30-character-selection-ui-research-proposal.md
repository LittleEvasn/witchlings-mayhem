## 3. 레이아웃 대안

### A. 네 명 가로 카드형
- 네라/루미/모카/세라를 같은 크기의 인물 카드 4장으로 나란히 배치.
- 장점: 네 명을 동시에 비교하고 관계를 보여주기 쉬움.
- 한계: 캐릭터 설명, 시작 주문, 시작 버튼이 함께 붙으면 카드마다 작은 글씨와 중복 정보가 늘어남.

### B. 대형 선택 인물 + 4인 초상화
- 선택한 캐릭터 한 명의 **큰 전신 또는 상반신 일러스트**와 핵심 정보를 크게 표시.
- 네 명은 작은 고정 초상화로 탐색. 선택 초상화와 본문·배경 컬러가 함께 변경.
- 장점: 네 명 규모에서도 선택 인물의 존재감, 이름, 고유 능력 전달이 선명.
- 한계: 비교하려면 여러 인물을 차례로 선택해야 함.

### C. 실습실 장면형
- 마법 실습실에 네 명이 모여 있고 클릭/포커스로 선택.
- 장점: `마녀들의 사고현장`이라는 세계관과 관계성을 화면만으로 전달.
- 한계: 별도 배경 배치, 포즈, 애니메이션과 클릭 영역 관리 등 제작 부담이 큼.

### 우선 추천: **B안의 정보 구조 + C안의 배경 분위기**

- 배경은 기존 실습실 톤을 활용하되 세부 장식의 대비를 낮춘다.
- 선택한 마녀의 그림을 화면의 가장 큰 시각 요소로 배치한다.
- 나머지 마녀는 **고정 위치의 4개 초상화 버튼**으로 제공한다.
- 선택 인물 오른쪽에 이름, 한두 줄 소개, 실제 존재하는 고유 능력을 표기한다.
- 다음 버튼은 명확히 `이 마녀로 선택` 또는 `다음: 시작 주문`이라고 표시해 버튼을 누르기 전엔 전투가 시작되지 않도록 한다.
- 기존 반응형 스킨·버튼 및 일관된 슬롯/프레임 스타일과 조화를 이루며, 구매형 GUI 에셋 도입 여부는 별도 결정으로 남긴다.

## 4. 개념적 화면 배치 (확정 픽셀 아님)

기준 `1600×900` 화면에서 시작하는 **레이아웃 후보**:

```text
┌────────────────────── 마녀를 선택하세요 ─────────────────────┐
│                                                             │
│       [선택한 마녀의 큰 전신 일러스트]   마녀 이름           │
│                                       한두 줄 소개          │
│                                       (구현된) 고유 능력     │
│                                       플레이 스타일 요약     │
│                                                             │
│            [네라]   [루미]   [모카]   [세라]                   │
│                                                             │
│   [타이틀로]                          [다음: 시작 주문 →]     │
└─────────────────────────────────────────────────────────────┘
```

- 인물/설명/초상화/확정 버튼의 계층을 우선 검토한다. 위 배치는 구조도이지 실제 UI 스크린샷이 아니다.
- `1280×720`, `1600×900`, `1920×1080`에서 잘림 및 빈 공간 문제를 확인한 뒤 실제 수치 확정.
- 마우스 오버/포커스 시 해당 캐릭터가 강조되더라도 **선택 완료(확정)**는 별도 행동으로 분리.

## 5. 권장 플레이 흐름과 단계별 도입

**향후 목표 흐름(제안):**

`타이틀 → 마녀 선택 → 시작 주문 선택 → 선택적 도입 → 전투`

- **마녀 선택:** 누구로 플레이할지 결정.
- **시작 주문 선택:** 현재처럼 시작 조합 4개 중 하나 선택. 캐릭터와 조합의 관계는 향후 캐릭터별 밸런스 설계에서 결정하며 지금 일괄 공유를 확정하지 않는다.
- **도입 이야기:** 현재 토글/건너뛰기 및 전투 전 정지 처리 유지.
- **실험 시작:** 선택/탐색으로 자동 개시하지 않고 별도의 확정 동작 유지.

**현 구현에 적용할 현실적인 단계:**
1. 첫 단계는 **루미 한 명 + 기존 4개 시작 조합**을 유지하면서 화면의 선택 인물 강조와 시작 조합 가독성을 개선해도 된다. 다수 인물 선택 기능이 없어도 화면 완성도를 검토할 수 있다.
2. 네라·모카·세라의 실제 플레이 기능과 구분된 능력이 준비되면 초상화 탐색 영역을 확장한다.
3. 그때 단일 준비 화면에 캐릭터/주문을 탭으로 둘지, 2단계 페이지로 나눌지 사용자 결정 후 적용한다.

**미구현 캐릭터 표시:** 아직 조작할 수 없는 마녀를 메뉴에 노출한다면, `준비 중` 등 실제 구현 상태를 분명히 나타낸다. **게임 내 정식 잠금·해금 조건으로 오인될 표현을 임의로 부여하지 않는다.** 고유 능력과 수치도 구현 전에는 가공하지 않는다.

## 8. 실제 구현 시 독립 완료 조건 (이번 작업에서 검사하지 않음)

1. 플레이 가능 캐릭터와 미구현 캐릭터가 명확히 구분되며, 미구현 버튼으로 전투가 실행되지 않는다.
2. 선택 초상화를 바꾸면 큰 일러스트/이름/능력 요약/선택 강조가 일치한다. 해당 자산이 없으면 임시 플레이 가능 표시를 만들지 않는다.
3. 캐릭터를 탐색하는 행위만으로 게임 시작/기존 저장 덮어쓰기/자원 소비가 일어나지 않는다.
4. 캐릭터 선택과 시작 조합 선택 각각의 확정·취소·되돌리기 상태가 예상대로 보존된다.
5. 네 시작 조합의 실제 레시피와 `Economy.KITS` 지급 결과가 화면 표시와 일치한다.
6. 처음 진입/반복 진입/타이틀 복귀/도입 건너뛰기/재도전에서 선택이 섞이지 않는다.
7. 마우스, Tab/화살표, Enter, Esc 및 필요한 경우 패드 포커스가 모든 활성 요소에 도달하며 오선택하지 않는다.
8. `1280×720`, `1600×900`, `1920×1080`에서 캐릭터가 잘리거나 버튼이 가려지지 않는다.
9. 실제 Godot 렌더와 입력 검사 결과를 각각 남기고, 기존 타이틀/도입/결과 화면의 회귀를 검사한다.
10. 실제 화면 확인, 자동 테스트, 사용자 시각 승인, 재미/선택 만족감은 구분해 기록한다.

## 9. 사용자 결정이 필요한 부분

1. **정보 구조:** B안 대형 인물+초상화 4개 및 실습실 배경(C안 일부)을 채택할지.
2. **선택 단계:** 캐릭터와 시작 조합을 *별도 화면*으로 나눌지, 기존 한 화면 안에서 두 단계/탭으로 둘지.
3. **캐릭터 차이:** 실제로 각 마녀가 다른 고유 능력/기본 능력치를 갖는지, 외형 차이인지.
4. **미구현 캐릭터:** 선택 불가로 공개할지, 실제 플레이 기능이 준비될 때까지 아예 숨길지.
5. **표현 자산:** 큰 일러스트/SD/스프라이트 중 어느 쪽을 캐릭터 선택 화면에 쓸지.

위 선택은 제안 단계에 있으며, **사용자 요청 전 구현을 시작하거나 기존 준비 화면을 강제로 변경하지 않는다.**
