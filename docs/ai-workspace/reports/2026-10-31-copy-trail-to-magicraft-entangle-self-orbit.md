## 1. 최신 확정안 — 반드시 구현할 동작

**현재 복제 궤적(`trail`)을 마법공예 휘감기(Entangle, 3204)의 '부모를 중심으로 하위 마법이 회전'하는 구조로 교체한다.**

단, 원작은 **뒤에 이어지는 다른 하위 마법**을 부모 주변에 생성하지만, **우리 게임은 뒤 슬롯에 관계없이 부모와 동일한 마법을 복제**하여 **그 부모 주변을 공전**하게 한다.

- **발동**: 부모 공격 마법이 생성/발사될 때 해당 부모를 중심으로 복제 마법을 배치하고 공전하게 한다. 기존의 이동거리 90 누적이나 이동 중 순차 방출은 **신규 기준이 아님**.
- **복제 대상**: 복제본은 같은 부모 마법의 **실제 공격체**다. 투사체라면 모양만 같은 점이 아니라 고유 공격 성질·적 접촉/피해를 가진 개별 공격체여야 한다. 시각 잔상/VFX-only/피해 없는 장식은 불합격.
- **회전 중심**: 매 프레임 **자신의 부모 공격체 위치**를 기준으로 원형 궤도 위에 배치한다. **플레이어 중심의 공전**이나 초기 좌표에 고정한 원형 배치로 대체하면 안 된다.
- **배치**: 같은 고리에 **균등한 각도 간격**으로 복제본을 펼치고 부모의 움직임에 따라 회전 고리도 이동한다. 첫 시작각도 무작위 또는 결정적 시드 구현은 추후 선택하되, 간격은 고르게.
- **재귀 방지**: 복제본이 스스로 또 다른 2~5개를 무한 생성하지 않는다.
- **연결 구체와 분리**: `A + 복제 궤적`만으로 `A` 주변 복제본이 생긴다. 마법공예 원작의 후속 주문 `B`가 필수인 문법으로 바꾸지 않는다.
- **기존 카드·저장 호환**: 내부 ID `trail` 우선 유지. '휘감기'는 **참고 메커니즘 이름**이고, 현재 표시명 **‘복제 궤적’**을 직접 '휘감기'로 변경할지 여부는 별도 확정 필요. 효과 설명은 반드시 신규 동작으로 수정한다.

## 2. 참고작 동작과 우리 개편의 차이

### 마법공예 휘감기(Entangle; `OnStartRotationTrigger`, ID 3204)

공개된 제3자 PC 역컴파일 자료에서 확인된 사실:

- `ShootSpellUtils.SipToSSP`: `OnStartRotationTrigger`의 `int2`를 합산해 **`TwineTriggerComponentData.Count`**, `float1`의 최댓값을 **`Radius`**로 만든다.
- `SpellTwineTriggerSystem.OnUpdate`: 부모 생성 후 `SubGroup`을 불러 **Count개 자식 주문**을 발사한다. 첫 회전 각도는 무작위, 이후 **360°/Count** 간격으로 자식들의 회전 시작각도를 균등하게 부여한다.
- 자식은 `SpellTag.Twine`, `RotationMovementInfo`가 설정되어 **회전 이동**한다. 처리한 부모의 `SpellTwineTriggerComponentData`를 **disabled**로 전환하여 해당 생성 트리거를 일회성으로 처리한다.
- 과도한 발사량에 대한 복잡도·프레임 예산 최적화 경로가 있지만, **자식을 단순히 생략해도 정상 완성**이라고 주장해서는 안 된다.
- 원작 **Lv1/Lv2/Lv3**는 `int2 = 3 / 5 / 8` (우리 2/3/4/5와 **다름**). `float1=2`는 원작의 월드 단위 반경으로, **우리 Godot 픽셀값 2가 아님**. 이것들을 우리 값으로 자동 이식하지 않는다.
- **원작은 하위 주문을 회전**시키며, **우리 프로젝트는 부모 자기 자신을 복제해 회전**시킨다는 것이 의도적 차이이다.

### 폐기되는 기존 방향

1. **기존 `trail` 동작**(노이타 Copy Trail 참고): **90 이동거리마다 저위력 잔상** + 최대 2/3/4/5개 + 피해 20% + 복제본 재복제 금지 → **교체 대상**. 단 생성 수 2/3/4/5만 새로운 **동시 공전 복제본의 개수**로 확정하며, 기존 '90 이동거리'와 '20% 피해'는 이번 사용자 새 승인 내용이 아니다.
2. **2026-10-31 이전 보고서 MAGIC-CHAIN-2026-10-31-01**: 마법공예 **연쇄(3203)식 부모 이동 중 측면으로 자기 마법 발사** → 사용자 최신 요청으로 **SUPERSEDED**. **연쇄 이동 트리거·좌우 90° 교대·후속 발사 규칙을 구현하지 않는다.**
3. **마법공예 `공전(orbit)` 보조**는 별도로 존재한다. 휘감기식 `trail`의 **'부모 중심 자식 고리'**와 일반 `orbit`의 기준점·속도를 동일 기능으로 취급하거나 `orbit` 카드를 무단 폐기하지 않는다.

### 구현자에게 중요한 추가 주의

- **부모·복제본 식별**: 부모의 개별 마법 ID를 참조하는 궤도 앵커가 필요하다. 여러 오브/동시에 여러 부모가 발사될 때 서로 다른 고리끼리 섞이거나 모두 플레이어를 중심으로 회전하면 실패.
- **공격 성질**: 부모의 피해/반경/원소/관통/속도/수명을 그대로 상속할 범위는 충돌 테스트와 함께 결정. **이전 피해 20%를 조용히 확정 유지하지 않는다**.
- **추가 생성 권한**: 분열·보조 메아리·새 연쇄 개편안(폐기)·후속 연결 등 재귀·증식 효과는 의도한 한 세대만 발생해야 한다. 자식이 부모의 후속 연결을 임의 중복 발동하면 안 된다.
- **비투사체**: 레이저(즉발), 장판/잔불, 위성, 도약/낙하, 설치 씨앗, 부메랑 등의 공격은 단순히 좌표만 움직이는 반짝임으로 대체해서는 안 된다. **휘감기 복제본이 실제 공격을 하는지** 유형별 검사하고 호환 예외가 필요하면 별도 보고.
- **종료/지연 생성**: 부모가 사라진 뒤 고리가 잘못 남거나 텔레포트·다음 웨이브·게임오버 뒤 공격이 발생하는 현상을 방지. **자식 수명·부모 사망 이후 동작**은 아직 확정하지 않은 세부 계약이므로 임의의 원작 고증이라 단정하지 않는다.
- **성능**: 모든 발사에 원본 외 2~5개가 증가한다. 다수 적·4오브·중복 보조에서 생성 제한을 이유로 **설명된 자식 수가 조용히 줄거나 실피해가 사라지면 완료 아님**.

## 4. 구현 완료 기준 / 검사 설계

1. **대표 시전(고정 생성 수)**: `복제 궤적 + 별빛탄(bolt)`을 0/+1/+2/+3강으로 시전할 때 복제본 **2/3/4/5**, 원본 포함 **3/4/5/6** 실제 공격체가 생긴다. 보고된 수치와 실제 공격체 수가 일치한다.
2. **각도/이동**: 2개면 180°, 3개면 120°, 4개면 90°, 5개면 72° 간격을 유지. 부모가 움직여도 **고리 중심은 부모**이며, 원본의 위치 변화를 따라간다. 고정 원형 생성만 하고 공전하지 않는 구현은 불합격.
3. **실제 피해**: 적이 자식의 궤도에 접촉하면 **자식이 적을 타격하고 유효 피해를 준다**. 부모/복제본별 피격 중복 판정도 확인한다. 생성·그리기만 성공한 것을 실제 마법 작동 성공으로 확대하지 않는다.
4. **재귀/중복**: 생성 순간 복제본마다 추가 `trail` 발동이 없다. 부모가 둘 이상이면 각자 고리를 유지. 복제·분열·다단히트·연결/유물·메아리와 겹칠 때 생성권한 무한 증식과 예약 유실이 없는지 확인한다.
5. **특수형**: 부메랑/광선/장판/위성/소멸/명중/낙하 등 대표 사례별 독립된 실제 동작·충돌·수명 종료를 확인한다.
6. **수명/화면/부하**: 부모 종료·경계 이탈·전투 종료·다음 웨이브·저FPS·고부하 시 좌표 고아 참조나 이상 발사 없음. 실제 렌더·공전 애니메이션·프레임 처리·실피해 측정은 별도 증거로 보고한다.
7. **중복 보조와 강화**: 동일 `trail` 보조를 여러 장 달았을 때 기존 합산 코드의 의미가 무엇인지 별도 결정하고, 가방/편집/강화 UI와 보상 도감 설명에 표시한다. 중복 2장에 **자동으로 4/6/8/10개 추가**를 확정한 것은 아니다.
