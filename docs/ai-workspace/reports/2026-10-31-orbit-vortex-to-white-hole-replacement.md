## 1. 사용자 확정 개편

### 1.1. 정체성·합성 관계

- 합성 마법의 새 표시명은 **화이트홀**.
- 현재 합성 레시피 **소용돌이 씨앗(`vortex`) + 공전(`orbit`)**은 **그대로 보존**한다. 재료 자체를 다른 카드로 바꾸라는 지시는 없었다.
- 기존 내부 합성 식별자 `orbit_vortex`는 **기존 세이브·레시피 호환을 위한 유지 권고**이다. 새 표시명과 내부 ID를 구분한다.
- 이미 승인된 **소용돌이 씨앗 → 마법공예 블랙홀(1007) 방식** 변경을 기본 비교 대상으로 삼는다. 화이트홀은 **그 블랙홀의 발사/이동 방식 그대로 발사**하되 영향을 받는 적에게 가하는 힘의 방향만 **흡인 → 반발**로 뒤집는다.
- 기존 합성 `orbit_vortex`의 별도 쌍핵 공전/적 이송 정체성은 이 사용자 결정으로 **SUPERSEDED**. 독립 보조 카드 `orbit` 자체의 다른 주문에 대한 공전 동작 승인 사항은 삭제하거나 변경하지 않는다.

### 1.2. 블랙홀과 화이트홀 동작 비교

| 항목 | 기본 소용돌이 씨앗 = 개편 예정 블랙홀(`vortex`) | 완성 합성 화이트홀(현 ID `orbit_vortex`) |
|---|---|---|
| 발사 | 블랙홀식 투사체 발사 | **같은 방식으로 발사** |
| 이동 | 마법공예 블랙홀 참고 이동형 개체 | **같은 이동 경로/방식** |
| 범위 효과 | 주위 적을 **중심으로 끌어당김** | 주위 적을 **중심에서 바깥으로 밀어냄** |
| 피해 | 주기적 범위 피해 | **주기적 범위 피해 유지** |
| 범위 성장 | 블랙홀의 시간 경과 기반 성장 정책 | **기본적으로 같은 성장 구조** |
| 소멸 | 블랙홀의 수명/정리 규칙 | **같은 정상 종료 구조** |
| 개체 구성 | 단일 블랙홀 | **단일 화이트홀** (쌍핵 공전 아님) |

- 반발은 **중심 좌표에서 적의 위치를 향하는 방사 방향**으로 이동/힘을 가하는 메커니즘이다. 반대 핵으로 좌표를 **순간이동**시키는 현재 이송 코드를 재활용해 반발을 흉내 내면 안 된다.
- ‘블랙홀과 동일’은 **발사·이동·성장·수명 및 주기 피해의 작동 구조**를 의미한다. **정확한 피해 배율, 반발 힘 크기, 보스/엘리트에 대한 강도, 밀침 저항** 등은 사용자 미지정. 블랙홀 코드가 아직 개편 전이므로 현재 구형 `vortex`의 수치·이동을 ‘완성된 블랙홀 원본’으로 오해하지 않는다.
- **기존 블랙홀의 소용돌이끼리 합체·겹침 성장 폐기** 계약은 화이트홀에도 부합하게 설계한다. 서로 다른 개체 중첩의 구체적 배치 정책은 블랙홀 보고서에서도 미확정이므로 여기서 임의 확정하지 않는다.

### 1.3. 삭제할 과거 합성 전용 동작

다음은 기존 공전 소용돌이의 더 이상 유효하지 않은 고유 효과이며, **화이트홀 구현 시 제거**한다.

1. **흡인핵 2개**를 서로 마주 보게 생성하는 동작.
2. 두 핵이 **공전**하는 합성 전용 동작.
3. 흡인 대상 적을 **반대편 흡인핵 위치로 옮기거나 순간이동**시키는 로직.
4. '서로 마주 도는 흡인핵 둘 · 포획한 적을 반대 핵에 넘김'이라는 구형 **툴팁·도감 설명**.

## 2. 현재 코드 사실(아직 미구현)

- `scripts/magic_catalog.gd`의 `FUSIONS.orbit_vortex`는 여전히 `name="공전 소용돌이"`, `parents=["vortex","orbit"]`, `base="vortex"`이며, 쌍핵 이송 설명이 등록되어 있다.
- `scripts/magic_extensions.gd`에서 현재 `orbit_vortex`는 설치형 `vortex`에 대해 `_motion="orbit"`, `_transfer_ids`를 설정하고 **반대편 위상의 twin 개체**를 생성한다. 적 이동은 `e.position=...` **즉시 좌표 변경** 방식이다. 화이트홀의 **연속적 방사 반발**이 아니므로 교체해야 한다.
- **기본 블랙홀의 원작식 개편은 승인된 보고서 단계이며, 현재 Godot 게임 코드의 구형 `vortex`를 기준 완성형으로 취급할 수 없다.**
- `docs/MAGIC60-IMPLEMENTATION-v1.md`의 기존 합성 설명도 쌍핵 이송이며, 해당 과거 구현 기록은 보존하되 **새 승인 방향은 본 보고서가 우선**한다.

## 3. 미확정 사항 — 제안과 확정을 구분

1. **반발 강도, 반발 범위, 보스/엘리트 밀침 저항, 벽·지형과의 충돌 처리**.
2. **화이트홀의 피해 배율** 및 반발로 피해 범위에서 빠져나가는 적에 대한 실제 누적 피해 밸런스 보정.
3. **반경·성장 속도·피해 틱·지속시간**의 구체적 Godot 수치: 블랙홀 확정 수치 매핑이 먼저 필요하다. '같은 구조'는 숫자 1:1 확정이 아니다.
4. 발사체의 색·형태·시각 효과: **밝고 방출적인 연출**은 방향성 제안. 정확한 VFX·아트 에셋은 미확정.
5. 기존 레시피에 공전 보조가 들어 있지만 **화이트홀 자체는 공전하지 않는다**. 재료 교체는 사용자가 지시하지 않았으므로 하지 않으며, 향후 레시피 적합성 검토 사항으로만 남긴다.

## 4. 향후 구현 시 사용자 요구에서 도출한 검증 조건

1. **기본 블랙홀**과 **화이트홀**을 같은 조준 방향으로 각각 시전해 **발사 시작·이동 경로·지속시간·범위 성장 구조**가 대응하는지 실제 좌표/피해/화면으로 비교한다.
2. 블랙홀은 **흡인**, 화이트홀은 **반발**이 실제 적 위치 변화로 나타나야 한다. 원형 그래픽 색만 변경하거나 넉백 이펙트만 보이는 경우 **불합격**.
3. **화이트홀 1개만 생성**, 기존 2개 쌍핵·공전·반대편 순간이동 이벤트는 발생하지 않아야 한다.
4. 밀려나는 적에게도 **실제 피해 판정이 작동**해야 한다. 동일 강도/밀도 적을 상대로 블랙홀·화이트홀 누적 피해를 대조하고, 반발로 조기 이탈하는 문제를 검토한다.
5. 0/1/10/다수 적, 보스·엘리트, 벽·맵 경계, 강화 0~3, 갈래·낙하·추적·연결·분열·일반 공전 보조·다중 오브 등 대표/경계 상황을 확인한다.
6. `collapse_vortex`(붕괴 소용돌이)와 `thorn`(가시꽃 덫) 등 다른 마법의 합성/중첩 계약을 변경하지 않는다.
7. **새 구현 요청 후** Godot 구문·실제 생성·이동·실피해·UI·부하·게임 체감 검증을 각각 별도 기록한다. CI 통과만으로 체감 완료 주장 금지.
