## 1. 핵심 문제와 결론

**결론:** **Magicraft의 제목·아이콘·분류·핵심 효과·발동/적용 조건·하단 보충 설명을 나누는 카드 구조**를 기본으로 하고, **Backpack Battles의 관련 슬롯·조합 강조**, **Brotato의 수치 가독성**, **Slay the Spire의 짧은 유물 설명**을 보완적으로 참고한다.

현재 게임에는 필요한 데이터가 상당 부분 있지만, 화면마다 표현 방식이 달라 다음과 같은 문제가 생길 수 있다.

- 아이콘에 마우스를 올려 나온 **기본 `tooltip_text`의 긴 줄글**과, 제작대에서 선택해 열리는 **큰 상세 패널**의 스타일이 다르다.
- 마법은 **공격/보조/연결/완성 합성**, 유물은 **조건부 패시브 효과**로 필요한 정보가 다른데, 공통 제목·아이콘·효과·조건의 위계가 확립되어 있지 않다.
- 사용자는 마법의 효과뿐 아니라 **실제 어느 오브 슬롯/오른쪽 공격에 적용하는가**까지 알아야 한다.
- 강화할 수 있는 구체는 `현재 단계 → 강화 후 단계`를 비교할 수 있어야 한다. 단순한 총괄 설명으로 현재 수치를 대신하면 안 된다.
- 게임이 전투 중에도 편집할 수 있는 구조이므로 **짧게 읽는 호버 카드**와 **제작대·도감의 상세 설명 패널**을 구분할 필요가 있다.

외부 레퍼런스의 문구·수치·게임 규칙을 그대로 가져오는 것이 아니라 **정보 배치 원리**만 적용한다.

### 3.2 유물의 실제 데이터 예시

- **금이 간 왕관**: `주는 피해 +30% / 받는 피해 +20%`. 보호막에도 받는 피해가 증가한다는 예외가 있다. 하나의 긴 문장보다 **장점/단점 분리**가 직관적.
- **변덕쟁이 장갑**: 직접 시전 4회마다 추가 복제, 복제 위력 40%, 무작위 방향. `다음 복제까지 N회`는 **현재 런 상태에 의존**한다.
- **욕심쟁이 저금통**: 보유 마석에 따라 피해 증가, 최대 +20%. `현재 피해 보너스 +N%`는 현재 마석에 의존하므로 **도감/과거 기록에서 현재 런의 수치를 보여주면 안 된다.**
- **영혼 솜옷**: 현재 보호막과 처치 누적은 웨이브에 따라 바뀌며 웨이브 끝에는 초기화. 역사 화면은 그 상태가 저장되지 않는 한 **당시 수치 표시 불가**.
- **등급:** `Relics.definition()`은 `tier = "unassigned"`을 반환한다. 현재 모든 유물에 원작처럼 **희귀도를 임의로 부여하면 안 된다.**

## 4. 추천 공통 카드 골격 — Magicraft 중심

```text
┌─────────────────────────────────┐
│ [큰 아이콘]  마법/유물 이름        │
│             공격 / 보조 / 연결    │  ← 실제 역할, 단계
│             +2 / 완성형 등       │
├─────────────────────────────────┤
│ 핵심 효과                       │
│  • 현재 구체/유물의 정확한 효과 │
│  • 중요한 수치·장단점            │
├─────────────────────────────────┤
│ 적용 조건 / 작동 예외            │
│  • 오른쪽 공격에 적용 / 연결 사건│
│  • 언제 발동하는가 / 무엇이 제외 │
├─────────────────────────────────┤
│ 선택적 상세                     │
│  • 강화 전 → 후 변화              │
│  • 실제 런 상태(지원하는 화면만) │
│  • 설정·서사 한 줄(있을 때만)     │
└─────────────────────────────────┘
```

- **아이콘 + 제목 + 역할 + 핵심 효과 + 작동 조건**은 공통의 최상위 정보 위계다.
- 등급/희귀도는 **데이터가 있을 때만** 표시하고, 마법의 공격/보조/연결 역할을 희귀도와 혼용하지 않는다.
- 보충 설명은 아래에 별도로 배치; 원작처럼 긴 문구가 너무 많으면 접거나 상세 화면에서만 노출.
- 현재 게임의 **밝은 크림·라벤더/둥근 카툰 스킨**과 맞추고, 원작 카드 텍스처·아이콘/일러스트를 직접 재사용하지 않는다.
- **화면별 툴팁 높이가 달라도 뼈대는 같다.** 전투용 작은 카드가 매번 `366×632`짜리 제작대 패널 크기로 열려서는 안 된다.
- 카드 본문에 구매·강화·장착 버튼을 무조건 넣지 않는다. **툴팁은 정보**, 실제 행동 버튼은 해당 화면이 소유한다.

### 4.1 마법 역할별 표시 규칙

| 대상 | 상단 | 본문 1순위 | 본문 2순위 | 추가 |
|---|---|---|---|---|
| **공격 마법** | 이름/아이콘/공격/현 강화 단계 | **발동·타격·피해 특성** | 지속·반복·조건/대상 | 정확한 강화 차이는 제작대에서 |
| **보조 마법** | 이름/아이콘/보조/현 강화 단계 | **실제로 바꾸는 행동** | **오른쪽 어느 공격에 적용되는지** / 예외 | 호버 중 적용 슬롯 강조 권고 |
| **연결 마법** | 이름/아이콘/연결/현 강화 단계 | **앞 주문의 어떤 사건에서 후속 공격을 발동하는가** | 두 공격 사이의 조건/범위 | 실제 후속 슬롯 강조 |
| **완성 합성** | 이름/아이콘/완성형/공격·보조·연결 | **실제 완성형 효과** | 조건·보조 적용/연결 등 | **추가 강화 불가**, 필요시 실제 재료 두 개 +3 |
| **유물** | 아이콘/이름/유물 | **발동 조건과 효과** | 제한·장점/단점 | 지원 가능한 곳에서만 동적 수치 |

마법공예의 '오른쪽 주문에 적용'은 중요한 참고이지만, **우리 게임은 자체 컴파일·연결 경계·상쇄/비작동 규칙을 우선한다**. 모든 보조·연결에 똑같은 오른쪽 범위 문구를 억지로 넣지 않는다.

### 4.2 마법 카드 개념 예시

```text
┌─────────────── 관통 +2 ─────────────┐
│            [보조 구체 아이콘]       │
│             보조 · +2              │
├────────────────────────────────────┤
│ [현재 강화 단계의 정확한 효과]     │
│ 오른쪽 공격 주문에 적용            │
├────────────────────────────────────┤
│ 실제 적용되는 대상 / 예외 조건     │
│ [제작대에서만: 현재 → 강화 후]     │
└────────────────────────────────────┘
```

**구체적인 +2 효과 수치**는 예시에서 임의로 정하지 않는다. `Spells.modifier_token_text()`/실제 조합 컴파일 결과를 써야 한다.

### 4.3 유물 카드 개념 예시 — 금이 간 왕관

```text
┌────────────── 금이 간 왕관 ────────┐
│             [유물 아이콘]          │
│                   유물             │
├────────────────────────────────────┤
│ 주는 피해 +30%   (장점)           │
│ 받는 피해 +20%   (위험)           │
├────────────────────────────────────┤
│ 모든 마법 피해 증가.              │
│ 보호막에 받는 피해도 증가.         │
└────────────────────────────────────┘
```

이 두 값은 **현재 `scripts/relics.gd`의 정의에 근거**한다. 장식성 문구는 실제 존재하는 문안 또는 별도 승인된 문구만 추가한다.

## 5. 사용 화면에 따른 상세 수준

| 사용 화면 | 권장 표시 형태 | 정보/기능 경계 |
|---|---|---|
| **전투 중 가방·오브 슬롯** | **호버 즉시 작은 설명 카드**. 중요한 효과/적용 조건만 | 전투는 계속되므로 화면을 크게 가리지 않음; 클릭 없이 내용 확인 |
| **상점·마법 제작 작업대** | 작은 호버 카드 + **선택시 고정 상세 패널** | `현재 +N → 다음 단계`, 정확한 마석 비용/보유수량·장착 위치, 작동 가능한 행동은 기존 제작 UI에 |
| **3중 1택 보상 카드** | 카드에 핵심 변화, 호버에 상세/예외 | 선택 후 효과와 기존 단계 비교; **보상 선택 행위**와 툴팁 표시를 분리 |
| **유물 획득·보유 목록** | 유물 요약 + 필요시 자세한 카드 | 동적 상태는 실제 현재 런 맥락에서만 표시 |
| **발견 도감** | 같은 시각 스타일의 **고정 자세히 보기** | 강화 기본/+1/+2/+3, 관련 합성법, 발견 여부 정책 유지. **미발견 세부 공개 금지** |
| **실험 기록(과거 판)** | 저장된 마법/유물 설명 **읽기 전용 툴팁** | **현재 런의 마석·유물 카운터·시전 수를 과거 기록인 것처럼 표시 금지** |

- 이미 `tooltip_text`를 사용하는 슬롯 진단과 일반 마법 설명이 서로 **덮어쓰지 않도록** 공통 자료 생성/우선 표시 정책이 필요.
- 기본 툴팁의 문구가 긴 아이템에 대해서는 고정 폭·줄바꿈·창 경계 보정, 손쉬운 마우스 이동 및 키보드 포커스 대안을 제공.

## 6. 중요 부가 기능: 영향 슬롯 강조와 경고 통합

### 6.1 관련 슬롯 강조 — Backpack Battles 방식의 *응용 제안*

1. 플레이어가 **보조/연결 마법 구체를 호버 또는 키보드 선택**한다.
2. UI가 **실제 현재 오브 컴파일/진단 결과**로 어느 슬롯에 적용되는지 확인한다.
3. 해당 공격·후속 슬롯만 **간단한 테두리/밝기**로 강조한다.
4. 커서를 벗어나거나 다른 마법을 선택하면 강조를 정리한다.

정적 선언문만 보고 전체 오른쪽을 무조건 강조하지 않는다. 앞·뒤 공격, 연결 경계, 빈칸, 합성 보조, 상쇄 우선순위 등 **실제 동작하는 적용 대상**이 기준이다.

이 기능은 **고급 옵션**이며 첫 구현 단계의 필수조건은 아니다. 구현할 때는 툴팁·하이라이트·실제 마법 행동이 서로 모순되지 않아야 한다.

### 6.2 기존 확정 색상 계약 유지

[경고 UI 보고서](2026-10-30-magic-suppression-slot-diagnostics.md)와 [사용자 색상 확정](../decisions/2026-10-30-magic-warning-severity.md)에 따라:

- **상쇄(SUPPRESSED) = 노란색 경고**: 마법 조합이 유효하지만 특정 보조 효과가 실제로 무력화된 경우. **시전·장착 차단 금지**.
- **비작동(INACTIVE/ERROR) = 빨간색 경고**: 특정 구체/연결이 실행 불가능한 경우. 실제 동작하지 않는 부분을 명확히 설명.
- 슬롯에 커서를 올리면 **마법의 일반 정보 + 왜 상쇄/비작동인지**를 모두 확인 가능하게 한다.
- 색뿐 아니라 `상쇄됨` / `작동 안 함` 문구, 경고 아이콘 및 어떤 효과가 남는지도 함께 제시한다.
- 장점/위험이나 강화 효과의 초록/빨강 색과 **슬롯 오류 색을 혼동시키지 않도록** 위치·도형·라벨을 분리한다.
- 아직 검사되지 않은 조합에 근거 없이 경고를 생성하지 않는다.

## 7. 권장 설계/기술 구현 순서 — 사용자 승인 이후만

| 단계 | 제안 작업 | 완료 확인 조건 |
|---|---|---|
| **P1** | 툴팁 **공통 데이터 뷰 모델** 구성(이름·아이콘·역할/단계·주효과·조건·보충설명·상태) | 마법/유물 각각 현재 게임 데이터와 1:1 대응. **원본 게임 규칙 불변** |
| **P2** | 마법공예풍 **공통 툴팁 카드 외형** 및 화면 밖 자동 배치 | 슬롯·유물·보상 선택지에서 글자/아이콘 안 잘림, 호버/포커스 동작 |
| **P3** | 제작·보상·도감에 같은 스타일 재사용 | 동일 마법/유물의 효과와 단계 설명이 화면마다 일치 |
| **P4** | 현재/강화 후 차이와 유물 동적 수치의 **상황별 조건 노출** | 실제 quote/시전 상황을 반영, 과거 기록에서 현재 상태값 재사용 금지 |
| **P5** | 선택적 슬롯 연계 강조 + 노랑/빨강 경고 통합 | 실제 컴파일 결과와 강조·경고/툴팁이 정합 |

### 검증 체크리스트 — 이번에는 미실시

1. **대표 예제:** 기본 공격 +0/+3, 보조 +2, 연결 +3, 완성형 공격/보조/연결, 금이 간 왕관/변덕쟁이 장갑/영혼 솜옷/저금통을 분리 시험.
2. 마법/유물 이름·설명·수치가 실제 `Spells.definition`, `modifier_token_text`, `spell_progression`, `relics.definition`와 맞고 **원작 Magicraft의 수치가 섞이지 않음**.
3. 보조·연결의 실제 적용 범위와 강조 위치가 컴파일된 오브의 실제 시전 경로에 일치.
4. 상쇄 노랑은 유효한 구성을 차단하지 않고, 비작동 빨강은 정상인 다른 구체까지 막지 않음.
5. 강화 전후 비교에서 유효한 `quote`/수치만 표시하고 **+3 최대 강화 및 합성 완성형 강화불가**를 정확히 나타냄.
6. 유물의 동적 수치(보유 마석, 시전 카운터, 처치/보호막)가 실제 현재 상태에서 갱신되고 **도감/과거 기록/일시정지 시 틀린 값이 나오지 않음**.
7. 도감의 미발견 항목은 이전 공개 정책대로 남으며 정보 누출 없음.
8. 스크롤 가능한 가방·오브 슬롯·상점 카드·보상 카드·유물 아이콘에서 호버가 시야 밖으로 잘리지 않고 커서를 옮길 때 툴팁이 의도치 않게 깜빡이거나 선택/드래그를 가로막지 않음.
9. 키보드 포커스/컨트롤러 조작/단축키·터치 대응이 필요한 화면에 호버와 동등한 정보 접근 수단 제공.
10. `1280×720`, `1600×900`, `1920×1080` 실제 Godot 렌더 확인(논리 해상도·스케일 보정 포함).
11. 툴팁을 읽는 동안 전투 입력·보상 선택의 동작/정지 정책, 가방 드래그, 상점 편집·되돌리기가 변경되지 않음.
12. 코드 정적 열람·자동 테스트·실제 Godot GUI 시험·사용자 미관 승인을 **서로 다른 근거 수준**으로 기록.

## 8. 미확정 사용자 결정

1. **Magicraft형 카드 외형**(직사각형·큰 아이콘·본문 분리)과 기존 둥근 스킨을 어느 정도 혼합할지.
2. 전투 중 가방용 **짧은 카드**의 기본 크기, 세부 설명은 키/클릭 확장형인지.
3. 제작대의 상세 패널과 호버 툴팁을 통합 데이터 모델로 일치시키되 **정보 표시 위치를 얼마나 유지할지**.
4. 실제 적용 슬롯 강조를 **1차 필수** 또는 **추후 고급 기능** 중 어디에 둘지.
5. 유물의 현재 동적 상태와 세계관 문구를 언제/어디까지 노출할지.
6. 유물/마법의 실제 **희귀도 신설** 여부는 이 UI 연구에서 결정하지 않으며, 구현 전에 별도 디자인/규칙 결정이 필요하다.

## 9. 작업 기록 및 근거 제한

- **실제로 수행:** HUD2에서 사용자와 비교한 Magicraft·Backpack Battles·Brotato·Slay the Spire·Noita 설명 카드 자료 정리, GitHub의 제작·가방·보상·도감·유물 데이터 소스 열람, 공통 정보 카드/화면별 이용방안 제안, 공용 보고서로 등록.
- **실제로 수행하지 않음:** 참고 게임 직접 실행·동작 시간 실측, Godot 툴팁 개편 코딩, 새로운 이미지/스프라이트 생성, GUI 에셋 다운로드/구매·프로젝트 반입, 실제 게임 렌더/마우스 입력/키보드·컨트롤러/유저테스트.
- **완료 범위:** 자료 조사 내용을 설계 보고서로 등록하고 인덱스에 연결하는 문서 작업. **PROPOSED = 사용자가 게임 UI 개편을 승인했다는 뜻이 아님.**
