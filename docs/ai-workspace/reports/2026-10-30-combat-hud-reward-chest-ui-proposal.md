## 2. 디자인 원칙

- **전투에서는 적·마법이 주인공:** HUD는 정보량보다 즉시 인지와 중앙 시야 확보를 우선.
- **레벨업에서는 3~4개 카드가 주인공:** 선택지를 화면 중앙에 올리고 다른 UI는 접음.
- **편집에서는 가방과 오브가 주인공:** 선택 전후에 필요하면 슬롯 전체를 펼침.
- **상자에서는 개봉 결과가 주인공:** 일반 HUD를 숨기고 기대→해제→보상 공개→정리 단계를 제공.
- **정보는 삭제보다 재배치:** HP와 보호막 수치는 전투 판단에 필수이므로 없애지 않음.
- **시각 연출과 보상 로직 분리:** 애니메이션·스킵이 보상 개수·내용을 바꾸거나 중복 지급하지 않도록 처리.

## 3. 전투 HUD 권장 배치

기준 해상도 `1600×900`; 아래 숫자는 **개발 시작용 제안치**이며 확정된 픽셀 규격이 아니다. 실제 구현은 뷰포트 앵커·안전 여백과 `1280×720`, `1920×1080`을 함께 고려한다.

| 요소 | 권장 위치 / 표현 | 결정 근거 |
|---|---|---|
| 전체 XP | **최상단 Y=0~6**의 얇은 진행 바 | 진행은 보이되 화면을 가리지 않음 |
| 전체 경과 시간 | **상단 정중앙 Y≈16~58**, 가장 큰 HUD 숫자 | 30분 생존의 핵심 정보 |
| 다음 제작 휴식 | 시간 바로 아래 `Y≈60~82`: `3/5구간 · 휴식까지 00:18` | 전체 시간과 6분 구간을 모두 확인 |
| 30분 이후 | 휴식 안내 대신 `최종 보스 · 처치 시 승리` | 잘못된 휴식 카운트 방지 |
| 가방 버튼 | **좌상단 X≈16, Y≈25**, Tab/클릭 | 전체 슬롯은 기본 숨김 |
| 오브 상태 | **좌측 세로 1~4개**, 작은 아이콘/번호(약 36~40px) | 자동 발사 오브 확인, 상세 슬롯 상시 노출 안 함 |
| 레벨·마석 | **우상단**, 한 줄/두 줄의 작은 숫자 | 생존 시간보다 낮은 시각적 우선순위 |

| 보호막 | HP 옆 별도 작은 숫자 또는 얇은 보조 바 | 피해 흡수와 HP 감소를 구분 |
| 회피 | **우하단** 쿨다운 아이콘/부채꼴 게이지 | `Space 회피 준비` 등의 긴 텍스트 제거 |
| 유물 | **우하단** 작은 아이콘 열, 넘치면 `+N`/자세히 보기 | 아이콘 길이 무제한 확장 방지 |
| 보스 HP | **시간 표시 아래 Y≈96~114**를 기본 후보로, 전투 공간 및 보상 모드 겹침 회피 | 보스 시점에만 노출 |
| 처치 수·위력 배율 | 일시정지/상세 통계 화면으로 이동 | 지속 노출 필요성 낮음 |
| 조작 힌트 | 첫 진입 시만 안내, 이후 자동 최소화 | 시야 확보 |

### HP 표시 결론

- **HP 시스템·HUD 완전 삭제는 비추천.** 현재 `max_hp=100`, 피격 무적, 회복, 보호막, 6분 휴식 회복이 작동하므로 수치가 의사결정에 필요하다.
- HP는 **작게 유지**, 위험 상태에서 강조(예: 30% 이하 경고), 피격은 캐릭터에도 명확한 즉시 피드백 제공.
- 보호막과 HP 피격 피드백은 분리. 플레이어 머리 위 간이 바는 선택 사항이며 상시 두 체력바로 중복 표시하지 않도록 검토.

## 4. 레벨업 3중 1택 / 합성 4번째 카드

### 선택 모드 — 기본

- 전투 일시정지를 유지하고 **가방과 오브 상세 편집 UI는 기본적으로 접는다.**
- 중앙에 카드 **3장, 조건부로 합성 카드 1장 추가**. 기존 280×398 세로 실루엣을 출발점으로 삼되, 뷰포트 크기에 따라 카드 크기와 세로 위치 조절.
- `1600×900` 기준 **카드 상단 Y≈220~235, 하단 Y≈618~633**을 첫 후보로 둔다. 위/아래 화면 영역과 겹치지 않는지 Godot 실측 필요.
- 카드 내용 우선순위: **큰 아이콘 → 이름 → 신규/+강화 → 효과 핵심 변화**. 상세 비교·배치 위치는 마우스 오버 또는 별도 상세 뷰로 보완.
- 공격/보조/연결 구분은 읽기 쉬운 짧은 레이블로 제공; 색상만으로 구분하지 않는다.
- 합성 4번째 카드: 다른 카드와 선택 조건은 같되 테두리/문양을 별도 강조. **소비 재료 2종, 합성 결과의 고유 행동**을 구체적으로 표기.
- `Tab`/화면 버튼으로 선택 전에도 현재 오브·가방을 확인하고 편집 모드로 이동 가능.
- 선택 모드로 복귀해도 **후보를 재추첨하지 않는다.** `reward_id`, `revision`, 잠금 후보를 보존.

### 편집 모드 — 선택 전후 모두 접근 가능

- 기존 `compact_inventory.gd`의 연속 가방(가로 스크롤)과 1~4오브, 6~8슬롯 드래그/교환/되돌리기는 그대로 유지.
- 편집 모드에서는 중앙 카드가 **축소 요약/접힘** 상태가 되어 슬롯과 겹치지 않게 한다.
- 아직 보상을 선택하지 않았다면 선택 화면으로 돌아갈 수 있고, 보상 후보는 변하지 않음.
- 카드를 선택하면 **새 마법은 가방에만 지급**, 이후 편집 모드로 전환해 원하는 위치에 배치.
- 남은 보상이 있으면 다음 카드 선택 화면으로 이어지고, 마지막 선택 후 편집 및 **명시적 `전투 재개`**가 필요함.
- 전투 중 일반 Tab 편집은 기존대로 **게임 시간이 흐르고**, 보상 선택 전후 Tab 편집은 **일시정지 유지**.

### 시각적 화면 상태와 게임 상태 분리

- `combat_rewards.gd`의 보상 `stage`는 보상 지급/선택의 진실 원천으로 유지.
- `level_reward_ui.gd`에는 표시용 `selection_view` / `inventory_view` 개념을 따로 둔다. **보기 전환으로 보상 지급 상태를 바꾸면 안 된다.**
- 카드 선택 및 열기에는 기존 `reward_input_gate.gd`의 누르고 있던 클릭/확정 입력 해제 가드를 유지.
- `1280×720`에서 네 번째 카드가 화면 밖으로 나가면 폭·간격·타이포 크기를 조정해야 한다. 고정 `top=350` 대체로 끝내지 말 것.

## 5. 보물상자 — 별도 전체 화면의 1/3/5 단계별 보상 연출

### 현행 문제

- `level_reward_ui.gd`의 상자 경로는 텍스트 패널, 버튼, 0.8초 기다림, 간단 결과 표시에 가깝다.
- 현재 보상 수 1/3/5 비율은 `combat_rewards.gd`의 **80% / 17% / 3%**. 보상 수에 따른 차등 연출이 사실상 없다.
- 5개 보상이 나와도 그 사실을 특별하게 인지시키는 대형 공개/연출이 부족하다.

### 권장 UX

1. **상자 등장:** 일반 HUD를 숨기고 배경 전투 화면을 어둡게 처리. 중앙 대형 상자와 개봉 동작.
2. **기대 형성:** 짧은 진동/빛/봉인 해제. 결과가 나오기 전부터 1/3/5를 텍스트로 미리 공지하지 않음.
3. **연출 분기:** 1개는 간결, 3개는 순차 공개·광선, 5개는 훨씬 큰 섬광·리본·폭죽·다섯 개 보상 순차 공개.
4. **결과 확정:** 아이템 이름·아이콘·합성 여부·획득 수량을 쉽게 확인 가능한 최종 결과 화면으로 정리.
5. **편집·재개:** 연출 후 기존 보상 편집 화면으로 넘어가며, 이후 수동 전투 재개.

**연출 시간은 A/B 실험용 권장 초안**: 1개 약 1초, 3개 약 1.5초, 5개 약 2.5초. 실제 클릭 템포·가독성 측정 후 조절. 모두 스킵 가능.

### 보상 안전성과 성능

- **보상 개수·내용과 애니메이션 타임라인을 분리.** 개봉 시작 시 1회 보상 트랜잭션을 확정하거나 재실행 불가능한 고유 ID로 잠근다.
- 현행 `reveal_chest()`는 **이전 보상을 지급한 다음 매 회 후보를 다시 계산해** 합성 부모 소모·최대 강화 후 후보 변화를 반영한다. 새 연출 설계가 이 순차적 후보 계산을 몰래 깨서는 안 된다.
- 스킵·빠른 획득·ESC·창 크기 변경·연속 상자에서 중복 지급이나 결과 변경이 없도록 검증.
- **1/3/5 비율, 보상 획득·마석·합성 경제 수치는 이번 범위에서 변경하지 않음.**
- 합성 보상에는 두 재료가 중앙에서 결합하는 별도 시각 효과 제안. 일반 강화와 차별화하되 실제 합성 규칙은 변경하지 않음.
- 폭죽·파티클에는 상한과 품질 옵션을 둔다. 5개 잭팟에도 프레임 급락이 생기지 않도록 한다.
- **BGM·새 효과음은 모두 이번 구현 대상에서 제외.** '빰빰빠' 감각은 당장은 크기·속도·대비·단계별 공개 등 시각적 리듬으로만 설계.

## 7. 독립 완료 기준 — '카드 3장 표시'만으로 완료 처리 금지

1. `1600×900`, `1920×1080`, `1280×720`에서 **3택과 4택** 모두 화면 중앙에 표시되고 잘리지 않는다.
2. 보상 선택 시 카드가 화면 시각 중심에 있고 가방·오브 전체 슬롯이 카드를 가리지 않는다.
3. 선택 **이전/이후** 모두 Tab 편집이 가능하고, 선택 화면으로 돌아와도 보상 후보가 바뀌지 않는다.
4. 보상 중 타이머가 멈추고 명시적인 전투 재개 전에는 시간이 흐르지 않는다. 일반 Tab 편집의 비정지는 유지.
5. 카드 전체 클릭, 버튼 클릭, 키보드/패드 입력을 처리하고 입력 가드가 오선택을 막는다.
6. 전투 HUD에서 상단 중앙에 전체 시각·휴식 카운트다운이 읽히고, HP/보호막/레벨/마석을 찾을 수 있다.
7. 위험 HP 상태가 명확히 보이고, 회복·보호막 흡수 시 수치/UI가 올바르게 동기화된다.
8. 상자 1/3/5개가 **화면상 구분되는 연출**을 제공한다. 5개 잭팟은 단순 텍스트 5줄로 대체할 수 없다.
9. 빠른 획득/애니메이션 스킵/ESC/중복 클릭/화면 리사이즈/상자 연속 처리 후 **동일한 보상 결과**와 지급 1회만 보장한다.
10. 보물상자의 순차 보상 후보 재계산·합성 부모 소비·가방 배치·저장·체크포인트 회귀 테스트가 정상.
11. 전투 장면에서 이펙트/투사체와 HUD가 겹쳐 읽기 어렵거나 상호작용 클릭이 막히지 않는지 실제 화면·입력으로 확인한다.
12. 자동 스크립트 통과, 실제 Godot 화면, 사용자 시각적 승인, 장시간 런/성능은 **각각 별도**로 보고한다.

## 9. 승인해야 하는 선택지 / 미확인

- 제안 핵심: **전투 HUD 재배치 + 중앙 카드 선택/편집 전환 + 상자 전용 잭팟 화면**.
- HP: 없애지 않고 **좌하단 얇은 바**로 축소(권고).
- 전체 시간: **상단 중앙**(강한 권고).
- XP: **상단 얇은 바**(권고). 보스 HP와 충돌 여부 실측 필요.
- 유물/회피의 우하단 압축과 좌측 오브 아이콘 형태는 프로토타입에서 검토 필요.
- 사용자 최종 레이아웃 승인 전까지 이 문서는 **PROPOSED**. Godot 코드 편집·UI 이미지 제작·음향 작업 없음.
