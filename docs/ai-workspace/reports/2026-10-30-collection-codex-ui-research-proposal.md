## 1. 설계 목표

도감은 단순 수집률 화면이면서 동시에 다음 실험에 활용할 마법·합성 정보를 찾는 공간이다. 플레이어가 다음 질문에 쉽게 답하게 해야 한다.

1. 내가 어떤 주문·합성을 발견했는가?
2. 원하는 마법은 **공격/보조/연결** 중 무엇인가?
3. 주문이 기본→+1→+2→+3에서 **어떻게 달라지는가**?
4. 특정 완성 합성은 **어떤 두 재료가 필요한가**?
5. 일반 주문에서 **관련 완성 합성 결과로** 빠르게 이동할 수 있는가?

**권장 방향:** 한눈에 탐색할 수 있는 아이콘 격자 + 읽기 쉬운 상세 정보 + 합성 관계 시각화. 도감에 새로운 전투 기능을 끼워 넣지 않는다.

### 현재 구조가 이미 잘하는 것

- 일반 주문/완성 합성/유물이라는 주요 범주를 분리한다.
- 획득한 항목을 발견 처리하고 실험이 끝나도 기록을 유지한다.
- 일반 주문은 한 번 발견하면 기본부터 +3까지 정보를 볼 수 있다.
- 합성 ↔ 재료 방향으로 클릭해 탐색할 수 있다.
- 타이틀 또는 제작함에서 접근하며, 해당 출처에 맞는 뒤로 가기 버튼이 있다.

### 개선 필요 여부를 확인할 항목

- 공격/보조/연결 주문을 하나의 격자에 모두 넣어, 같은 역할의 마법을 비교하기 어렵다.
- `156×96` 목록 카드가 이름까지 직접 보여주지만, 30개 항목을 빠르게 훑기에는 면적 소비가 크다.
- 기본/+1/+2/+3 정보가 아래로 연속 배치되어, 특정 단계의 변화점을 찾기 어렵다.
- 합성 관계가 주로 문자 버튼이어서 **두 재료 → 결과**를 즉시 시각적으로 읽기 어렵다.
- 아이콘 클릭·필터/탭 전환 때 `build(ui)`로 전체 모달을 재생성한다. **선택한 아이콘을 눌렀을 때 목록 스크롤 위치가 초기화될 가능성**이 있으나, 이 현상은 실제 Godot 클릭으로 재현한 것이 아니다. 구현 시 우선 확인한다.
- 현재 `finish()`의 기본 포커스 목록에 그리드 아이콘·상세의 합성 링크가 별도로 들어 있지 않다. 키보드/패드 탐색의 실제 도달성과 포커스 복귀는 검증이 필요하다.

## 4. 제안하는 UI의 중심 구조

**기본 B안: 왼쪽 아이콘 탐색 + 오른쪽 상세 정보.**  
**미술 방향: Magicraft의 서적/책갈피 분위기를 일부 반영.**  
**완성 합성 탭: 간결한 재료→결과 시각 구조를 추가.**

### 1600×900의 개념 배치 (승인 전 가변)

```text
┌────────────────────────────────────────────────────────────────────┐
│ 발견 도감                                    총 발견 진행도          │
│ [주문  OO/30]    [완성 합성 OO/30]    [유물 OO/12]                 │
│ [전체]  [공격]  [보조]  [연결]   ← 해당 역할 분류가 있는 탭에서     │
│ ┌───────────────────────┐ ┌──────────────────────────────────┐    │
│ │ ○ ○ ○ ○ ○ ○            │ │ 선택 마법 이름 / 역할 / 발견 상태 │    │
│ │ ○ ○ ○ ○ ○ ○            │ │ 큰 아이콘, 한 줄 핵심 요약        │    │
│ │ ○ ○ ○ ○ ○ ○            │ │ [기본] [+1] [+2] [+3]           │    │
│ │ ○ ○ ○ ○ ○ ○            │ │ 선택 단계 설명 / 변경 강조       │    │
│ │ ○ ○ ○ ○ ○ ○            │ │ 관련 완성 합성/재료 관계         │    │
│ └───────────────────────┘ └──────────────────────────────────┘    │
│ [← 타이틀 / 제작함]               조회 전용 · 장착/지급 불가       │
└────────────────────────────────────────────────────────────────────┘
```

### 상세 동작 원칙
- 상위 탭은 **주문 / 완성 합성 / 유물** 그대로 유지.
- 주문·합성 탭에는 **전체 / 공격 / 보조 / 연결** 보조 필터 제안. 유물 탭은 필터 없이도 충분.
- 왼쪽 아이콘은 **약 6열×5행**의 시험용 초안. 이름은 선택한 상세 영역과 툴팁에 제공.
- 선택한 아이콘은 테두리/강조를 주되 **색상만으로 구분하지 않는다**.
- 오른쪽 상세는 항목 이름/역할/설명 → 강화 단계 또는 합성 레시피 → 관련 항목 순서로 배치.
- **미발견 표시 방식**은 현행처럼 명시적 `?`를 유지하고, 합성 재료 공개 여부는 기존 코드 기준을 보존한다.
- 필터를 바꾸어도 기존에 선택한 항목이 필터 결과에 포함되면 그 선택을 보존. 포함되지 않으면 새 목록에서 첫 발견 항목 등 예측 가능한 기본 항목을 선택.
- 리렌더 비용보다 **선택·스크롤·키보드 포커스 보존**을 우선. 모든 클릭마다 전체 도감을 새로 만드는 방식의 필요성을 재검토.

## 5. 세부 개선 제안

### 5.1 아이콘 4열 → 6열 검토 (우선 1)

- 현행 목록: 680×540, 4열, 156×96, 간격 10.
- 제안 초기 시험: **96×96 슬롯 × 6열 / 간격 10 → 총 너비 626**, 높이 **96×5+10×4=520**. 30개 주문을 5줄에 배치할 수 있는 산술상 후보.
- 이 계산만으로 실제 UI 성공을 선언할 수는 없다. `ScrollContainer` 내 테마 여백·패딩·스크롤바·포커스 테두리·텍스트 판독을 Godot에서 검증해야 한다.
- **지금의 156×96 이름표시 카드 → 96×96 아이콘형 카드**로 바꿀 때는 툴팁·선택 후 상세에 이름을 충분히 드러낸다.
- 유물 12개는 동일 격자를 쓰거나 항목 수에 맞춰 과도한 빈 공간을 조정.

### 5.2 역할 필터 (우선 2)

- 일반 주문 30: **공격 12 / 보조 15 / 연결 3**.
- 완성 합성 30: **공격 24 / 보조 5 / 연결 1**.
- 검색창/복잡한 다중 정렬은 72개 규모에서 필수 아님. 종류별 필터가 1차 개선안.
- 발견률은 탭 전체를 기준으로 유지하되 필터 결과에서도 `N개 중 발견 M개`를 보조로 표시할지는 UI 검토.

### 5.3 합성 레시피 관계를 명시적으로 표시 (우선 3)

실제 정의 예시: `별빛탄 +3` + `관통 +3` → `빛나는 창`.

```text
[별빛탄 +3] + [관통 +3] → [빛나는 창]
                         관통마다 측면 광파 발생
```

- 부모 두 아이콘을 각각 클릭하면 해당 일반 주문 도감으로 이동. 완성 합성 아이콘 클릭 시 합성 상세로 이동.
- 일반 주문의 상세에서는 해당 주문을 재료로 사용하는 **관련 완성 합성**을 보여준다.
- 합성은 원래부터 아이템 장착/지급이 아니라 도감의 지식 링크임을 유지한다.
- **미발견 합성의 레시피를 숨기거나 바꾸는 것은 이번 UI 제안에 포함하지 않는다.** 현행 코드는 미발견 상태에서도 부모 재료를 보여준다.
- 비용/합성 횟수 등 게임 규칙 문구는 실제 최신 보상 로직을 구현 전에 다시 검토해야 한다. 오래된 `docs/CHECKPOINT-AND-COLLECTION-v1.md`의 12마석 합성과 현행 UI의 무료 보상 상자 합성은 **버전 이력 차이**가 있다. UI 개선 작업에서 경제 규칙을 결정하거나 변경하지 않는다.

### 5.4 강화 설명 단계화 (우선 4)

- 현재는 일반 주문의 **기본/+1/+2/+3 네 단계**를 연속 텍스트로 표시.
- 제안: 우측 상세에서 `[기본] [+1] [+2] [+3]` 버튼으로 선택하고, **현재 단계**와 **직전 단계 대비 차이**를 나누어 읽게 한다.
- 발견한 기본 마법 하나를 열면 네 단계 설명을 확인할 수 있는 기존 공개 수준을 유지한다. 새롭게 강화별 도감 해금 조건을 도입하지 않는다.
- 변경값이 없는 단계에서는 실데이터와 달리 임의 수치/효과를 만들어 강조하지 않는다.
- **완성 합성은 일반 주문처럼 추가 강화할 수 없는 경우가 있으므로** 일반 주문의 강화 탭을 일괄 복사하지 않는다. 선택 항목 종류에 따라 상세 서식을 다르게 한다.

### 5.5 스크롤·포커스·뒤로 가기 보존 (우선 5)

- 같은 탭 안에서 아이콘만 바꾸면 좌측 목록의 스크롤 위치가 유지되어야 한다.
- 합성의 부모 주문 링크로 이동한 뒤 뒤로 돌아오면 가능한 한 **이전 합성 항목·탭·스크롤 위치**가 유지되는 것이 바람직하다.
- Tab/화살표·Enter, 필요 시 패드 탐색으로 탭/필터/모든 아이콘/재료 링크/뒤로 가기에 접근 가능하도록 한다.
- `collection_origin` 기반으로 타이틀/제작함 복귀 계약을 유지.
- 도감을 여닫거나 탭을 바꾼다고 발견 상태가 늘거나 저장에 변경이 생기면 안 된다.

### 5.6 미술 스타일 (우선 6)

- 책갈피·크림색 양피지 느낌·연한 라벤더를 활용할 수 있으나, 현재 프로젝트의 **평면적인 둥근 UI** 및 가독성을 우선.
- 무거운 나무·금속·사실적인 종이 텍스처를 필수로 만들지 않는다.
- 별도 일러스트 구매/제작, 새 배경/VFX는 이번 범위에 넣지 않음.
- 아이콘/상세/화면 비율이 먼저 안정되고 나서 아트 마감을 판단.

## 6. 개편 우선순위와 예상 코드 작업 범위 (승인 후만)

| 순서 | 작업 | 예상 위치 |
|---|---|---|
| 1 | 아이콘 격자 6열 시제품과 세 해상도 확인 | `scripts/collection_ui.gd` |
| 2 | 상위 탭 안 공격·보조·연결 필터 | `scripts/collection_ui.gd`, 필요 시 UI 상태 |
| 3 | 합성 재료→결과 카드형 연결 | `scripts/collection_ui.gd`, 기존 카탈로그 정의 참조 |
| 4 | 기본/+1/+2/+3 비교/강조 표시 | `scripts/collection_ui.gd`, 기존 단계별 설명 함수 재사용 |
| 5 | 아이콘 선택·스크롤 위치·포커스 상태 유지 | `scripts/collection_ui.gd`, `scripts/interface.gd`의 호출부 필요 시 |

## 7. 구현 승인 후 완료 조건 — 이번 보고서에서 검사하지 않음

1. 일반 주문 30 / 완성 합성 30 / 유물 12 및 발견 건수가 실제 데이터와 일치한다.
2. 주문 12/15/3, 합성 24/5/1 필터가 데이터 정의 기준 정확히 작동한다.
3. `1280×720`, `1600×900`, `1920×1080`에서 선택 아이콘·툴팁·설명·뒤로 가기 버튼이 잘리지 않는다.
4. 30종 아이콘이 한 화면에 들어오는 6×5 배치가 실제 테마/스크롤바 환경에서도 성립하는지 **Godot 렌더로 확인**한다. 안 되면 5열/크기 조정을 비교한다.
5. 기본~+3 강화 설명은 현재 카탈로그/진행 계산 함수와 일치하며, 변경된 단계만 읽기 쉽게 구별된다.
6. 합성 재료 두 개에서 일반 주문으로 이동할 수 있고, 해당 주문에서 합성 결과로 이동할 수 있다.
7. 미발견 합성 재료의 공개 범위가 기존 동작과 일치하며 미발견/발견 상태 표시가 뒤바뀌지 않는다.
8. 목록 중간/끝에서 항목 전환·왕복 링크 탐색 후 선택·스크롤·포커스가 예상대로 보존된다.
9. 마우스뿐 아니라 키보드/패드 입력으로 모든 주요 도감 조작이 가능하다.
10. 도감 열기·선택·탭 전환·닫기 후 발견 기록·마석·마법 소유/장착이 변하지 않는다.
11. 타이틀 및 제작함에서 진입/복귀 시 게임 시간 진행 상태·저장·입력 포커스가 기존과 같다.
12. 결과는 **소스 열람/자동 테스트/Godot 실제 렌더·입력/사용자 미술 승인**을 구분해 기록한다.

## 8. 승인 필요 사항과 미확인

- **아직 확정 아님:** 6열 아이콘 구조, 역할별 보조 필터, 책 형식 미술, 선택 강화 단계 UI, 합성 레시피 카드 디자인.
- **기존 구현 보존:** 미발견 합성 부모 공개, 발견·저장·경제·지급 금지 규칙.
- **추후 검증:** 스크롤 초기화 현상의 실제 재현, 모든 항목의 포커스 접근성, `1280×720`에서 우측 설명 과밀.
- **범위 제외:** 몬스터 도감·마녀 인물 도감·별도 기록 통합, 신규 이미지 제작.
