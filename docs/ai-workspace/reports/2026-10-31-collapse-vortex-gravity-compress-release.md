## 1. 승인된 핵심 콘셉트

**기본 블랙홀(소용돌이 씨앗)보다 작은 중심핵이 극단적으로 강한 흡인력을 발생 → 주변 적과 탄환을 모아 압축/저장 → 잠시 뒤 핵이 붕괴하며 저장한 탄환과 끌려온 적을 여러 방향으로 다시 분출.**

### 1단계 — 강력한 흡입

- 기본 블랙홀에 비해 **시각적 중심핵/공격 크기는 작게** 표현한다. 정확히 핵 크기만 줄일지, 피해/흡인 반경까지 줄일지는 미확정이다. **작은 핵인데도 넓은 거리에서 빨아들이는 인상**이 사라지면 의도 불충족.
- **일반 블랙홀보다 현저히 강한 적 흡인력**을 가진다. 범위 안의 적이 실제로 핵 쪽으로 이동해야 하며 단순 화면 연출만으로 대체해서는 안 된다.
- **주변 탄환도 흡수한다.** 우리 게임에서 검토해야 할 종류는 플레이어 마법 투사체(`game.projectiles`)와 적의 발사체(`game.hostile_shots`)다. 어떤 소유권의 탄환을 무효화/흡수할지 예외는 미확정이지만, '탄을 흡수한다'는 핵심 자체를 단순 흡수 카운터나 빛 이펙트로 대체하면 안 된다.
- 광선/장판/공전 위성 등 **물리적 비행 탄환이 아닌 공격**의 흡수 가능 여부는 별도 정책. 무조건 모두 지원한다고 약속하지 않는다.

### 2단계 — 압축·축적

- 일정 시간 탄환을 중심핵에 끌어들여 저장한다.
- 적은 중심 근처로 끌려와 압축되는 모습을 보인다. **적을 제거하고 탄환으로 변환한다는 의미가 아니다.** 적 개체의 체력·상태·종별 속성은 유지하고 방출 시 원래 적으로 다시 날려 보낸다.
- **실제 탄환을 흡수했다는 사실과 시각 표현**을 일치시키고, 저장한 탄환은 흡수 직후부터 전장에 별도 히트/이동/연결을 계속 일으켜서는 안 된다.
- 탄환 저장 시 원래 공격의 식별자/기본 피해/속성/상태/관통/수명/소유권/원본 발동 경계 등을 기록할지, 어떤 필드로 압축하는지는 구현 계약에서 정한다.
- 탄환 종류별 예시(원본 성질 보존을 목표로 하는 제안): 별빛탄→별빛탄, 화염구→화염구/원래 폭발, 빙결탄→빙결, 관통탄→관통. **모든 원본 속성 완전 보존을 구현 완료로 약속한 것은 아니며**, 예외를 기능 축소 없이 사용자에게 드러내야 한다.

### 3단계 — 붕괴·폭발·방사형 방출

- **잠시 뒤 한 번의 명확한 붕괴 폭발**이 발생한다. 단순 종료 범위 피해로 끝나지 않고 **탄환 재발사 + 적 방출**까지 이어지는 것이 필수.
- 흡수된 탄환을 **사방으로 다시 발사**한다. 탄환이 실제로 이동·충돌·피해를 입혀야 한다. 단순 장식용 조각을 그리는 것만으로는 불합격.
- 모인 적은 중심에서 바깥으로 **강한 방사형 밀침/방출**을 받는다. 순간적인 좌표 재배치만으로 처리하기보다는 짧은 **방출 운동 상태·속도**로 실제로 날아가는 동작을 만드는 것이 권고 구현이다. 이후 정상 AI/피격으로 복귀.
- **다시 내뿜은 탄환과 적이 실제로 충돌·명중**할 수 있어야 한다. 피격 여부는 대상 소유권 및 충돌 규칙에 따르며, 아군탄/적탄 구분은 미확정.
- 다수 적·탄환이 주변으로 퍼져나가는 모습을 주어 **블랙홀(지속 흡인·피해)** 및 **화이트홀(지속 반발·피해)**과 고유성이 겹치지 않게 한다.

## 2. 기존 '붕괴 소용돌이'와 차이

| 항목 | 현재 실제 구현 | 새 개편 방향 |
|---|---|---|
| 레시피 | `vortex + expire` | **유지** |
| 블랙홀과 비교한 크기 | 별도 소형 중심핵 설정 없음 | **더 작은 중심핵** |
| 적을 모으는 힘 | 일반 소용돌이 흡인 | **훨씬 강력한 흡인** |
| 탄환 | 별도 흡수/축적 기능 없음 | **탄환을 실제 흡수·저장** |
| 적 저장 | 범위 안에 들어온 **서로 다른 적 ID**만 카운트 | 적을 실제로 **끌어모아 폭발 시 바깥으로 방출** |
| 종료 | **포획 ID 수에 비례한 원형 압축 충격파 1회** | **일정 시간 뒤 붕괴 폭발 + 흡수 탄환 재발사 + 적 방사형 방출** |
| 기존 피해 공식 | `(20 + min(20, 포획고유ID수)*3) * power`, 반경 `radius*1.25` | **기존 포획 수례 종료 충격파 전용 기믹은 새 중심 효과로 대체**. 새 피해 공식·파동 유무 미확정 |

- **기존 `_captured` 고유 ID 카운트만 남겨놓고 마지막에 피해량을 키우는 기존 방식은 이번 개편의 핵심을 충족하지 못한다.**
- 붕괴 시 추가 광역 피해 자체는 가능하지만, **최종 피해량/범위, 기존 공식의 부분 상속 여부**는 사용자 미승인 수치다.

## 4. 구현 권고 — 확정이 아닌 선택지

1. **탄환 흡수 범위:** 실제 **비행 탄환**부터 지원. 광선/장판/위성 등 특수 공격의 처리 규칙을 별도 정의. 지원하지 않는 공격 범위를 몰래 전부 흡수 가능이라 설명하지 않는다.
2. **탄환 정보 보존:** 가능하면 기존 공격의 유형과 속성·기본 피해·관통을 보존한 채 방사형으로 재발사. **모든 탄환을 별빛탄 하나로 치환하지 않는 방향**을 권고. 이벤트 후속·재분열 등은 **새 무제한 생성 루프가 없도록** 명시적 규칙을 만든다.
3. **플레이어탄/적탄 소유권:** 흡수한 적탄을 **적탄으로 재방출**할지 플레이어 공격으로 **반사/전환**할지 아직 미확정. 전투 역할에 큰 영향을 주므로 임의로 결정하지 않는다.
4. **적의 저장 표현:** 적의 실체는 유지하고 중심으로 모으는 방식을 기본으로 검토. 강제 위치 변경이 아니라 **흡인/방출의 실제 이동 궤적**을 확인한다.
5. **저장·동시 발사 성능:** 저장 가능한 실제 탄환 수에 상한을 두고 초과 흡수분을 에너지로 환산하는 방식은 **권고안**. 사용자가 흡수한 모든 탄환의 재발사를 기대할 수 있으므로, *상한을 두어 일부 탄환을 생략한다면* 해당 손실과 대체 효과를 명확히 보고하고 승인을 받는다. 또는 여러 프레임에 나눠 **모든 탄환을 손실 없이 방사형으로 재발사**할 수 있는 큐/가상화 방안을 검토한다.
6. **보스/엘리트 반응:** 보스 AI 무력화를 막기 위한 흡인/방출 저항은 제안. **실제 제어 효과**를 보스에게 어느 정도 줄지는 결정 필요.
7. **타이밍:** '잠시 뒤 폭발'의 충전 지속시간·수명·정상 종료 이벤트, 다른 연결/취소/웨이브 종료 시 예외는 미확정. 구형 `expire` 연결과 최신 **소멸 후→마법공예 이중주식 교체 결정**의 관계는 별도 호환 검토할 것.
8. **VFX:** 작은 중심핵으로 물체들이 쏠리는 흐름 → 핵 압축/충전 → 강한 방사형 탄환·적 분출. 단순 1회 링 VFX로 대체하지 않는다.
9. **원작 출처:** 기본 블랙홀은 **마법공예(Magicraft) 1007**에 근거하는 별도 보고서가 있지만, **주변 탄환과 적을 저장해 방사형 재발사하는 이번 붕괴 효과는 사용자가 제안한 우리 합성 개편안**이다. 원작 블랙홀 고유 효과였다고 오기하지 않는다.

## 5. 향후 구현 전·후 테스트 기대값(사용자 요구에서 독립 도출)

- **흡인:** 같은 거리/시간/종류의 적을 놓고 일반 블랙홀 대비 **더 강한 중심 이동**을 실제 적 좌표로 확인. 중심핵은 **더 작게 보이되** 흡인/피격 범위와 VFX가 어긋나지 않을 것.
- **탄환 흡수:** 주변을 통과하는 플레이어탄·적탄의 **실제 움직임이 핵을 향해 꺾이고 핵에 들어간 뒤 전장에서 제거/비활성화**되는지 확인. 회수된 탄이 동일 프레임에 재피격/중복 처리되지 않을 것.
- **속성·개수:** 흡수한 별빛탄/화염구/빙결/관통 등의 **보존 가능한 공격 정보**가 재발사 후 의도한 실제 충돌·피해/상태를 내는지 검사. 적탄 소유권/특수탄 예외는 정책 확정 뒤 별도 시험.
- **적 방출:** 핵에 모인 일반 적 여럿이 폭발과 함께 **여러 방향으로 실제 날아가고**, 단순 좌표 순간이동 없이 뒤이어 원래 AI 상태로 복귀. 보스/엘리트는 허용 규칙에 따라 검증.
- **붕괴 시점:** 설정된 충전 시간이 끝나면 **1회만 폭발**, 탄환/적 방출. 아무것도 없을 때·탄환 0개일 때도 정상 종료하고, 강제 종료/화면 밖/웨이브 전환 시 유령 탄환/잔여 예약·2중 폭발 방지.
- **상한/성능:** 1개/복수 붕괴핵, 적 수십~수백, 4오브, 탄환 상한 근접, 큰 `delta`, 경계/보스전에서 **폭발이 겉으로만 발생하고 실제 탄환이 차단**되는 실패를 측정. 과도한 발사로 CPU가 폭증하거나 끝나지 않는 파생 생성 금지.
- **다른 결정 보호:** 기본 블랙홀(`vortex`)은 원작식 이동·흡인·피해·시간 성장, 화이트홀(`orbit_vortex`)은 반발형 단일 핵으로 각각 **별도 확정 설계**. 둘을 이번 붕괴 기능으로 덮어쓰지 않는다. 기본 보조 공전·소멸 후 및 가시꽃 등 다른 조합 회귀 확인.
- **검증 수준 분리:** 소스 정적 확인 / 컴파일·자동 검사 / 실제 생성·피격·속성·종료 / 화면 VFX / 성능 / 게임 체감을 구별. 단순 탄환 생성만 성공했다고 전체 기능 완료로 보고 금지.
