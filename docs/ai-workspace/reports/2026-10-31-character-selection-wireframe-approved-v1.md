## 1. 채용 목업 식별 — 원본과 PNG 포함 범위를 구분

| 항목 | 값 |
|---|---|
| 채용 원본 파일명 | `마녀들의_사고현장_캐릭터_선택_화면.png` |
| 실제 생성 이미지 해상도 | **1672 × 941 px** (약 16:9) |
| 원본 이미지 SHA-256 | `16e87036b42822bdab190ff4c09aeef1c6bc990005471b984f441a8e256a9377` |
| 이미지 특징 | 회색/베이지 플랫 패널·가이드 테두리·보라색 선택 강조·캐릭터 실루엣 플레이스홀더 |
| 이미지 증거 수준 | **채팅에 실제 표시한 이미지 생성 와이어프레임** / Godot 게임 화면을 캡처한 PNG 아님 |
| GitHub 바이너리 포함 여부 | **이 보고서 커밋은 Markdown만 등록. 원본 PNG 바이너리는 아직 저장소에 첨부되지 않음.** 상대 이미지 링크를 만들어 첨부된 것처럼 표기 금지 |

**원본 파일의 명칭·SHA는 나중에 정확한 동일 이미지를 확인해 바이너리로 등록하기 위한 식별 정보다.** 원본을 가져올 때 비슷한 다른 캐릭터 채색 시안으로 바꾸지 않는다. 이미지의 플레이스홀더(마녀 실루엣, 마법 아이콘, 시연 문구)는 최종 캐릭터 아트·실제 런 빌드 데이터로 확정한 것이 아니다.

## 2. 확정된 화면 구조

1. **상단 영역:** 왼쪽 `마녀들의 사고현장` 로고/화면 제목. **오른쪽 위에 `타이틀로` 독립 버튼**. 시작 버튼 아래에 붙이거나 같은 버튼 그룹으로 묶지 않는다.
2. **왼쪽 큰 캐릭터 전시:** 실루엣/향후 실제 일러스트를 위한 **큰 직사각형 영역**을 화면 좌측 대부분에 둔다. 현재 선택된 캐릭터와 표시 이름이 연동된다.
3. **왼쪽 아래 네 마녀 초상화:** `네라 / 루미 / 모카 / 세라` 순서로 네 개의 **가로 인물 카드**를 배치한다. 화면에 동시에 모두 보이며, 현재 선택된 카드만 **보라색 테두리·체크/선택 표시**로 구별한다.
4. **오른쪽 위 정보 패널:** 선택된 마녀의 **큰 이름 → 캐릭터 소개(짧은 1~2줄) → 플레이 스타일 요약** 순서로 구성한다. 줄바꿈과 여백으로 위계를 구분한다.
5. **오른쪽 중단 시작 마법:** `시작 마법` 패널에 **가로 카드 4개**를 배치한다. 카드마다 아이콘·시작 조합 이름·핵심 설명; 선택된 카드의 보라색 테두리/체크 표시를 적용한다.
6. **오른쪽 하단 주요 행동:** 폭이 큰 보라색 **`실험 시작`** 버튼. 오른쪽 정보/마법 패널과 자연스러운 그룹이지만 `타이틀로`와는 충분히 분리한다.
7. **하나의 준비 화면:** 채용 와이어프레임에서는 **캐릭터 선택과 시작 마법을 동일한 화면에서 동시에 확인하고 선택한다.** 이전의 별도 화면으로 넘기는 2단계 UI는 이 배치 계약을 대체할 수 없다. 선택 상태만 바꿔서는 게임이 시작되지 않고, `실험 시작`에서만 확정한다.

### 레이아웃 개념도 (실제 원본 PNG의 대체물이 아님)

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 마녀들의 사고현장                                    [← 타이틀로]   │
├────────────────────────────────┬─────────────────────────────────────┤
│ 캐릭터 선택                     │ 정보 패널                           │
│ ┌────────────────────────────┐ │ ┌─────────────────────────────────┐ │
│ │                            │ │ │ 루미                            │ │
│ │   선택 캐릭터 큰 일러스트   │ │ │ 캐릭터 소개 (1~2줄)             │ │
│ │   (현재 루미/실루엣 예시)   │ │ │ 플레이 스타일                   │ │
│ │                            │ │ └─────────────────────────────────┘ │
│ └────────────────────────────┘ │ ┌─────────────────────────────────┐ │
│ [네라] [루미✓] [모카] [세라]    │ │ 시작 마법                        │ │
│                                │ │ [작은 정원✓][큰 한 발]           │ │
│                                │ │ [반짝 연사][얼음 실험]           │ │
│                                │ └─────────────────────────────────┘ │
│                                │ [         실험 시작           →]   │
└────────────────────────────────┴─────────────────────────────────────┘
```

- **실제 채용 이미지에서는 시작 마법 4장이 한 가로줄**이다. 위 텍스트 개념도는 가독성 때문에 2행으로 축약한 것뿐이며, 2×2 카드 배치 변경을 승인한 게 아니다.
- 채용 원본 비율을 1600×900 같은 실제 게임 기준 해상도에 적용할 때 상대 배치·간격·정렬을 보존하고 Godot 컨트롤 앵커로 재검증한다. **원본 생성 해상도 1672×941이 엔진에 고정하는 픽셀 명세는 아니다.**

## 3. 시안에 쓰인 정확한 예시

| 영역 | 채용 이미지의 표시 | 승인 범위 |
|---|---|---|
| 선택 인물 | `루미` | 기본 표시 **예시**. 네 마녀 선택 영역 자체의 구조는 승인 |
| 인물 소개 | “즉흥적이지만 눈치가 빠른 실전파. 화려한 마법과 빠른 전개에 강하다.” | 소개문 **길이/위치 예시**. 게임 설정·캐릭터 능력치의 최종 설명으로 자동 확정하지 않음 |
| 플레이 스타일 | `공격적 / 직관적 / 연계형` | 정보 구조 승인. 실제 고유 특성·밸런스 사실 확정 아님 |
| 마법 후보 | `작은 정원`, `큰 한 발`, `반짝 연사`, `얼음 실험` | 기존 시작 키트 4종을 이 화면에서 나타내는 **실제 후보명**. 상세 설명 및 지급 마법은 `Economy.KITS` 실물 데이터에 맞춰야 함 |
| 마법 선택 | `작은 정원` | 선택 상태 표시 **예시**, 기본 선택 강제 아님 |
| 선택된 상태 | 캐릭터 루미·마법 작은 정원에 보라색 테두리와 체크 | 선택 피드백 **시각 구조 승인** |
| 비선택 인물·아이콘 | 회색 실루엣과 추상 심볼 | **플레이스홀더**. 캐릭터 외형/마법 아이콘 채택 아님 |

## 4. 사용자 지적 사항 및 반영 결과

- 이전에 보여준 화려한 그림은 **UI 목업이라기보다 콘셉트 아트**였으며, 실제 버튼/슬롯의 제작 기준으로 직접 사용하지 않는다.
- **`타이틀로`가 `실험 시작` 바로 아래 붙은 문제**는 이 채용 와이어프레임에서 해결: 상단 오른쪽 독립 버튼으로 확실히 분리.
- **캐릭터 일러스트보다 화면 구조 검토가 우선.** 실제 큰 일러스트와 초상화는 추후 자산을 교체하되 영역·상호작용은 유지.
- 시작 마법은 장식성 아이콘만 보여주는 것이 아니라, 각 조합을 구분할 이름과 기능 설명이 있는 실제 선택 UI를 목표로 한다.
- 게임플레이/UI 시스템 문구는 [확정 문구 톤 정책](../decisions/2026-10-31-battle-ui-copy-tone-no-cutesy-dialogue.md)을 따르며 과장된 감탄/대사로 대체하지 않는다.

## 5. 기존 구현과 충돌을 막는 계약

1. 선행 조사 기준 플레이 루프는 **루미 중심의 준비/시작**, 시작 조합은 **4개 `Economy.KITS`**이다. **화면에 네 마녀를 그렸다고 현재 네 명 모두 플레이 가능하다는 뜻은 아니다.**
2. 네라·모카·세라의 실제 런 구현·고유 능력·해금 정책이 없으면 **존재하지 않는 플레이를 버튼으로 실행하지 않는다**. `준비 중`처럼 실 구현 상태를 정확히 구분하거나 실제 사용 가능 시점에 활성화한다.
3. 시작 키트별 마법 지급·강화 상태·아이콘은 현재 데이터에서 가져와 표시한다. 시안 속 식물/별/눈 결정 아이콘·마법 설명을 실제 규칙으로 단정하지 않는다.
4. 마녀 또는 시작 키트를 **가리키거나 선택하는 행위만으로 실험 시작/저장 덮어쓰기/자원 소비가 발생하면 안 된다**. 실제 시작 입력은 `실험 시작` 한 번으로 분리한다.
5. 기존 선택적 도입, 타이틀 복귀, 체크포인트/재도전 흐름을 임의로 제거하지 않는다. 시안에 도입 토글이 없다는 이유로 기존 실제 기능을 삭제하지 않는다.
6. `front_flow.gd` 및 관련 구현과의 정합성, 키보드/패드 포커스는 실제 구현 전 다시 확인한다.

## 6. 구현 및 검증 조건 (현재 미실행)

- 화면에서 네 개 초상화가 동시에 보이고 현재 선택 상태가 분명하다.
- 캐릭터 선택을 변경하면 왼쪽 큰 그림/오른쪽 인물 이름·소개/플레이 스타일이 일치해 변한다. 구현되지 않은 캐릭터의 시작은 차단한다.
- 시작 조합 카드 4개가 **한 줄로** 표현되며 선택/설명/실제 지급 데이터가 일치한다.
- `타이틀로`는 상단 오른쪽에 별도로 있고, `실험 시작`은 오른쪽 하단의 단일 주요 버튼이다.
- 현재 이미지의 1672×941 비율을 기준으로 상대 배치를 보존하며 **1600×900, 1280×720, 1920×1080**의 잘림/간격/라벨 길이를 검토한다.
- 마우스 클릭, 키보드 Tab·방향키·Enter·Esc(필요 시 게임패드)로 올바른 선택과 복귀가 가능하다.
- 선택/포커스와 실제 확정 구분, 루미 실험 시작/도입 스킵/타이틀 복귀/재도전 경로를 회귀 테스트한다.
- 디자인 와이어프레임 채택 / Godot 실제 구현 / 실제 렌더·입력 검증 / 최종 스킨·아트 승인은 **각각 독립적 단계**로 남긴다.

## 7. 추후 미확정 사항

- 네라·모카·세라의 실 플레이 기능 및 캐릭터별 능력치·특성.
- 네 마녀의 확정 큰 일러스트/실제 초상화 자산·캐릭터 소개 최종 텍스트·플레이 스타일 데이터.
- UI 스킨, 색상, 절대 좌표 및 모바일/초소형 해상도 대응.
- 실제 시작 조합 4종의 현재 정확한 마법 지급 수량·아이콘/효과 문구 대조.
- **원본 PNG GitHub 바이너리 등록**(이번 보고서의 글만으로 첨부되었다고 취급하지 않음).
