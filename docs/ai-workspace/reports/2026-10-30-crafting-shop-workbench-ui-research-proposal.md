## 1. 사용자가 지적한 문제와 검토 목표

사용자의 피드백: **현재 상점(제작) UI의 외형과 구성에 강한 불만**. 단순 색상 변경·GUI 테마 교체만이 아니라 상점/제작의 구조를 다시 조사해야 함.

3. **구매/편집 뒤 실제 조합이 어떻게 달라지는가?**

추천 판단 기준: 미술적 완성도 + 아이콘/가격 가독성 + 구체/오브 관계 인식 + 왕복 조작 수 + 기존 기능 안정성.

### 정적 코드에서 도출한 핵심 UX 가설

**문제 A — 상점과 가방/오브가 분리되어 있다.** 구매할 구체와 현재 보유/장착 상태를 동시에 대조하기 힘들 수 있다. 탭 이동 자체는 동작하지만 플레이어의 판단 과정에는 왕복이 발생한다.

**문제 B — 화면의 주인공이 모호하다.** 상단 오브, 왼쪽 구매 목록, 오른쪽 상세 카드, 4개 탭, 오브 성장·유물, 하단 버튼이 한 패널 안에서 경쟁한다.

**문제 C — 상점이라는 감각이 약할 수 있다.** 현재 상품 카드가 아이콘·가격·제작 버튼으로는 기능하지만, '진열품'의 비주얼 위계와 상호작용 피드백이 충분하지 않을 수 있다.

**문제 D — 조합 결과가 중심에 있지 않다.** 핵심 재미가 '구매 그 자체'가 아니라 '새 부품이 기존 오브의 작동 방식을 바꿈'인데, 구매 시점의 시각적 비교가 부족하다.

**중요한 검증 구분:** 위는 소스에 근거한 **UX 가설**이지 실제 최신 화면의 미관/가독성 또는 사람의 사용성 시험을 완료했다는 뜻이 아니다. 기존 구현 문서의 과거 스크린샷 경로는 이력으로만 사용했다.

## 4. 세 가지 레이아웃 대안

### A안 — 현행 오른쪽 1036px 패널 개선

- 장점: 현재 제작 UI·시험 창과 구조적으로 비슷하고 수정 범위를 통제하기 쉽다.
- 방향: 오브 슬롯 강조, 제작 카드 정보 정리, 상세의 과잉 문구 축소, 하단 버튼 위계 조절, 필요 시 탭 구조 수정.
- 단점: 가방과 제작 목록을 계속 탭으로 교체하면 가장 큰 UX 문제는 남는다.
- 판단: **최소 비용·회귀 위험 제한용 대안**. 최선의 완성형은 아닐 수 있다.

### B안 — 상점·오브·가방이 함께 보이는 통합 작업대 **(우선 추천)**

- **위쪽:** 현재 오브(활성 오브는 크게) 및 마법 순서. 전체 오브 선택 상태와 활성 편집 대상 명확화.
- **왼쪽 중심:** 구매 가능한 제작안 카드. 상품 아이콘/마법명/가격/구매 상태를 확실히 구분.
- **오른쪽 중심:** 선택한 구체의 큰 아이콘, 역할·효과, 강화/변화, 구매 또는 장착 등 **현재 행동 하나**에 대응.
- **하단:** 현재 보유한 마법 가방을 끊기지 않는 슬롯/격자로 제공하여 구매한 마법의 위치를 확인.
- **맨 아래:** 되돌리기/시험 발사와 `준비 완료`를 구별해 배치.
- **오브·유물 성장/합성:** 기본 주문 구매를 방해하지 않도록 별도 보조 뷰/탭/교체 가능한 중심 작업으로 처리하되, 현재 오브·가방과 관련된 정보는 유지.
- 효과: `제작 상품 선택 → 현재 오브 확인 → 구매 → 가방에 들어옴 확인 → 필요 시 장착/강화`의 맥락을 잃지 않음.
- **주의:** 제품 코드의 큰 패널을 그대로 두고 4개 영역을 단순히 추가하면 더 복잡해질 수 있다. 본격 적용 시 화면폭·행동의 우선순위를 재조정한다.

### C안 — 마법 실습실 내 물리적인 작업대 연출

- 상품을 받침대/선반/수정구 형태로 전시하고 제작대·마법 연구 도구를 배경 요소로 사용.
- 장점: '마법사의 상점'이라는 감각과 세계관 표현이 강함.
- 단점: 작화·애니메이션·클릭 영역·상호작용·유지보수 비용 증가.
- 판단: **기능 레이아웃 완성 후 장식으로 제한하여 도입 권고**. 별도 전면 씬 구축을 전제하지 않는다.

### 종합 권고

**B안의 사용자 행동 흐름 + Magicraft식 상품 진열감 + Noita식 배열 가독성 + 현재 게임의 둥근 카툰 테마**가 1순위. **외부 GUI 스킨 단독 교체는 최종 해결책이 아니다.**

```text
│ [오브1] [오브2] [오브3] [오브4]          [유물 상태]         │
│ 활성 오브: [공격] [보조] [연결] [공격] [ ... 슬롯 ... ]      │
├────────────────────────────────────────────────────────────┤
│ [마법 제작] [합성] [오브·유물 성장]                         │
│ ┌──────────────────────────┐ ┌───────────────────────────┐ │
│ │ 제작 가능한 마법 상품     │ │ 선택한 상품 / 보유 구체    │ │
│ │ [아이콘 이름 가격] [....] │ │ 큰 아이콘 · 효과 · 역할    │ │
│ │ [아이콘 이름 가격] [....] │ │ 강화 변화 / 상태 / 비용    │ │
│ │ [제작안 재구성]           │ │ [구매 또는 장착/강화]     │ │
│ └──────────────────────────┘ └───────────────────────────┘ │
│ [가방: 현재 보유 마법 구체 슬롯 / 역할 필터 / 드래그]       │
│ [되돌리기]   [시험 발사]                  [준비 완료 →]     │
└────────────────────────────────────────────────────────────┘
```

- **우선은 현재 1600×900 논리 레이아웃 내에서 검증**. 지금 1036px 오른쪽 패널을 고수할지, 넓은 별도 준비 화면을 사용할지는 사용자 미결정.
- 화면 크기가 작은 경우 가방을 항상 긴 줄로 보이게 하는 대신 **활성 오브 + 보유품의 최소 정보량**을 유지하는 수축 규칙이 필요하다.
- 제작 준비 화면과 **520px 시험 발사 편집 창**은 기능 목적이 다르므로 같은 폭을 억지로 통일하지 않는다.
- 예시 가격/아이콘은 컨셉 도식에서도 임의로 확정하지 않으며 실제 경제 정의를 재사용한다.

## 6. 주요 컴포넌트 개선 지점

### 6.1 상품 카드
- 최상위 정보: 아이콘 → 마법명 → 가격/무료 여부 → 구매 가능 상태.
- 부차 정보: 공격/보조/연결, 현재 보유/장착 여부, 배치 힌트(툴팁 또는 보조 텍스트).
- 구매 전/구매 가능/잔액 부족/제작 완료/선택 필요 상태는 서로 구분되어야 한다.
- 제작 클릭 후 실제 **인벤토리 수량 변화**와 동일한 아이콘이 가방에 나타나는 피드백 필요. 자동 장착으로 바꾸지 않는다.
- `286×122` 상품 카드를 더 크게 할지는 전체 레이아웃과 함께 테스트한다.

### 6.2 오브 / 마법 배열
- 1~4 오브 탭/번호 중 현재 활성 대상을 분명히 하고, 큰 슬롯 행은 해당 오브의 실제 순서를 표현.
- 보조 주문을 선택하면 **영향 받는 공격 위치**가 강조되어야 함.
- 경고색 계약은 이미 사용자 확정된 **상쇄=노랑, 비작동=빨강** 규칙을 존중; 색만이 아니라 경고 문구/아이콘도 함께.
- 기존 조합법, 빈칸, 드래그, 우클릭 해제, 되돌리기, 성장 단계·칸 수를 변경하지 않는다.

### 6.3 가방
- 상품 목록과 연결되도록 화면의 고정된 구역에 표시하는 것이 1순위.
- `공격/보조/연결` 필터와 현재 선택/스크롤 보존.
- 클릭으로 상세를 열고 드래그로 실제 오브에 배치. 제작 후 가방으로 바로 이동하는 기존 결과 보존.
- 전체 실물 수량과 현재 장착/미장착 구분이 정확해야 한다.

### 6.4 상세·강화
- 현재 선택한 대상이 `제작안`, `보유 구체`, `합성 결과`, `오브 성장` 중 무엇인지 표시.
- 동일한 오른쪽 상세 공간을 **선택 대상에 맞춰 내용만 바꾸는 방식** 권고.
- 마석 강화/동일 마법 합치기/완성형 합성/오브 성장·유물 제작을 같은 버튼으로 오인하지 않도록 행동 문구/위치를 분리.
- `Detail.wide_fusion()`에서 보여주는 두 +3 재료 및 보유량은 유지하고, 이를 시각적으로 `재료A + 재료B → 완성 마법`으로 전개.

### 6.5 명확한 마지막 행동
- `준비 완료`가 가장 강한 시작 행동이며, `시험 발사`는 검증 행동, `되돌리기`는 편집 보조 행동.
- `발견 도감`, `저장 후 타이틀`, 미수령 보상은 다른 수준의 보조 진입으로 묶을 수 있다.
- **준비 시간의 저장·다음 웨이브 전환·현재 조합의 유효성 검사**는 UI 미관 작업 중 손대지 않는다.

## 8. 단계적 설계·검증 로드맵 (승인 후만)

| 단계 | 제안 작업 | 완료 판단 기준 |
|---|---|---|
| P1 — 정보 재배치 | 제작안/현재 오브/가방/상세의 가시성 관계 수정 | 제작→가방 확인→오브 장착을 불필요한 화면 왕복 없이 수행 |
| P2 — 상품 표현 | 실제 마법 아이콘/이름/가격/상태가 읽히는 카드 | 구매 가능/불가·무료·완료가 즉시 구분됨 |
| P3 — 조합 피드백 | 보조 영향 범위·연결 위치·경고·활성 오브 명확화 | 선택한 구체가 실제 어느 슬롯에 영향 주는지 일치 |
| P4 — 기능 분리 | 오브·유물 성장과 합성을 기본 상품 영역에 맞춰 재구성 | 작업별 입력이 다른 행동과 혼동되지 않음 |
| P5 — 아트 마감 | 검증된 GUI 에셋/일관된 카드·탭·프레임 스타일 적용 | 텍스트·아이콘 판독성과 애니메이션 상태가 유지됨 |

### 검증 환경/검사 항목 (이번에는 미실시)
1. Godot 실제 `1600×900`, `1920×1080`, `1280×720` 렌더와 입력 확인.
2. 상품 4~5개, 합성 30개, 가방 길이 변화, 오브 1~4개·6~8칸 조합의 최악 레이아웃 확인.
3. 구매 전/후 재고·마석·체크포인트/세이브가 동일 계약으로 동작.
4. 오브 드래그/되돌리기/동일 구체 강화/오브 성장 3택/유물 제작/합성 정보/미수령 보상 진입 회귀 검사.
5. 가방 필터·선택·스크롤, 탭 이동, 키보드·마우스 포커스 보존.
6. 준비→시험 발사→복귀, 시험 중 구매/강화 비허용, 실제 적 없는 시험과 전투/경제 상태 분리.
7. `준비 완료`가 유효한 조합에서만 진행하며 중복 실행하지 않음.
8. 모든 화면의 실제 시각 확인과 사용자 미관 평가를 **자동 테스트 통과와 별개**로 기록.
9. 기존 `project.godot`, 저장 구조, 마법/몬스터/VFX 수치는 사전 승인 없는 변경 금지.

## 9. 검토/결정이 필요한 사항

- **B안 통합 작업대를 채택할지** 또는 기존 오른쪽 1036px 폭을 유지하면서 화면 구조만 개선할지.
- 활성 오브 한 줄만 크게 표시할지, 여러 오브를 동시에 축약해서 표시할지.
- `합성` 및 `오브·유물`을 탭·보조 패널·독립 준비 페이지 중 무엇으로 표시할지.
- 가방이 항상 보이도록 할지, 최소 공간에 축약된 고정 영역으로 할지.
- GUI 스킨 스타일/구매 여부 및 상업용 라이선스 검토.

이 항목들은 **제안 상태**이며 이번 보고서 등록은 사용자 승인·구현 개시가 아니다.
