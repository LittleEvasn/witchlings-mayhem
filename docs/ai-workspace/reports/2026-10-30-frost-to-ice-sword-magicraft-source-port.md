## 1. 확정된 목표

1. 공격 이름을 **서리숨결 → 얼음검**으로 교체한다. 기존 서리 부채꼴 분사 공격의 핵심 판정과 연출은 폐기.
2. **파마의 검처럼 시전자 전방에 얼음검이 생겨 실제로 좌/우 원호를 휘두르게 한다.** 공격 중심·회전하는 검의 각도·움직이는 충돌 영역이 일치해야 한다.
3. **파마의 검과 동일한 휘두르기 원리를 우선**하고, 우리 게임의 얼음검에는 기존 **냉기 누적 → 동결 → 다른 공격의 파쇄** 시스템을 결합한다.
4. **검을 휘두르는 애니메이션만 흉내내거나, 기존 서리숨결의 한 프레임 부채꼴 판정을 재활용해서는 안 된다.** 검격을 이동하는 공격 객체/히트박스로 다룬다.
5. 실제 `frost` 저장 ID는 변경 시 기존 저장/조합 호환성이 깨질 수 있으므로 **내부 ID는 우선 보존, 표시 이름만 변경**을 권장. 사용자 이름 확정과 내부 ID 변경은 별개.

## 2. 마법공예 파마의 검 — 읽은 소스의 필수 메커니즘

| 항목 | 역컴파일 코드 확인 내용 | Godot 구현 필수 요건 |
|---|---|---|
| **검격 단계** | `Before → Normal → After` 상태 전이 (`Spell1021SlashStage` 및 `Spell1021MoveJob`) | 검 등장/선딜 → **실제 히트박스 활성인 휘두르기** → 후딜/사라짐을 분리 |
| **회전 계산** | `GetCurveValue(진행률)`의 보간 곡선; `BaseDirection`에서 `Scatter` 각도만큼 회전 | 단순 일정 속도/순간 회전이 아닌 **원작 이징 커브 방식** 사용 |
| **원본 강화 각도** | `SpellConfig` 기본 설정에 150° / 180° / 240° | 기본 참고 각도. 우리 0~3 강화의 정확한 4단계 매핑은 **사용자 미확정**, 임의 확정 금지 |
| **좌우 스윙** | `InitFlipY()`가 보통 시전에서 좌우 방향 번갈아 설정 | 연속 시전 시 좌/우 검격 교대; 분열·공전 등의 특별 조건도 처리 |
| **공격 기준 위치** | 시전자 또는 보조가 지정한 `AroundCenter / AroundTarget` 중심 | 검의 중심점을 런타임에 유지하고, 캐릭터·후속 시전 위치 변화를 처리 |
| **검의 회전과 타격** | `Spell1021MoveJob`에서 현재 각도로 회전시켜 실제 `LocalTransform` 변경 | 회전하는 **검의 실제 충돌 영역과 시각적 칼날**이 동일하게 움직여야 함 |
| **활성 충돌 영역** | `Spell1021MagicBreakerSystem`이 칼날형 크기와 히트 트리거 구성, `DamageSystem`이 타격 계산 | 단일 원뿔 반경 테스트가 아닌 **칼날 스윕 충돌**을 판정 |
| **타이밍** | `Before` 페이드인, `Normal` 휘두르기, `After` 페이드아웃; 원작 코드에 0.2초 선연출·0.25초 후연출 경로 | 실제 휘두름의 전후 프레임·피해 가능 시간 명확화 |
| **검 시각** | `Spell1021Effect.cs`에서 칼날 스프라이트, 그림자, 검 자취 및 입자, 퇴장 연출 | 우리 2D 스타일로 검 몸체/회전 방향/잔상을 따로 구현 |
| **명중 기록** | 타격 트리거 및 대상 추적 버퍼로 동일 검격 중 피해 처리 | 프레임마다 같은 적이 무한히 맞지 않도록 원작 구조에 대응하는 명중 제한 |

**추가 주의:** 원작 코드에서 `SlashTime = Scatter / 360 / speed_ratio`와 같은 각도·속도 연동이 나타난다. 단순히 ‘검이 0.2초 돌면 된다’처럼 임의 상수로 대체하지 말고 **원본 수식을 항목별로 Godot에 대응**해야 한다. 원작은 Unity C#, 우리는 Godot GDScript이므로 물리 프레임/좌표/단위·이벤트 수명 차이를 문서화할 것.

## 3. 현재 구현과 필수 변경 지점

| 파일 | 현재 문제 / 변경 목표 |
|---|---|
| `scripts/magic_catalog.gd` | `frost` 표시명이 **서리숨결**. **얼음검**으로 교체하고 설명을 휘두르기·냉기·동결 중심으로 수정 |
| `scripts/spell_behaviors.gd` | `special()`의 `"frost"` 분기는 한 번 원뿔 내부 적을 고르고 피해·냉기 부여 후 `flash(kind:"cone")`로 종료. **이 즉발 부채꼴 판정을 검격 객체의 시간별 충돌로 완전히 교체** |
| `scripts/magic_visuals.gd` | `"cone"` 시각은 부채꼴 면 채우기/원호. 실제 칼날·회전·잔상·등장/퇴장 렌더링 필요 |
| `scripts/spell_runtime.gd` | `frost`가 현재 투사체가 아닌 `behavior.special()` 즉시 공격 분기. 검격 인스턴스 관리, 생존시간, 명중 이벤트/연결 트리거 필요 |
| `scripts/spell_progression.gd` | 현재 `frost` 강화는 부채꼴 각도 60°/70°/80°/90° 및 명중 대상 4/6/8/10. 원본 파마의 검처럼 **휘두르는 각도·사거리·검격 특성으로 재설계**, 4단계 수치 확정 후 수정 |
| `scripts/spells.gd` | 설명 문자열/태그·발사 간격/보조 적용값·관련 테스트 참고. `frost` ID 보존 시 외부 조합 호환 확인 |
| `scripts/magic_extensions.gd` | 이동·추적·공전·낙하·분열·메아리 등 보조를 검격에 연결하는 규칙 검토 |

**냉기/동결 시스템:** `spell_behaviors.gd`의 `hit()`는 현재 `cold` 누적, 3중첩 동결, 동결 중 다른 직접 공격의 추가 파쇄 피해를 처리한다. **이 상태 시스템을 유지하되 얼음검의 각 실제 명중 이벤트에서 호출**해야 한다.

## 4. 합성 공격 호환성 — 기존 숨결 합성은 그대로 둘 수 없음

- **`cold_flame` / 냉염숨결:** `frost + element_fire` 조합으로, 현재 '냉기와 화염 분사'를 전제. **얼음검으로 바뀌는 즉시 이름·검격/원소 반응 판정을 별도 개편**해야 함. 이름과 새 효과는 사용자 미확정.
- **`triple_frost` / 빙정 삼중파:** `frost + fan` 조합으로, 현재 부채꼴 방향을 늘리는 구조. **다중 검격/검 수/타격 각도의 새 방식**을 따로 설계해야 함. 이름과 새 효과는 사용자 미확정.
- **보조와 연결:** `갈래`는 단순 원호 수 증가인지 다중 검 생성인지, `추적`은 대상 중심 스윙인지, `공전`은 회전 중심 변경인지, `관통`은 검격 대상 상한인지, `시간 트리거`는 즉시 소멸할 때 예약 소실되는지 각각 확인.
- 빨간 비작동/노란 상쇄 경고 규칙은 [기존 결정 문서](../decisions/2026-10-30-magic-warning-severity.md) 준수. **새 검격 타입으로 기존 보조가 조용히 비활성화되는 것을 금지.**

## 5. Codex 구현 후 완료 판정 기준 (현재 미실행)

1. **정적 코드 대조표**: 원작의 생성→회전 계산→Before/Normal/After→실제 타격→종료 모든 경로를 Godot 대응 함수와 줄 단위로 매핑하고, 예외/생략을 명시.
2. 실제 엔진에서 **시전 방향을 기준으로 검이 한 바퀴가 아닌 지정 각도 원호만** 휘두르는지 궤적/히트박스 좌표를 프레임마다 기록.
3. 좌우 연속 시전으로 검격 방향이 교대하는지 검사.
4. 검이 지나지 않은 원뿔 영역 적에게 미리 피해가 발생하지 않는지, 지나간 적에게 정확히 피해와 냉기 누적이 발생하는지 검사.
5. 한 번 휘두르는 동안 같은 적의 중복 타격 제한을 확인하고, 여러 적 동시 명중이 가능한지 검증.
6. 강화 0~3의 각도·검 크기·시간과 화면 표시 텍스트의 일치 여부 확인.
7. 공격·보조·연결·합성 4오브 구성 및 웹 훈련장/Windows 원본에서 실제 동작 검사. 특히 `cold_flame`·`triple_frost`는 미확정 구현을 임의로 완료 처리 금지.
8. **'그럴듯한 검 그림 + 기존 원뿔 판정'이면 불합격.** 동작을 실제로 재현한 증거 없이 `VERIFIED` 처리 금지.
