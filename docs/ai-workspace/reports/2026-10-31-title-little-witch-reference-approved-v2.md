## 3. v2에 실제 존재하는 메뉴

정확한 노출 순서:

1. `이어하기`
2. `새 실험`
3. `마법 훈련장`
4. `발견 도감`
5. `실험 기록`
6. `설정`
7. `종료`

- `이어하기`와 `새 실험`은 **큰 글씨의 주요 항목**.
- 그 아래에는 짧은 간격을 두고 보조 항목 5개를 **작은 글씨로 배치**.
- 시연 기본 선택 항목은 `이어하기`. **시연 목업에서는 실제 저장 여부를 검사하지 않으므로** 현재 저장이 없더라도 항목이 선택 가능하게 표시될 수 있다. **실제 Godot 구현에 그대로 가져오면 안 된다.**
- 이 메뉴 개수와 용어는 **채용된 v2 목업 표현**. 저장에 따른 노출/비활성화는 원래 게임 기능 계약을 우선한다.

## 4. 상호작용과 현 목업의 한계

현재 HTML v2가 제공하는 동작:

- **↑ / ↓ 방향키**로 선택 위치를 순환 이동.
- **마우스 오버**로 해당 항목에 커서 이동.
- **마우스 클릭 / Enter / Z**로 선택 항목의 `… 실행 시연` 텍스트를 잠깐 표시.
- 메뉴의 선택 상태는 왼쪽 **삼각형 커서**로 구별됨.

**구현하지 않은 동작:**
- 실제 `이어하기` 체크포인트 로딩, `새 실험` → 선택 화면 전환, 훈련장·도감·기록·설정 및 종료 실행.
- 시작 조합/캐릭터 선택, 오프닝·전투 진입, 메뉴의 저장에 따른 활성 상태 변경.
- 실제 Godot 엔진 렌더·컨트롤 입력·해상도 적응/애니메이션 실측.
- 원작 게임의 음악·이미지·코드 사용, 새 BGM/SFX 제작.

**따라서 ‘인터랙티브’는 커서 탐색 및 실행 시연에 한정**한다. 목업이 전투 진입 구현을 완료했다고 기록하면 안 된다.

## 5. 화면 구성/연출 계약

- 메인 배경은 화면 **100% 전체를 덮는 장면**. 현재 HTML은 CSS 그라디언트·기하학적 달·구름·산·학교 실루엣·수면·전경 나무로 **임시 묘사**.
- 로고는 **오른쪽 위**. 왼쪽 위/중앙 왼쪽의 대형 메뉴 패널은 채택하지 않는다.
- 메뉴는 **로고 아래쪽 오른쪽 중하단**이며, 컬러 외곽선을 두른 밝은 글씨와 왼쪽 삼각형을 중심으로 시인성을 확보.
- 하단 왼쪽은 최소 조작 힌트 외에 큰 패널 없음.
- **한 화면의 전체 풍경이 주인공이고 UI는 그 위에 얹힘.** 별도의 캐릭터 디스플레이 박스는 타이틀 화면에 두지 않는다.
- 실제 캐릭터 선택 화면(02)은 이미 승인한 별도 **왼쪽 큰 일러스트 + 4인 초상화 + 오른쪽 소개/시작 마법** 구조를 따른다. 타이틀의 미니멀한 텍스트 메뉴를 02 화면에도 무조건 복사하지 않는다.

## 6. 시작 흐름과의 관계 — 아직 구현 계약 변경 없음

기존 03번 보고서 및 [FRONT-FLOW-v1](../../FRONT-FLOW-v1.md)에 있는 런 시작·저장 안전성은 유지:

- `새 실험` → **최신 승인된 02번 한 화면 캐릭터/시작 마법 선택** → `실험 시작` → 기존 선택적 도입/튜토리얼 흐름 → 전투.
- `이어하기`는 저장된 런으로 바로 복귀하며 캐릭터/키트 재선택을 요구하지 않음.
- 기존 체크포인트가 있는데 `새 실험`으로 시작하면 실제 게임에서는 **저장 교체 경고** 유지.
- 시작 화면을 바꾼다고 고유 능력, 미구현 마녀 3명, 오브·마법 지급 규칙을 새로 확정하지 않음.

## 7. Codex 인계 전 확인 사항 — 이번 등록에서 실행하지 않음

1. 해상도 1280×720 / 1600×900 / 1920×1080에서 전체 배경/오른쪽 로고/중하단 메뉴/하단 좌측 안내를 실제 Godot에서 확인.
2. 메뉴는 **박스/카드/패널 없는 텍스트만**, 선택된 단 한 항목에 **▶ 표시**.
3. 방향키·마우스·키보드/패드로 포커스 위치와 커서 위치가 동일한 항목을 가리킴.
4. 저장이 없으면 `이어하기`가 안 보이거나 비활성화되는 실제 게임 계약에 따라 처리. 시연 목업의 항상 활성 동작을 이식 금지.
5. `새 실험`으로 최신 02번 캐릭터 선택을 열고, 기존 저장 대체/취소·전투/도입을 안전하게 처리.
6. 다른 메뉴(훈련장·도감·기록·설정·종료) 실제 기능/복귀와 입력 충돌·상태 재설정 점검.
7. 구매 GUI 자산·배경 아트·반응형 포지셔닝은 기존 아트 시스템을 고려하되, **최종 레퍼런스의 텍스트만 남긴 원칙을 유지**.
8. **HTML 동작 확인 / Godot 코드 구현 / Godot 실제 화면 검증 / 최종 아트 승인**은 각각 별도 완료 기준.
9. 원작 리소스·코드·스프라이트·음악을 그대로 복사하지 않으며, 디자인 개념만 차용.
