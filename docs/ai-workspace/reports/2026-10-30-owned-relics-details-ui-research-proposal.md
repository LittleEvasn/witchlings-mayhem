## 1. 결론

**Slay the Spire의 작은 보유 유물 아이콘·호버 구조를 참고하되, 실제 HUD는 최신 승인안대로 오른쪽 상단 세로 배열**, 선택/상세 열람은 Magicraft식 공통 카드로 통일한다.

- 전투 화면에 보유 유물의 **작은 아이콘을 항상 노출**한다.
- 호버/포커스로 **이름·핵심 효과·중요 조건**을 빠르게 확인한다.
- 필요할 때 `유물 N` 버튼으로 **아이콘형 보유 목록 + 선택한 유물의 큰 상세 정보**를 본다.
- 복잡한 전용 장비 관리 화면이나, 전투를 크게 가리는 3열 텍스트 카드 격자는 우선 피한다.
- 유물 상세의 **실제 작동 수치·발동 조건·장단점·동적 발동 상태**는 데이터가 있을 때만 표시한다.
- 유물은 런 내 자동 적용 패시브이며, **강화 레벨/재료/강화 버튼은 현재 없음**. 기능이 없는 강화 UI를 임의로 만들지 않는다.

## 2. 레퍼런스 비교 (게임 내장 UI 기준)

### A. Slay the Spire — 보유 유물 표시 1순위

앞선 채팅에서 살펴본 게임 화면/카드의 관찰 요점:
- 게임 진행 중 아이콘들이 **짧은 가로줄**에 배치되어 보유 유물을 한 번에 파악한다.
- 각 아이콘을 가리켜 **유물 이름과 효과**를 빠르게 확인한다.
- 개별 정보는 **명확한 이름/아이콘/효과 문장**이 우선이며, 장식보다 판독성이 앞선다.
- 도감/전체 유물 목록 형태도 **작은 아이콘 격자**로 참고 가능. 단, **발견 도감과 현재 보유 목록을 혼동하지 않는다**.

**우리 적용:** 전투 중 보유 유물의 존재감을 유지하고, 개별 상세는 사용자가 원할 때만 열어 큰 화면 점유를 줄인다.

**주의:** 아이콘 배열을 복제해도 Slay the Spire의 유물 발동 순서/스택 규칙을 우리 게임에 도입하지 않는다. 이미지 중 모드 UI는 기본 게임 기능으로 단정하지 않는다.

### B. Magicraft — 상세 카드 1순위

앞선 채팅에서 살펴본 유물 도감/설명 카드의 관찰 요점:
- **아이콘·제목·효과·추가 설명/보충 정보**를 한눈에 구별할 수 있는 카드 레이아웃.
- 유물 종류/상태가 복잡해질 때도 **목록과 상세를 나누어** 설명할 수 있다.
- **현재 효과**와 필요한 경우 **추가 설명**을 읽는 정보 구조가 유용하다.

**우리 적용:** 유물 선택 시 공통 마법·유물 툴팁/UI 스타일(관련 [UI-2026-10-30-09](2026-10-30-spell-relic-tooltip-ui-research-proposal.md))을 재사용한다.

**주의:** Magicraft에 유물 강화·재구성 시스템이 있다고 해서, 우리 게임에 **유물 강화·레벨·강화 비용이 있는 것으로 표시하지 않는다**. 원작 카드/텍스처/실제 이미지의 코드·에셋 복제 금지.

### 3.1 전투 중 '유물 버튼'의 현재 연결 문제 — 수정 전 검증 필요

정적 코드 경로:
1. `interface.gd::show_relics()`: 전투 상태에서 `game.open_personal("relics")` 호출.
2. `game.gd::open_personal(tab)`: `personal_tab="relics"`를 지정하고 `ui.show_personal()` 호출.
3. `interface.gd::show_personal()`: `reward`가 아니면 `PersonalWindow.build()` 호출.
4. `personal_window.gd::build()`: **`g.personal_tab="inventory"`로 다시 설정**, 이후 `CompactInventory` 생성.

**결과:** 전투 중 유물 버튼을 누르면 보유 유물 상세가 아니라 **일반 가방 UI로 넘어갈 수 있는 경로가 정적 소스상 확인**된다. Godot 실제 클릭/동작 테스트는 이번 조사에서 수행하지 않았으므로 **실제 재현 여부는 검증 필요**로 둔다.

해결 방향은 '유물 버튼 → 유물 목록/상세'로 정확히 연결하되, **전투 중 일반 가방의 비정지 동작**, 보상 선택 정지 정책, ESC/Tab 닫기 처리와 충돌하지 않도록 한다. 이전 `RelicUI.inventory()`는 별도 오버레이에서 `combat`을 `paused`로 바꾸는 구현이 남아 있으므로, 무심코 연결만 바꾸면 **전투 정지 정책이 변경**될 수 있다. 전투 중 유물 상세가 정지형일지 비정지형일지도 사용자 결정/테스트 필요.

## 4. 권장 레이아웃

### 4.1 전투 HUD — 최신 승인 HUD의 오른쪽 상단 세로 보유 아이콘

```text
          [유물 4]
          [왕관 아이콘]
          [모래시계]
          [저금통]
          [장갑]
              ↑ 오른쪽 상단 세로 배열·호버 / 키보드 선택
             ┌──────────────────────────────┐
             │ 금이 간 왕관                 │
             │ 주는 피해 +30%               │
             │ 받는 피해 +20%               │
             │ 보호막 피해에도 적용         │
             └──────────────────────────────┘
```

- **기존 왼쪽 아래 유물줄 배치는 폐기**한다. 전투 HUD의 최신 사용자 확정 기준인 **오른쪽 상단 세로 배열**에 맞춘다. 가방·오브·시계·체력·경험치 바의 나머지 최신 위치를 변경하지 않는다.
- 글리프 한 글자 대신 유물별 정식 아이콘을 사용하되, **현재 전용 그림 존재/라이선스 범위를 확인하기 전에는 새 그림이 준비됐다고 말하지 않는다**.
- 배열은 **획득 순서** 등 명시한 표시 순서에 따라 안정적으로 유지하고, 효과/발동의 처리 순서로 보장하는 기능을 추가하지 않는다.
- 아이콘 호버 시 **짧은 설명 카드**. 긴 단서·정밀 예외는 큰 상세에만.
- 화면 폭·유물 수에 따라 줄바꿈/가로스크롤/추가 보기 등 **레이아웃 수용 방법**을 실제 해상도에서 결정한다. 전투 중 조작 방해/적 공격 예고 가림 방지.
- HUD의 아이콘은 **선택/해제하는 장비 슬롯이 아니라 보유 확인용**이다.

### 4.2 전체 보유창 — 아이콘 그리드 + 선택 상세

```text
┌──────────────────── 이번 실험의 유물 4 ────────────────────┐
│                                                          │
│ 보유 유물 목록                선택한 유물 상세             │
│ ┌───────────────────────┐     ┌────────────────────────┐   │
│ │ [♛][⌛][◇][✦]       │     │ [실제 유물 아이콘]      │   │
│ │                       │     │ 금이 간 왕관           │   │
│ │ (선택한 아이콘 강조)   │     │ 주는 피해 +30%         │   │
│ │                       │     │ 받는 피해 +20%         │   │
│ └───────────────────────┘     │ 발동 조건·제한/예외   │   │
│                               │ (가능한 동적 상태)     │   │
│                               └────────────────────────┘   │
│                                             [닫기]       │
└──────────────────────────────────────────────────────────┘
```

- 한눈에 **보유 현황/종류/유물 개수**를 읽고, 선택한 것만 자세히 본다.
- 현재 3열 **큰 텍스트 카드 전부를 동시에 읽게 하는 UI**와 차별화된다.
- 모든 유물이 항상 상세 패널을 하나씩 차지하지 않아 **확장성/가독성**이 낫다.
- 유물 없는 상태: `아직 이번 실험에서 획득한 유물이 없어요.`와 획득 경로 설명, 빈 상세 영역/닫기.
- 어떤 유물을 보고 있었는지 선택 상태를 닫기/재열기·보상 이후에도 일관성 있게 유지. 삭제/획득이 반영되면 유효한 항목으로 선택 보정.
- 최초 오픈 시 첫 유물 자동 선택은 **제안**일 뿐 확정 동작이 아님.
- 카드의 단추/스크롤과 일반 가방의 드래그 입력을 혼동하지 않는다.

## 5. Magicraft식 상세 카드의 실제 정보 위계

공통 원칙은 이전 [마법·유물 툴팁 보고서 UI-2026-10-30-09](2026-10-30-spell-relic-tooltip-ui-research-proposal.md)를 따르되, **유물 보유창에서는 다음의 독립 정보가 중요**하다.

| 우선순위 | 표시 | 예시/정확성 |
|---|---|---|
| 1 | 아이콘·이름 | **금이 간 왕관** |
| 2 | 핵심 효과 | 주는 피해 **+30%**, 받는 피해 **+20%** |
| 3 | 발동 조건 | 상시 패시브인지/특정 행동 뒤 발동인지 |
| 4 | 예외·제외 조건 | 왕관: **보호막에 받는 피해도 증가** |
| 5 | 동적 상태 | 실제 카운터가 있는 유물만 추가 |
| 선택 | 짧은 설정/세계관 문구 | 실제 문구가 있을 때만 |

- **존재하지 않는 '유물 레벨 1/3', 희귀도, 강화 비용**은 카드에 표시하지 않는다.
- 숫자는 현재 코드에 근거해야 하며 일반적인 게임 수치/참고작 설명을 섞지 않는다.
- 유물 타입/등급을 장식 목적으로 새로 지어내지 않는다. 필요하면 '유물'이라는 통일된 중립 라벨이면 충분하다.
- 유물 효과가 동적으로 변한다면 스냅샷이 아닌 **현재 런 상태**에서 읽되, 과거 기록/도감에는 현재 상태를 과거 사실처럼 보여주지 않는다.

### 5.1 실제 유물 동적 상태

`scripts/relics.gd::tooltip()`는 현재 다음 정보를 제공한다.

| 유물 | 기존 동적 정보 | 표시 정책 |
|---|---|---|
| **욕심쟁이 저금통** | 현재 보유 마석에 따라 피해 **+0~20%** | 실제 현재 마석 기준. 도감/과거 실험에서 현재값 사용 금지 |
| **변덕쟁이 장갑** | 다음 복제까지 **남은 직접 시전 횟수** | 실제 런 카운터. 획득 UI에서 가상의 진행도로 표시하지 않음 |
| **영혼 솜옷** | 현재 보호막 **0~10**, 처치 누적 **0~10** | 현재 웨이브 상태. 웨이브 종료 시 초기화 사실 반영 |
| **도망쟁이 구두** | 내부적으로 활성시간/재사용 대기 상태 존재 | 현재 `tooltip()`은 타이머를 노출하지 않음. 표시하려면 별도 뷰 모델/계산 검증 필요 |
| **그 외 유물** | 주로 정적 효과 설명 | 불필요한 0/N 진행바나 충전 UI 만들지 않음 |

유물 HUD 업데이트가 `owned` 변경 여부만 검사해 아이콘을 재생성하는 구조여도, **실시간 툴팁 수치 갱신은 별도로 정확히 처리**해야 한다. 지속 호버 중 업데이트 정책을 실제 GUI에서 시험.

## 6. 강화 UI 범위 정리 — 현재는 '보유·설명'에 집중

**유물 자체 강화는 현재 구현되지 않았다.** `relics.gd`는 보유 ID와 유물별 효과·카운터를 갖지만 **동일 유물 +1/+2/레벨업·합성 강화 스키마가 없다**. `acquire()`도 중복을 막는다.

| 기능 | 현재 구현 여부 | 이 보고서 권고 |
|---|---|---|
| 유물 보유/호버 설명 | **있음** (글리프/기본 툴팁) | **표시 개선 핵심** |
| 유물 전체 창 | **있음** (3열 큰 카드) | **목록+선택 상세로 개편** |
| 유물 획득/제작 선택 | **있음** | 기존 구입·보상 시스템 그대로 |
| 일부 유물 현재 카운터 | **있음** | 상세 카드에 실제 동적 상태 표시 |
| 유물 중복 보유·합성 | **없음** | 새로운 기능으로 임의 추가 금지 |
| 유물 자체 강화·레벨·비용 | **없음** | **UI 버튼 만들지 않음** |
| 마법 +3/오브 성장 | **별도 존재** | 유물 강화로 잘못 표시하지 않음 |
| 희귀도·등급 | `tier=unassigned` | 색 등급 시스템 임의 도입 금지 |

향후 사용자 별도 요청으로 유물 강화가 추가되면, 그때 **강화 전후 효과·비용·레벨/상한·중복·저장 정책**을 새로 결정하고 Magicraft를 기능 기준으로 재조사한다. 현재 조사만으로 유물 강화의 구체 규칙은 확정하지 않는다.

## 7. 다른 화면과 일관성

- **획득 보상**: 유물 획득 전의 효과 카드는 '보유 유물 상세'와 **같은 효과 설명/아이콘 컴포넌트**를 재사용. 획득 선택 버튼은 보상 화면 소유.
- **제작대**: 유물 제작은 실제 가격/보유 여부만 표시하고, 선택시 동일한 상세 카드. 제작/보상 외의 임의 강화 버튼 금지.
- **발견 도감**: 획득한 유물만 상세 표시한다는 현재 발견 정책 유지. 해당 런에서 소유하지 않는 발견 유물과 **현재 보유 유물**의 구별 필요.
- **실험 기록**: 과거 런의 보유 유물 ID와 정의된 효과를 조회할 수 있으나, 당시의 장갑/솜옷/저금통 누적 동적 상태는 런 기록에 없으므로 **현재 런의 값으로 속이지 않는다**.
- **마법 툴팁**: UI-2026-10-30-09의 이름·아이콘·효과·조건·보충 설명 카드 문법 재사용.
- **전투 HUD**: [UI-HUD-2026-10-31-01 최신 확정 배치](2026-10-31-combat-hud-revised-approved-v1.md)를 우선한다. **유물은 오른쪽 상단 세로열**, 다른 최신 HUD 요소와 충돌 금지. 왼쪽 아래 구형 유물 영역은 사용하지 않는다.

## 8. 승인 후 구현 우선순위

1. **전투 HUD 보유 유물 표식 정돈**: glyph→시각적 아이콘, 개수/구분·호버/포커스.
2. **전투에서 유물 버튼의 실제 목적지 수정**: 유물 보유/상세가 열려야 함. 현행 `personal_tab` 재설정 버그 의심 경로의 실재 여부를 대표 클릭으로 검증하고, 전투 정지 여부는 사용자 정책에 맞춰 결정.
3. **보유 목록 재구성**: 3열 긴 카드 → 아이콘 그리드 + 선택한 유물 상세.
4. **정보 일관화**: 기존 `name/desc/note/detail/tooltip()`과 공통 툴팁 데이터 모델 통합.
5. **동적 상태 정확성**: 장갑/저금통/솜옷 등 현재 상태 표시는 실시간 정확성·이전 기록 분리.
6. **최종 아이콘·카툰 UI 마감**: 전체 UI 스킨에 맞춰 아트/라이선스 검토. 외부 유물 아이콘 복제·구매는 별도 승인.

### 8.1 게임에서 검증할 관찰 가능한 완료 기준 (이번에는 미실시)

- 전투 HUD `유물 N`이 실제 `relics.owned` 수와 일치, 0개/1개/최대12개 및 유물 추가 때 중복 표기 없음.
- 전투 중 HUD 유물 버튼 클릭이 **실제 보유창/유물 상세를 열며 가방으로 자동 변경되지 않음**.
- 전투 중 유물창에서 **정지/비정지 정책을 합의대로 유지**하고, 닫을 때 전투·보상 선택 상태/입력을 정확히 복귀. Tab/ESC의 기존 순서 보존.
- 각 아이콘 선택/호버/키보드 포커스로 이름·효과·중요 예외를 확인할 수 있고 툴팁이 화면 경계 밖으로 잘리지 않음.
- 유물 선택 목록이 소유 데이터 그대로이며, 도감의 '발견했지만 현재 미보유'와 구별.
- 유물 중복 획득·강화 버튼이 없는 현재 게임 계약 유지.
- 장갑의 다음 복제 횟수, 저금통의 현재 마석 연동 보너스, 솜옷의 보호막·처치 누적이 실제 값과 같고 변화 후 갱신.
- 웨이브 종료·재시작·타이틀 복귀·시험 발사·지난 실험 기록에서 카운터가 다른 런으로 새지 않음.
- `1280×720`, `1600×900`, `1920×1080`에서 기존 좌측 아래 HUD/가방/보상 버튼·시계와 겹침 없음; 아이콘이 12개일 때도 입력·가독성 유지.
- 새 유물 제작과 보상 획득의 실제 가격·인벤토리/도감·모달 흐름을 변경하지 않음.
- 실제 씬 실행/컨트롤러·키보드 탐색/화면 스크린샷을 확인해야 **UI 구현 검증 완료**로 인정. 코드 정적 열람만으로 완료 선언하지 않음.

## 9. 사용자 검토가 필요한 사항

- 전투 유물 보유창을 **전투 비정지형으로 볼지** 또는 **정지형으로 볼지**: 현재 구현은 경로에 따라 정책이 섞일 수 있어 단순 디자인 변경이 아니라 동작 결정이 필요.
- **오른쪽 상단 세로 유물 HUD**에서 아이콘 개수가 많아질 때 몇 개부터 스크롤/축약할지. 위치 자체는 이미 승인됨.
- 아이콘 클릭은 간단한 고정 카드, 전체 창은 `유물 N` 버튼으로 열도록 나눌지.
- 정식 유물 그림을 새로 제작할지/기존 보유 아이콘을 변형해 쓸지; 원작 에셋 복제 금지.
- 신규 유물 강화 기능은 **현행 UI 조사에서 미확정**: 게임 규칙 추가를 원하면 별도 기획/승인.
