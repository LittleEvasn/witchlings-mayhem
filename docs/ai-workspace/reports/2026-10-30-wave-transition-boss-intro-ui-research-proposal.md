## 1. 핵심 결론

**일반 웨이브는 짧고 가볍게, 위험 이벤트는 실전 가시성을 우선해, 최종 보스에서만 강한 등장 연출**을 권고한다.

- **일반 실습 시작:** 짧은 \`WAVE 03 / 05\`와 실습 이름/위험 요약. 전투는 멈추지 않는다.
- **실습 완료:** 짧은 성공 표시 및 실제 회복/획득 정보. 기존 제작대 진입·보상 흐름을 그대로 유지.
- **정예·무리/포위:** 간결한 경고, 실제 생성된 적 위치·진입 방향과 맞는 신호. 전투 비정지.
- **최종 보스:** 실제 소환이 확인되면 **짧은 \`FINAL BOSS — 끝없는 모범답안\` 소개 카드/실루엣**을 내보내고 이미 구현된 보스 체력바에 시선을 연결. 기본안은 비정지.
- 별도 긴 컷신/매분 웨이브 배너/보상 완료용 필수 확인 페이지는 추가하지 않는다.

이 구분은 **이미 구현된 5×6분 진행과 전투↔제작 전환**을 유지하면서 연출의 강약을 조절하는 것이다.

### 2.2 현행 알림

\`game.gd\`의 \`announce(message, duration)\`는 \`notice\`라는 **문자열 1개**와 \`notice_left\`만 갱신한다. 새 안내가 오면 이전 안내를 대체한다. \`interface.gd\`의 \`notice_label\`은 HUD의 단일 텍스트를 표시한다.

- 시작 전투: 조작 안내/루미 대사 약 5초.
- 다음 실습 시작: \`RunContent.chapter(wave).lumi\` 5초.
- 최종 보스 단계: \`30분 생존! 마지막 폭주를 멈추면 승리야.\` 6초.
- 박쥐 횡단: \`박쥐 떼가 전장을 가로질러!\` 2초.
- 포위: \`실패작이 둘러쌌어! 틈으로 빠져나가거나 뚫어봐.\` 2초.
- 보스는 이름 \`끝없는 모범답안\` 및 생존 시 체력바가 이미 등장한다.

**문제 가설:** 웨이브 소개, 보스 등장, 정예 위험, 평범한 조작 안내를 같은 텍스트 통로에 넣으면 중복·덮어쓰기 때문에 중요한 사건이 묻힐 수 있다. 실제 미관/사용성은 실행 테스트가 필요하다.

### 2.3 UI와 전투의 정확성 관련 주의

- \`begin_final_boss()\`는 \`final_boss_started=true\` 이후 \`_ensure_boss()\`를 호출하고 반환 성공을 확인하지 않은 채 \`announce(...)\`한다. \`_ensure_boss()\`는 실패 시 후속 업데이트에서 재시도될 수 있다. 따라서 새 \`등장!\` 연출은 **실제 보스 인스턴스 생성 성공을 확인한 뒤** 트리거해야 한다. 30분 도달 경고와 \`보스 실제 등장\`은 별개의 사건이다.
- \`waves.gd\`의 \`start_event()\`는 \`elite\`, \`crossing\`, \`ring\` 등을 실행한다. 일부 이벤트는 \`spawn_enemy(...)\`의 결과가 \`null\`일 수 있고, 박쥐/포위 안내는 해당 호출 루프 뒤에 출력될 수 있다. **요청한 적 수 = 실제 생성 성공 수**로 취급하지 않는다.
- 특히 앞선 [\`docs/PROJECT-HANDOFF.md\`](../../PROJECT-HANDOFF.md)의 2026-10-30 보류 항목은 박쥐/포위의 실제 전투 압박·틈/역할을 미검증으로 기록하고 있다. **UI만 근사하게 만든 후 이벤트 자체도 검증됐다고 주장하면 안 된다.**
- \`waves.gd\`의 \`title\`(예: \`돌진 주의\`)과 \`run_content.gd\`의 \`CHAPTERS.title\`(예: \`빠뜨린 안전장치\`)은 **다른 제목 체계**이다. 실습 타이틀의 기준과 부제 조합을 확정해야 화면과 대사/작업대의 이름이 충돌하지 않는다.
- 사용자가 이전에 임시 BGM을 제거했다. \`set_music("boss")\` 호출이 남아 있어도 **보스 BGM이 실제 재생된다고 단정하지 말고**, 새로운 BGM을 임의로 추가하지 않는다.

## 4. 권장 네 가지 연출 유형

### 4.1 A. 일반 웨이브 시작 — 작고 빠른 배너

\`\`\`text
          WAVE 03 / 05
             돌진 주의
        추격 · 긴 돌진 · 사격 적
         (전투는 계속 진행)
\`\`\`

- 기존 \`Waves.config(wave).title\`과 \`hint\` 활용 가능.
- **추천 길이: 1~1.5초 (제안, 실제 검증 전)**. 전장을 가리지 않는 얇은 상단/중앙 상단 배너.
- 첫 웨이브의 이동·조준·회피 안내, 루미의 장 대사가 꼭 필요한 경우 **우선순위와 동시 표시 규칙**을 지정한다.
- 준비를 마치고 출발하는 시점에 표시. 준비 중에는 기존 작업대의 다음 실습 예고가 우선.
- 비정지 기본안. 입력을 막거나 타이머를 추가로 지연하지 않는다.

### 4.2 B. 일반 웨이브 완료 — 짧은 성취 표시

\`\`\`text
             실습 완료!
              2 / 5
       [실제 회복량] [실제 정산]
          마법을 정비할 시간
          ↓ 기존 제작대 진입
\`\`\`

- **추천 방식:** 약한 성공음/빛/배너. **별도 완료 확인 버튼 없음**. 전투 종료가 완전히 정리된 상태에서 제작대 UI에 연결한다.
- 현재 \`complete_wave()\`는 적·탄환·이펙트 정리 후 \`_enter_preparation()\`으로 즉시 진입한다. 따라서 완료 배너를 실제로 보이게 하려면 **제작 화면 위에 짧게 표시**하거나, UI 표현에 한정된 전환 계층을 설계해야 한다. 단순히 전투 전경에 글씨를 넣은 뒤 바로 모달이 뜨면 가려질 수 있다.
- 회복·마석 정산은 **실제 수령한 값**에만 근거하며, 고정값으로 허위 지급하지 않는다.
- 기존 보물상자/레벨업/유물 보상 흐름에 새로운 필수 화면을 추가하거나 선택 순서를 바꾸지 않는다.
- 웨이브 완료와 런 승리(보스 처치)는 별도. **승패 결과 연출과 혼동 금지**.

### 4.3 C. 정예 및 위험 이벤트 — 전투 비정지 안내

\`\`\`text
      ! 정예 실패작 출현 !
       (짧은 상단/측면 안내)
      ← 실제 박쥐 진입 방향
      ○ 실제 포위 구역 경고
\`\`\`

- 경고는 이벤트 유형에 따라 강도를 차등화: **정예·포위·횡단**은 강한 주의, 평범한 적 추가는 알림 생략.
- **실제 이벤트 생성 성공**에 근거한 표시. 무리의 생성 개체 수/중심/진행 방향/생존 기간 등 실제 물체 상태와 경고 정보를 연결한다.
- 박쥐 방향 표시는 최초 생성 방향뿐 아니라 진행 경로가 플레이어 시야에 들어오는 방식까지 고려.
- 포위는 실제 생성된 둘레와 탈출 가능 지점을 가리는 화살표가 없어야 한다. **지형상의 실제 빈틈/파괴 가능성**과 UI 안내가 충돌해서는 안 된다.
- 보상 UI·가방·오브 편집이 화면 위에 있을 때 알림 우선순위와 위치를 따로 확인한다.
- 전투를 정지하지 않고 긴 \`WARNING\` 오버레이로 가리는 것을 지양.
- 기존 게임의 이벤트 생성/물리 동작에 문제가 있으면 **연출 완료와 이벤트 자체 정상 동작 검증은 별개**로 기록.

### 4.4 D. 최종 보스 — 가장 강한 소개 연출

\`\`\`text
       !  FINAL BOSS  !
         끝없는 모범답안
      [보스 실루엣/전용 이미지]
       폭주한 마법 조수가 나타났다!
                 ↓
      [기존 보스명 + 보스 HP바]
                 ↓
          정상 전투 지속
\`\`\`

- 30분 도달: 최종보스 **시작 조건**. **실제 보스 엔티티가 생성된 것이 확인된 뒤** \`등장\` 카드 확정.
- 등장 카드에는 보스명·실루엣·짧은 경고를 강조. 현재 별도 보스 이미지 준비 여부가 확인되지 않으므로 기존 아트/실루엣으로 시작할지 **별도 아트 제작이 필요한지 미정**.
- **기본 제안: 전투 비정지**, 노출은 짧게(예: 1.5~2.5초를 시안 비교 대상으로만 제안). 커다란 카드가 플레이어와 적 탄환을 장시간 가리지 않게 위치·투명도를 검토.
- HP바는 현재 \`interface.gd\`의 \`boss_bar\`/\`boss_label\`을 재사용하고, 등장 직후 작은 강조 애니메이션을 줄 수 있다.
- 보스 생성 실패/후속 재시도/리스폰에서 **'처음 등장' 연출이 매번 중복 재생되지 않도록** 신호/플래그를 설계한다. 연출 처리로 기존 보스 재시도·실제 전투 시간을 고치지 않는다.
- 현재 효과음은 기존 짧은 UI·피격 계열을 사용하거나 새 사운드 정책을 별도 승인. **임시 BGM 자동 추가 금지**.

## 5. 공통 UI 정책 — 게임을 가리지 않고 우선순위 충돌 방지

### 5.1 알림 통로 분리 제안

| 층 | 담당 | 예시 | 충돌 시 |
|---|---|---|---|
| **일상 안내** | 기존 \`notice_label\` | 조작법, 루미 한마디, 마석 정보 | 높은 경고보다 우선순위 낮음 |
| **웨이브 배너** | 짧은 전환 레이어 | \`WAVE 3/5\`, 실습 완료 | 준비/전투 상태에 따라 표시 |
| **실시간 위협 경고** | 전투 위험 경고 레이어 | 정예, 박쥐, 포위 | 겹칠 경우 대기/통합/상위 경고 우선 |
| **보스 등장** | 최상위 1회 소개 레이어 | \`끝없는 모범답안\` | 짧고 강하게, 다른 경고와 중복 남발 금지 |
| **지속 HUD** | 기존 HUD | 보스 HP바, 남은 시간 | 위험 알림과 무관하게 계속 정확하게 표시 |

- \`announce()\`를 무작정 여러 줄 쌓거나 매 새 이벤트에서 덮어쓰지 않도록 **소유권/상태 우선순위** 설계 필요.
- 위치는 HUD 시계·오브 가방·보상 3~4택·보스 HP바·적 텔레그래프와 겹치지 않도록.
- 애니메이션은 밝기/위치/투명도 중심으로 짧게. 플레이어 시야를 막는 전면 흰 플래시/반복 흔들림 지양.
- 소리를 끈 설정, 피해 숫자·보상 옵션, ESC 일시정지/설정, 전투 중 가방 편집과 충돌하지 않아야 한다.
- 텍스트/아이콘 대비 및 가독성은 밝은/어두운 전투 배경 둘 다 확인.
- 실제 연출 시간이 정해지면 **타이머/적 이동/공격/피격 입력에 어떤 영향이 있는지** 명확히 시험한다.

## 6. 구현 순서 권고 — 사용자 별도 승인 이후

| 우선순위 | 작업 제안 | 기대 효과 |
|---|---|---|
| **P1** | 최종 보스 실제 생성 성공과 연동한 **소개 카드 + 기존 HP바 하이라이트** | 30분 도달의 최종 전투 성취감 |
| **P2** | 정예·박쥐·포위의 **실제 생성 사실과 방향/구역**을 반영한 경고 | 전투 중 위험 인지 및 기존 허위 안내 감소 |
| **P3** | 웨이브 완료 → 기존 제작대의 **짧은 완료 표시** | 실습을 마친 감각·준비 동선 강화 |
| **P4** | 웨이브 진입 시 **짧은 시작 배너** | 5개 큰 장 구분과 스토리 제목 연결 |
| **P5** | 캐릭터/스킨/효과음/애니메이션의 최종 미술 마감 | 전체 게임 UI 톤 통일 |

위 순서에서 **P2의 이벤트 실제 발생/움직임/피해 검증 문제는 UI 개편만으로 해결할 수 없다.** 기존 오류를 발견하면 이벤트 로직 수정을 자동 수행하지 말고 독립 이슈로 보고·승인 받아야 한다.

## 7. 구현 완료 기준과 회귀 검증 계획 (이번에는 미실시)

1. 첫 전투 및 웨이브 2~5 시작 시 **실제 웨이브 번호/제목**이 정확하게 뜨고, 준비 화면과 중복/불일치 없이 사라짐.
2. \`RunContent.CHAPTERS.title\`와 \`Waves.WAVES.title\`의 실제 채택 표시 규칙을 확정한 뒤 시안대로 일관 적용.
3. 1~4 웨이브 정상 완료 때만 완료 안내가 뜨고, 제작대·보상·적/투사체 정리·회복·마석/저장 값·재개 흐름이 이전과 일치.
4. 보스 처치로 끝나는 승리 경로는 **일반 웨이브 완료를 오표시하지 않음**.
5. 정예/박쥐/포위 이벤트를 **생성 요청/부분 생성/0개 생성/성공**으로 나누어 각각 경고 조건이 실제와 일치함.
6. 횡단 경고는 실제 무리의 위치·이동 방향, 포위 경고는 실제 생긴 틈/실제 공격 가능 영역과 일치함. 생성 숫자나 배치 그림만으로 통과 처리하지 않음.
7. 보스 30분 조건 도달 시 소환 성공/실패→재시도 경로에서 **실제 스폰 확인 전 등장 확정 연출 없음**, 성공 시 소개 정확히 1번.
8. 보스 소개가 사라져도 기존 \`boss_bar\`/HP 수치/이름과 보스 공격·피격/승리 조건이 정상.
9. 등장 카드/배너가 적·탄막·피격 예고를 가리지 않으며 전투 비정지 상태의 이동·회피·조합 편집 입력이 정상.
10. 보상 중 정지/ESC/타이틀 설정/전투 개인창·훈련장 복귀와 알림 레이어 입력이 충돌하지 않음.
11. \`1280×720\`, \`1600×900\`, \`1920×1080\` 실제 창 렌더에서 제목과 HP바, 시계, 가방, 보상 카드 겹침/잘림을 확인.
12. 연출 수치(제안 1~2.5초), VFX/화면 흔들림, 사운드 On/Off를 각각 실제 게임에서 비교 검증.
13. **코드 열람/자동 검사/Godot 실동작/실렌더/사용자 미관**을 각각 다른 증거 수준으로 기록하며 일부 성공을 전체 완료로 확대하지 않음.

## 8. 사용자 검토가 필요한 미확정 결정

- 최종 보스 인트로를 **짧은 비정지 카드**로 시작할지, 특정 시점에 한정된 짧은 정지형 연출까지 비교할지.
- 최종 보스 전용 캐릭터 이미지/실루엣의 새 에셋이 필요한지, 기존 보스 아트를 활용할지.
- 웨이브 시작 제목 기준을 \`Waves.title\` / \`RunContent.title\` 중 어느 쪽으로 두고 부제를 어떻게 만들지.
- 웨이브 완료 배너를 **제작대 위에 잠깐 겹치게** 할지, 별도 전환 레이어로 처리할지.
- 정예·박쥐·포위 경고를 **위치 기반 화살표/원형 가이드**까지 확장할지.
- 기존 사운드만으로 구현할지, 나중에 정식 UI 효과음만 따로 준비할지.
- 실제 이벤트 로직 미해결 문제가 남아 있어, **연출 구현과 사건 정상 동작의 완료 조건을 구분**해야 한다.

- **미수행:** 게임 코드/보스 AI/이벤트 생성기 수정, Godot 실행·화면/입력 검증, 다른 게임 최신판 직접 플레이, 연출 애니메이션·실루엣·일러스트·사운드 제작, 원작 스크린샷·리소스의 저장소 반입, 새로운 BGM 추가.
