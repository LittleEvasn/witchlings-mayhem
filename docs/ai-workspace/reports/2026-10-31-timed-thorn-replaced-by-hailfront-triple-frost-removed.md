## 1. 기존 시한 가시꽃의 삭제와 교체

| 항목 | 기존 코드(폐기 예정) | 최신 사용자 결정 |
|---|---|---|
| 완성 합성명 | **시한 가시꽃** | **빙설 전선**(제안 이름, 우박 구름 컨셉 채택) |
| 합성 ID | `timed_thorn` | **신규 내부 ID 필요**, 기존 ID를 즉시 재활용하지 말 것. 저장·도감 이관 정책 미확정 |
| 조합 | `thorn + timer` (가시꽃 덫 + 시간 트리거) | **`element_ice + fall` (빙결 + 낙하)** |
| 구형 고유 효과 | 적 접근과 관계없이 가시파 2회·마지막 폭발 | **느리게 이동하는 구름이 아래에 우박을 지속적으로 떨어뜨려 실제 피해와 냉기를 부여** |
| 공격체 역할 | 고정된 가시 덫 | **전진하는 기상 효과 / 이동형 다중 착탄 영역 공격** |
| 개발 결정 | `timed_thorn` 구형 특례 삭제 예정 | 후속 우박 구름을 **별도 공격체로 구현**. 구형 가시꽃 연출/코드 재활용 금지 |

### 왜 기존 조합을 폐기하나?

- 기존 `timer`는 **0.6초 후 후속 주문 1회**였으나, 최신 승인 방향은 **마법공예 휘감기(Entangle 3204)** 참고의 **후속 마법 B가 부모 A 주위를 공전**하는 연결로 변경됐다. [사용자 최신 확정 결정](../decisions/2026-10-31-correction-trail-chain-timer-entangle.md).
- 따라서 구형 시간 트리거를 전제로 만든 `thorn + timer`의 **시한 가시꽃**은 최신 연결 개편과 정체성이 어긋나므로 **삭제한다.**
- 삭제는 **시한 가시꽃 합성만**을 뜻한다. **기본 가시꽃(`thorn`)**, 새로 확정한 **작열 가시꽃(`thorn+element_fire`)**, **연결 `timer`의 휘감기 개편** 자체를 삭제하지 않는다. `clock_satellite` 등 다른 `timer` 합성은 사용자 지시 없이 함께 삭제하지 않는다.

## 2. 빙결 + 낙하 — 느린 우박 구름

**플레이에서 보여야 할 최소한의 고유 행동:**

1. **구름 생성:** 마녀가 조준한 방향에 차갑고 큰 구름이 나타난다. 생성 지점, 전방 오프셋, 덮는 범위는 세부 조정.
2. **느린 전진:** 구름이 **처음 지정된 방향으로 서서히 진행**한다. 특정 적 위치에 고정된 단발 낙하가 아니며, 계속 이동해 **우박 낙하 영역 자체가 바뀐다**.
3. **실제 우박:** 구름이 움직이는 동안 **아래쪽으로 여러 개 우박이 떨어진다**. 우박이 착탄할 위치가 보여야 하고 실제 낙하/피해 지점이 구름의 그때그때 위치와 일치해야 한다. 단순 광역 냉기 장판을 우박 그래픽으로 가리는 것으로 대체하면 안 된다.
4. **착탄 판정:** 실제 우박이 지면에 닿으면 **범위 피해와 냉기 누적**을 준다. 여러 번 맞은 적은 기존 냉기·둔화·동결 시스템으로 연결된다.
5. **전진하며 구역을 덮음:** 구름이 이동함에 따라 우박 피해 범위가 전진하고 이미 지나간 뒤의 구역은 더 이상 같은 구름에서 낙하가 발생하지 않는다. (얼음 잔여 장판은 사용자 미확정)
6. **종료:** 구름의 유지시간이 끝나면 추가 우박 생성을 중단하고 정상적으로 소멸한다. 이미 예고/낙하 중인 우박의 착탄·취소 규칙은 별도 구현 계약.

- **비교:** `thunder`(벼락)은 지점별 낙뢰, `meteor`(운석)은 착탄 후 충격파, `ember_path`(잔불 발자국)은 지나간 위치에 장판. **빙설 전선은 전진하는 구름이 이동 중 여러 번 우박을 쏟아내는 공격**이므로 다르다.
- **화상/냉기 원소 반응**, 냉기 중첩의 정확한 배율/동결 요구량은 기존 공통 규칙을 우선한다. 우박 하나가 냉기 전체 시스템을 무시하는 고유 즉시 동결을 갖는다고 주장하지 않는다.
- **구름 자체의 접촉 피해 없음**, **적 추적 없음**은 직전 추천안을 이어받은 방향이며, 구현 세부 최종 승인은 별도 정한다. **구체 수치(예: 4~5초, 0.3~0.4초 간격)는 제안값일 뿐 확정 아님.**
- 결과는 **`element_ice` 보조와 `fall` 보조를 합성한 뒤 생성되는 독립 공격**이다. 현재 `frost`(향후 얼음검)+`fall`과 혼동하거나, 구형 `frost` 부채꼴 코드로 우박을 흉내 내지 않는다. `element_ice`와 `fall`은 모두 `modifier`이므로 현행 카탈로그에 단순 행 추가만으로 이 공격이 자동 구현되지는 않는다. 합성 결과의 `kind=attack`/실행 프로필·발사/예약/상태/피해 처리·도감/아이콘 등을 새로 설계해야 한다.

### 제안(미확정) 수치 및 최적화

- 구름 수명 약 **4~5초**, 느린 선속도, **0.3~0.4초 간격**으로 우박 여러 개 낙하. **사용자 승인 수치 아님**.
- 발사체 상한/낙하 예약 큐/다수 구름 동시 생성·4오브 상황을 고려해 우박의 개별 충돌/원소 프로크·시각 예고를 합리적으로 설계한다. 단순 **0.3초마다 전체 범위에 즉시 AoE**를 넣어 “우박 낙하 구현 완료”라고 주장하지 않는다.
- 구름 위치의 시간 경과 이동, 각 우박의 **예고→낙하→착탄**을 별도 상태/좌표로 관리하고, 높은 부하에서 실제 착탄 누락을 숨기지 않는다.

## 3. 빙정 삼중파 — 대체 없이 삭제

- **사용자 최신 지시:** “빙정 삼중파도 삭제로 가고.”
- 기존 완성 합성 `triple_frost`, `frost + fan`(서리숨결/향후 얼음검 + 갈래)을 **기획 목록에서 삭제**한다.
- 과거 `triple_frost`의 **냉기 삼중 부채·겹치는 끝점에서 빙정 폭발** 효과는 폐기한다. 원래도 얼음검(`frost`) 개편으로 부채꼴 전제가 맞지 않아 별도 재설계가 필요했던 대상이다.
- **이번 삭제에 대체 합성을 자동 배정하지 않는다.** 이후 사용자와 별도 조합을 설계하기 전까지 `frost + fan` 조합으로 완성 합성이 나타나지 않도록 구현해야 한다.
- **기본 `frost`→얼음검**, **기본 `fan` 갈래**는 그대로 유지한다. **기존 완성 `cold_flame`(`frost + element_fire`)**은 삭제 지시가 아니므로 별도 개편 과제로 남긴다.
- **합성 수 기록:** 과거 **완성 합성 30종**을 기준으로, 시한 가시꽃 1종은 빙설 전선 1종으로 **교체**, 빙정 삼중파는 **대체 없이 1종 삭제**하므로 **신규 기획 목표는 29종(1개 공석)**. 이는 **코드상의 현재 30종이 즉시 29종으로 변했다는 뜻이 아니다.** 30종 고정에 맞추려고 임의 조합을 1개 추가하지 않는다.

## 4. 현재 코드와 구현 변경 범위(실제 미변경)

- [`scripts/magic_catalog.gd`](https://github.com/LittleEvasn/witchlings-mayhem/blob/main/scripts/magic_catalog.gd): 현재 `timed_thorn = thorn + timer`; `triple_frost = frost + fan`. 둘 다 구형 합성 데이터가 남아 있다. 다음 코드 구현 시 각각 제거/신규 교체하고, 빈 슬롯을 명시적으로 남겨야 한다.
- [`scripts/magic_extensions.gd`](https://github.com/LittleEvasn/witchlings-mayhem/blob/main/scripts/magic_extensions.gd): `timed_thorn` `attach()`의 `thorn_wave` 예약(3개의 스케줄 중 가시파 2회+마지막 폭발), `triple_frost` `finish()`의 3방향 후속 공격은 제거 대상. **해당 예약 처리 자체가 다른 주문에서 쓰이는지 검증한 후 전용 분기만 정리**, 공용 루틴을 무단 삭제하지 않는다.
- [`scripts/spell_progression.gd`](https://github.com/LittleEvasn/witchlings-mayhem/blob/main/scripts/spell_progression.gd): 합성은 `FUSIONS`를 순회해 부모 쌍을 찾고, 데이터에 있는 완성 합성은 런타임/도감/제작에 영향을 준다. 새 보조+보조 조합의 공격형 합성 타입·구현을 따로 처리해야 한다.
- [`scripts/magic_extensions.gd`](https://github.com/LittleEvasn/witchlings-mayhem/blob/main/scripts/magic_extensions.gd)의 기존 `fall` 예약 동작은 현재 별도 확정 낙하 정책(착지 전 무피해)과 호환되도록 우박에 맞게 설계해야 한다.
- 기존 세이브/런 기록/도감·획득 후보/이미 발견한 합성 ID/훈련장과 마법 60종 고정 테스트에서 **삭제된 두 ID의 유령 참조**가 남는지 확인한다. 내부 ID `timed_thorn`을 우박 구름에 그대로 덮어써 과거 플레이 기록이 우박으로 재해석되지 않도록 이관 정책 필요.
- **시간 트리거(→휘감기식 후속 공전)의 승인**은 유지한다. `clock_satellite`를 포함한 다른 연결 합성 영향 검토는 별도이며 이번 문서에서 함께 삭제하지 않는다.

## 5. 사용자 요구 기준 완료·검증 항목(향후 구현 시)

1. **기획 목록:** 시한 가시꽃·빙정 삼중파가 정상적인 신규 합성 보상/제작/도감에서 제외되고, `element_ice + fall`만으로 **빙설 전선**이 등장한다. `thorn + timer`/ `frost + fan`은 더 이상 두 폐기 합성을 생성하지 않는다.
2. **빙설 전선의 실제 작동:** 구름이 느리게 **직선 전진**, 우박이 시간 간격으로 **구름 밑으로 떨어져 충돌 피해/냉기 축적**. 적 0/1/10명, 고정·이동 대상, 구름 통과 전후, 보스/엘리트에 대해 실측한다. 단순 냉기장판 재색칠은 불합격.
3. **동결과의 연결:** 실제 반복 우박 피격으로 둔화→동결, 중복 원소 적용/상쇄·기존 화염/빙결 반응 예외를 확인한다.
4. **상한/종료:** 다수 우박/구름, 우박 비행 중 구름 만료, 맵 경계, 4오브 300적, 큰 `delta`, 전투 종료/사망·재시작에서 예약·개체 유령/무한 누적 없음.
5. **다른 결정 보존:** 작열 가시꽃(`thorn + element_fire`)의 새끼 씨앗 번식, 기본 가시꽃의 굴림 후 원형 전개, `timer`→휘감기식 후속 공전, `frost`→얼음검, 다른 낙하/빙결 조합을 임의 취소/수정하지 않는다.
6. **검증 수준 분리:** 새 설계 문서·원격 코드 읽기(이번 수행) / Godot 구문 / 시각적 구름·우박 좌표 / 실제 충돌·피해·냉기 / 연계·성능 / 게임 체감(미수행)을 개별 보고.
