## 1. 통합 목적 및 전제

**시각 콘셉트:** 마법 실습의 우당탕한 코미디를 담되, 인터페이스는 깔끔하고 읽기 쉬운 **2D 카툰·둥근 패널·크림/라벤더**로 통일한다. 짙은 재질감(금속/나무/가죽), 3D풍 과잉 장식, 큰 빈 패널을 지양한다.

**플레이 원칙:**
1. **전투는 비운다.** 생존 시간·HP·현재 오브만 우선 읽히게 하고 시전/회피 공간을 가리지 않는다.
2. **조합에서는 관계를 보인다.** 상품/보유품/슬롯/강화 전후/상쇄·비작동을 실제 데이터로 보여준다.
3. **보상은 선택을 강조한다.** 카드 3~4장과 상자 결과가 중심이 되되, 조합 편집 흐름을 보존한다.
4. **축하는 차등화한다.** 웨이브 시작은 작게, 보스·상자 잭팟·최초 완성 합성은 강하게.
5. **다른 게임의 원리만 참고한다.** 외부 원작 아트·사운드·게임 규칙의 복제·반입이 아니다.
6. **지금 없는 기능은 UI에 있는 척하지 않는다.** 유물 강화·캐릭터 4인 플레이·과거 런 DPS/날짜 등은 별도 구현 전 미지원.

## 4. 전투 HUD / 가방 / 보상 — 상태별 배치

### 4.1 전투 중 HUD (UI-01을 전역 기준으로 정리)

**참고:** Vampire Survivors의 생존 시간 중심, Brotato의 전투 시야, Slay the Spire의 유물 아이콘.

| 항목 | 제안 위치 | 실제 현재와의 관계 |
|---|---|---|
| 시간·다음 제작 휴식 | **화면 상단 중앙** | 현재 일반 전투에서는 아래 중앙. **위치 변경은 제안** |
| HP·보호막·XP·마석 | **오른쪽 아래** | 기존 코드·[UI-LAYOUT-REVISION](../../UI-LAYOUT-REVISION-v1.md) 유지/축약 |
| 유물 작은 아이콘 | **왼쪽 아래** | 기존 코드·[UI-11](2026-10-30-owned-relics-details-ui-research-proposal.md) 유지 |
| 가방 Tab 버튼 | 화면 상단의 안전 영역 | 가방 펼침·타이머와 겹치지 않아야 함 |
| 오브 1~4 요약 | 왼쪽 세로 축약 표시 | 실제 오브와 슬롯 수, 현재 사용 상태 일치 |
| 보스 HP바 | 상단 타이머 아래 독립 영역 | `interface.gd`의 기존 HP바를 재사용 |
| 회피/보조 조작 | 우하단 상태와 간섭 없는 작은 영역 | 실제 쿨다운에 근거 |

**일반 가방 편집:** 상단 **연속 가로 가방** + 오브 1~4, 각 실제 6~8칸, 스크롤/드래그/우클릭/되돌리기. 일반 Tab은 비정지. **가방 확장 중 상단 시간과 겹치는 충돌을 해결**하기 위해 작은 시계를 가방 헤더로 옮기는 방안을 제안하지만 시안 승인 전 확정하지 않는다.

### 4.2 보상 3~4택

**참고:** Brotato의 보상 비교, Vampire Survivors의 빠른 레벨업 선택.

```text
[ 레벨 N · 하나를 골라요 ]
     [  세로 카드  ]  [  세로 카드  ]  [  세로 카드  ]  ([완성 합성])
                ↕ 선택 화면 ↔ 가방/오브 편집 상태
            [미수령 보상] [명시적 전투 재개]
```

- 기존 카드 **280×398**과 3장/4장 중앙 배치를 시안 출발점으로 삼는다.
- **보상 선택과 보상 후 편집은 정지**. 마지막 보상을 받기 전 재개 버튼은 비활성.
- 가방·오브 편집으로 돌아가도 실제 후보/획득 상태를 바꾸거나 카드 내용을 다시 뽑지 않는다.
- 새로 얻은 마법은 **가방에만**, 자동 장착 금지.
- **보상 선택할 때는 카드 중심, 편집할 때는 오브·가방 중심**. 두 패널을 동시에 화면 전체에 크게 펼쳐 전투를 가리지 않는다.

### 4.3 보물상자

**참고:** Vampire Survivors의 보물상자 개봉 리듬과 1/3/5 등급별 차등 기대감.

| 보상 결과 | 추천 시각 강도 |
|---|---|
| 1개 | 짧은 개봉과 단일 결과 |
| 3개 | 빛·연출과 결과 순차 공개 |
| 5개 | 가장 강한 잭팟·보상 강조 |

기존 **자동 지급 규칙·개수·마석·무료 합성·보상 스테이지**는 그대로. 연출 스킵/화면 닫기/중복 입력 시 지급 결과가 달라지지 않아야 한다. 첫 발견은 상자 결과와 **중복 축하하지 않도록 결합하거나 대기**한다.

## 5. 상점·제작·합성 (UI-05)

```text
┌─────────────── 마녀의 작업대 ───────────────┐
│ 오브1 오브2 오브3 오브4       마석·현재 상태 │
│       [선택 오브 실제 마법 슬롯]            │
├─────────────────────┬──────────────────────┤
│ 마법제작/합성/성장   │ 선택 아이템 상세      │
│ [상품명·가격·아이콘] │ [아이콘/효과/조건]    │
│ [상품명·가격·아이콘] │ [현재→강화 후 비교]   │
│ [제작안 재구성]      │ [구매/제작/장착]      │
├─────────────────────┴──────────────────────┤
│   현재 보유 가방: 연속 가로 슬롯·스크롤     │
│ [되돌리기]     [시험 발사]     [준비 완료] │
└────────────────────────────────────────────┘
```

- **전체 4오브를 항상 같은 크기로 펼치지 않는다.** 현재 선택 오브만 크게, 나머지는 요약 버튼으로 전환해 과밀 방지.
- 구매 가능한 마법/유물, 실제 인벤, 실제 오브를 **같은 작업 맥락**에 배치한다.
- 상품 선택은 정보 표시; 구매 버튼에서만 비용 발생. 구매 후 실제 가방 반영 및 자동 장착 없음.
- 합성은 **실제 +3 재료 보유/수량·조건**과 결과를 비교. 전투 로직·강화 한도·오브 최대4 개념 불변.
- 보조/연결 마법의 영향 슬롯은 실제 컴파일·진단 기준으로만 강조. 노랑/빨강 경고는 확정된 계약 준수.
- [현행 `crafting_workbench.gd`](../../../scripts/crafting_workbench.gd)의 큰 우측 패널을 전면 재배치할지는 실물 목업을 보고 결정; 이 스케치는 **픽셀 레이아웃 확정이 아님**.

## 6. 마법·유물 툴팁 및 보유 UI (UI-09/11)

### 6.1 공통 정보 카드 — Magicraft형

**참고 요소:** Magicraft의 제목·아이콘·역할/단계·효과·조건·보충 설명 분리. Brotato의 줄 단위 수치 비교. Backpack Battles의 관계 강조.

```text
┌─────────────────────────────┐
│ [큰 아이콘] 이름            │
│ 역할 · 강화 +N / 유물       │
├─────────────────────────────┤
│ 현재 핵심 효과와 실제 수치  │
├─────────────────────────────┤
│ 발동 조건/적용 대상/예외    │
├─────────────────────────────┤
│ 선택적: 강화 비교·현재 상태│
└─────────────────────────────┘
```

- 공격: 타격 방식/피해. 보조: 실제 수정 효과/대상. 연결: 앞 사건→뒤 발동. 완성 합성: 완성형/한계. 유물: 발동/효과/예외/실시간 카운터.
- 작은 전투 호버와 제작·보상·도감·실험 기록의 상세는 **공통 원본 정보**를 참조하되 노출량만 달리한다.
- **미발견 합성 재료 힌트는 보존**, 발견 전 **완성형 효과는 공개 정책에 따라 제한**. '미발견 정보는 전부 감춘다'로 구현하면 안 된다.

### 6.2 유물 보유 — Slay the Spire + Magicraft

**Slay the Spire에서:** 작은 유물 아이콘 줄·호버로 즉시 효과 확인. **Magicraft에서:** 선택한 유물의 큰 상세 카드 구성.

- 전투 **왼쪽 아래**에 `유물 N` + 실제 아이콘 배열; 호버/포커스는 전투 비정지.
- 전체 보유창은 **아이콘 격자 + 선택한 유물 상세**, 원래 3열 큰 텍스트 카드보다 축약.
- **전체 창은 정지형 권고안**이나 실제 보상/ESC 정지 원인과의 중첩 안전성을 먼저 검증한다.
- 현재 `interface.gd::show_relics()` → `game.open_personal("relics")` → `personal_window.gd`가 `inventory`로 다시 지정하는 **정적 경로 문제**가 있어 실제 클릭 검사 및 승인 후 수정 필요.
- **유물 자체 강화/레벨·중복/희귀도는 현재 미구현.** 없는 성장 버튼과 가짜 등급 표시 금지.
- 장갑/저금통/영혼 솜옷 같은 유물의 **현재 시전·마석·보호막 카운터는 현재 런에서만**. 과거 기록의 당시 수치처럼 사용하지 않는다.

## 7. 타이틀·캐릭터 선택·시작 (UI-02/03)

**참고:** HoloCure의 큰 인물·선택 강조, Vampire Survivors의 빠른 반복 런, 20 Minutes Till Dawn·Brotato의 캐릭터와 시작 조합 분리.

**장기 흐름:** `타이틀 → 마녀 선택 → 시작 마법 조합 선택 → 실험 시작 확정 → 선택적 도입 → 전투`.

- 타이틀은 게임 이름·**새 실험/이어하기**를 최고 우선순위, 훈련장·도감·기록·설정은 보조 메뉴.
- 선택 인물 큰 이미지 + 네 마녀 후보 초상화는 **장기 시안**. 현재 플레이 가능한 루미와 미구현 네라·모카·세라를 명확히 구분.
- 시작 마법 키트는 실제 존재하는 4개 조합의 지급 결과를 정확하게 표시.
- 선택·탐색만으로 게임 시작/저장 덮어쓰기 발생 금지.
- 일러스트 없는 인물이나 구현되지 않은 고유 능력·성장·해금 조건을 가상으로 만들지 않는다.

## 8. 승리·패배 결과 / 실험 기록 (UI-06/08)

### 8.1 결과 화면

**참고:** Brotato의 실제 빌드·결과 통계, HoloCure의 큰 승패 텍스트, Hades의 승리 강조.

- 동일 공통 레이아웃으로 **사고 수습 완료 / 실험 중단**을 위쪽 크게 표시.
- 루미 반응/일러스트는 실제 자산·승인 시에만. 승리 밝은 축하, 패배는 지나치게 비극적이지 않은 실험 실패.
- **전투 시간·편집 시간·처치·실제 얻은 마석·도달 웨이브**, 오브 1~4 마법 배열과 유물, 짧은 결말 및 재도전/타이틀 버튼.
- 실제 저장되지 않는 DPS/마법별 피해량을 가상으로 만들지 않는다. 런 종료 때 현재 메모리 자료로 보여줄 수 있는 것과 과거 기록의 저장 필드를 구별한다.
- **결말+결과 한 화면** 유지. 다시 하기와 다른 시작 조합 선택 행동 분리.

### 8.2 지난 실험

**참고:** Slay the Spire Run History, Hades의 Security Log, Monster Train의 런 복기.

- 왼쪽 **최근 최대 10판** 선택 목록, 오른쪽 **선택 런**의 승패/키트/전투·편집 시간/처치/마석/웨이브/오브·유물 상세.
- 전적을 세계관상 **실습 일지**처럼 표현. 억지로 큰 통계 대시보드/피해 그래프 만들지 않는다.
- 현재 스키마에 없는 **런 날짜, 과거 오브 자체 성장 랭크, DPS·무기별 피해량**을 자동 추가하지 않는다.
- 결과/실험 기록은 **같은 아이콘·빌드 표시 컴포넌트**를 재사용하되 데이터 소스는 분리.

## 12. ESC/설정 및 화면 상태

**참고:** Hades II의 단순한 중앙 메뉴와 HoloCure의 설정 표시, Brotato의 현재 런 요약.

- ESC는 `계속하기`를 가장 강하게. 설정/조작법/다시 시작/타이틀을 분리.
- 진행 중 런을 잃는 **재시작·타이틀** 행동은 확인창 제안. 현재 실존하지 않는 음량·화면·BGM 옵션을 완성된 기능처럼 표시 금지.
- 설정 기능 수가 적으면 **한 페이지의 일반/소리/화면·조작 구역**으로 시작하고, 필요해지면 탭 확장.

### 12.1 화면별 '전투 상태 + 입력 소유권' 표

| 상태 | 전투 타이머/적 행동 | 중요 규칙 |
|---|---|---|
| 타이틀·캐릭터 선택 | 전투 없음 | 탐색과 실제 확정을 구분 |
| 웨이브 사이 제작대 | 준비 상태 | 시전/경우에 따라 시험 발사 별도 |
| 일반 전투 | 진행 | 이동·회피·자동 시전 |
| **일반 Tab 가방/오브 편집** | **진행** | 드래그·우클릭·되돌리기; 경고·툴팁은 입력 방해 금지 |
| **보상 선택·수령 후 편집** | **정지** | 남은 보상 완료 후 **명시적 재개** |
| 마법·유물 작은 호버 | **원래 상태 유지** | 정보만 |
| 전체 유물 상세 | **정지형 제안** | 기존 보상/ESC 정지 이유를 보존해야 함. 확정 전 테스트 |
| 웨이브·보스·발견 알림 | **원래 상태 유지** | 비모달; 전투/보상 입력 가로채지 않음 |
| ESC 일시정지 | **정지** | 계속하기/설정/종료 확인 |
| 승리·패배 | 런 종료 | 재도전/타이틀 |

창을 닫는 동작이 원래 정지 중이던 보상을 **강제로 재개하지 않도록** 정지 원인/포커스를 추적한다. 기존 `personal_window.gd`의 `personal_tab="inventory"` 재설정과 유물 창 열기 경로는 실제 클릭으로 확인이 필요한 결함 후보.

## 13. 알림 우선순위 및 중복 방지

**전투 판단을 위한 경고 > 현재 입력 소유권을 가진 보상 > 나중에 확인 가능한 축하**.

1. 실제 보스 등장/즉시 회피를 요구하는 위험 경고
2. 보상 선택·상자 공개(입력 상태를 보존)
3. 완성 합성 첫 발견
4. 일반 마법·유물 첫 발견
5. 일반 웨이브 안내·조작 힌트

- 위 표는 **시각 충돌 관리 제안**이며 확정된 프레임 타이밍이 아니다.
- 공용 `announce()` 단일 문자열에 모든 알림을 넣어 덮어쓰지 말고 유형·우선순위·큐(또는 병합) 정책을 설계.
- 상자에서 여러 개를 얻었을 때 **같은 아이템의 획득/처음 발견 축하가 동시에 두 번** 크게 나타나지 않게 한다.
- 보스 HP바/시계/오브 슬롯·가방·보상 카드·플레이어의 실전 시야는 경고/축하 때문에 가려지지 않아야 한다.

## 14. 통합으로 해결한 보고서 간 충돌 (아직 사용자 확정 아님)

## 15. **Codex 전달용 이미지 규격** — 텍스트 그림만으로 구현 금지

### 15.1 화면마다 필요한 자료

| 자료 유형 | 내용 | 준비 여부 |
|---|---|---|
| **A. 원작 UI 실제 캡처** | 참고 게임·해당 메뉴/버전·모드 여부 | **통합본에 신규 첨부 없음** |
| **B. 참고 대상 표시된 캡처** | 가져올 카드·버튼·영역에 숫자/테두리·짧은 주석 | **미작성** |
| **C. 우리 게임 현재 캡처** | 같은 해상도에서 현행 UI 실물 | 기존 UI 배치 문서에 예전 캡처 파일명 있음. **이번 등록에서 재검증 안 함** |
| **D. 우리 게임 목표 16:9 배치 이미지** | 선택한 설계안의 패널·아이콘 실제 크기/여백 | **미작성** |
| **E. 상태별 비교 화면** | 일반/호버/클릭/가방/보상3·4택/ESC/최종보스 등 | **미작성** |

**우선 실제 이미지를 만들어 비교할 화면:** 전투 HUD → 보상 3~4택 → 상점·제작 작업대 → 유물 보유/상세. 이어서 도감/시작·결과/보스·발견.

### 15.2 이미지별 필수 주석 필드

- **참고 게임/출처·버전·스크린샷 URL** (확인 가능한 범위만; 모드·팬 UI 구분).
- **어느 요소를 참고**하는지 — 예: Slay the Spire **전투 중 왼쪽 상단 유물 아이콘 줄/호버 정보**.
- **우리 화면의 위치/크기·해상도·앵커·안전 여백**.
- **무엇을 가져오지 않는지** — 아트, 원작 효과/보상/인접 규칙 등.
- **보유/장착/선택/비활성/경고/호버·포커스 상태**.
- **현재 구현인지, 추가 구현 제안인지**.
- **실제로 검증한 것/미검증한 것**.
- 출처 게임을 단순 나열한 것만으로 외형/동작 구현 지시가 되지는 않는다.

**예: 유물 UI:** Slay the Spire 원작 유물 아이콘·호버의 정확한 캡처 → 참고 영역 표시 → Magicraft 유물 상세 카드 캡처 → 우리 게임 좌하단 아이콘/선택 상세 배치 → 유물 0/1/4/12개 실제 화면.

**예: 작업대:** Backpack Battles 구매 상품·가방 공존 → Magicraft 주문 조합 화면 → 우리 `workbench` 기존 캡처 → 상품/가방/선택 오브/툴팁 목표 배치 → 오브 1~4개·긴 가방·합성 재료 부족 상태 비교.

### 15.3 Codex 구현 승인 후 완료 조건

1. 참고 이미지/주석/목표 배치 시안 **검토·사용자 미관 승인**.
2. 현재 Godot 화면의 기존 동작·저장·입력 계약 **우선 확보**.
3. 표준 해상도 **1280×720 / 1600×900 / 1920×1080**에서 실제 렌더 캡처.
4. 마우스·드래그·우클릭·키보드 포커스·ESC·보상 재개 실제 동작 검증.
5. 보상 3/4택, 가방 길이, 오브 1~4, 유물 0~12, 긴 툴팁, 게임 첫 시작/종료, 최악 화면 중첩 확인.
6. 보스·박쥐/포위 경고는 **실제 적 생성·위협 행동**과 일치.
7. 첫 발견 큐는 **영구 처음 발견만** 1회/유효 ID, 복원/이관·재획득 중복 없음.
8. **빌드 성공·검사 통과·실제 화면·성능·사용자 체감**은 별개의 검증 근거. 일부만 확인했다면 VERIFIED로 단정하지 않음.

- **가방과 보상 시각 모드:** 기존 `UI-LAYOUT-REVISION-v1.md` 실구현 계약과 새 시안이 충돌한다면 실제 화면 비교 후 결정.
- **유물 전체 창:** 정지형을 권하지만 기존 보상/ESC 원인 및 사용자 의도와 함께 결정.
- **작업대 공간:** 1036px 우측 패널을 유지한 최소 수정 vs 판매 상품·오브·가방 공존형 큰 개편.
- **마녀 4인 선택:** 향후 캐릭터 플레이가 실제 구현된 시점에 확장.
- **새 보물상자/보스/합성 연출:** 애니메이션 지속시간·새 스프라이트·사운드는 실제 시안과 별도 승인 필요. 삭제했던 임시 BGM 재도입 금지.
- **도감 NEW:** 영구 읽지 않음 상태의 스키마 추가/옛 프로필 이관이 선행.
- **제품 구현 결함:** 박쥐/포위 실제 압박, 유물 버튼 라우팅 등은 **아트 개선과 별도 문제**.
- **기존 보고서 Markdown 정리:** UI-01 일부 상대 경로 `../../scripts/`와 UI-10의 백틱 이스케이프 오류는 이번 통합 설계서가 등록됐다는 이유만으로 자동 수정된 것이 아님.
