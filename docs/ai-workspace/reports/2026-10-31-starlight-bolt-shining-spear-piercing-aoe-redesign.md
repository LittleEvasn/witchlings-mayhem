## 1. 사용자 확정 변경 사항

### 1-1. 기본 공격 '별빛탄' (`bolt`)

- **0강 1발 / +1강 2발 / +2강 3발 / +3강 4발**로 **각 시전의 발사체 수**를 변경한다.
- **+1강 2발은 전방(현재 조준 방향) 1발 + 정반대 방향(180° 후방) 1발**로 발사한다. 단순 좌우 대칭 2발/전방 부채꼴 2발은 사용자 요구와 다르다.
- **0강은 전방 1발.**
- **+2강(3발), +3강(4발)의 정확한 방향 각도**는 사용자 미지정. 기존 4방향 십자 배치를 +2강에 그대로 유지할지, 균등 방사형/조준 방향 기준 어느 각도를 쓸지 **추후 설계 대상**이다. 임의 확정으로 취급하지 않는다.
- **갈래(`fan`) 보조로 추가되는 발사**는 별빛탄 자체 강화로 인한 개수와 다른 규칙이다. 기존 갈래·메아리·강화·연결 처리와 호환 검증 필요.

### 1-2. 완성 합성 '빛나는 창' (`shining_spear`)

**기존 합성 레시피 '별빛탄 + 관통'을 유지한다.** 해당 완성 마법 자체의 행동을 다음으로 개편한다.

1. **한 번 시전 시 창 투사체 4발(4갈래) 발사.** 기본 별빛탄의 새 강화별 1/2/3/4 발사 규칙과 구별한다. **완성 합성은 항상 4발**이라는 사용자 결정이다. 각도·조준 방향 정렬 기준은 추가 결정 사항이며, 원형 예시도는 확정된 각도 수치가 아니다.
2. **적을 대상으로 무한 관통.** 한 투사체가 적을 여러 명 통과하더라도 **적 관통 횟수가 소진되어 사라지면 안 된다**. 기존 `pierce=5` 제한을 폐지한다. 단 **투사체 수명·전장 경계·일반 종료·성능 안전장치까지 무한**이라는 뜻은 아니다.
3. **관통하여 적에게 명중할 때마다, 그 명중한 적의 위치를 중심으로 원형 범위 타격 판정을 발생**시킨다. 광파는 뒤쪽으로 2개 나오는 장식이 아니라, **실제로 근처 적에게 피해를 주는 범위 공격**이어야 한다.
4. **기존 측면 원 두 개 삭제.** 지금 코드는 접촉 지점 기준 진행 방향 양옆 `±36` 떨어진 위치에 `radius=28×scale` 원형 공격을 각각 생성한다. 이를 **'명중 대상 중심 원형 범위 1회'** 발동으로 교체한다. 적 한 명을 관통할 때마다 **대상 위치에 독립된 하나의 범위 판정**이 생긴다.
5. **다음 적 관통 시 다시 발동.** 투사체마다 한 번만 발동하고 더 이상 원형 공격이 안 나오는 구현은 잘못이다. 관통한 적 A, B, C 각각에서 범위 판정이 생겨야 한다.
6. **명중한 적의 직격 피해**와 **범위 피해**는 별개의 타격 경로다. 다만 **직격 대상에게 직격과 범위 피해를 중복 적용할지**, 범위에 들어온 다른 적의 반복 피해 제한은 **미확정**. 이 문제를 자동으로 양쪽 적용/자동 제외로 확정하지 않는다.

**예시:**

- 별빛탄 0강 단독: 전방 1발 / +1강: 전방 1발과 후방 1발 / +2강: 3발 / +3강: 4발.
- 빛나는 창 완성 합성: **창 4발** 발사 → 창 1발이 적 A를 **관통**하며 **A 중심 원형 피해** → 적 B도 관통하며 **B 중심 원형 피해** → 적 C도 관통하며 **C 중심 원형 피해** → 투사체는 **일반 수명/전장 경계 등 다른 정상 종료 조건**까지 비행한다.
- 왼쪽/오른쪽에 따로 생기던 **원형 2개**는 생성하지 않는다.
- **광파라는 이름에 현혹되어 원형 범위 판정을 장식/VFX로만 만들지 않는다.** 히트/실제 HP 감소로 검증한다.

## 4. 별도 구현 요청 시 사용자 요구 기반 성공/실패 검증

1. 동일 조건에서 기본 `bolt@0`/`@1`/`@2`/`@3` **실제 발사체 수 1·2·3·4** 확인. +1강은 조준 방향과 **정반대 180°**임을 움직이는 실제 탄 궤적으로 검증. +2/+3 각도는 별도 확정 후 그 기준 적용.
2. `shining_spear`를 한 번만 시전했을 때 **실제 공격체 4발**. VFX·탄수 표기만 4로 만드는 방식은 불합격. 주변 갈래(`fan`)/메아리 보조가 존재하면 고유 4발과 추가 발사·피해 예산 관계 검사.
3. 하나의 창이 직선상 여러 적 A→B→C→…를 **관통 제한 없이 통과**, 각 적에게 직접 접촉 피해를 전달. 5명/6명에서 잘리는 `pierce=5` 구현은 불합격. 실전에서 시험용 고정 인형과 실제 적 모두 확인.
4. 동일한 투사체가 **서로 다른 적에게 명중할 때마다** 해당 **적의 현재 위치**에 원형 실피격 판정을 발생. 기존처럼 좌/우 오프셋 위치에 **두 개씩 발생하지 않음**.
5. 범위 안의 **이웃 적 HP가 실제 감소**하는지 검사. 범위 밖 적은 피해가 없어야 함. 범위의 링/VFX 위치와 **실제 충돌 원의 중심** 일치 확인. **직격 대상 중복 피해 정책은 미확정**임을 테스트에 명시.
6. 각 창의 `hit` 기록은 개별 유지. **같은 적에 프레임마다 무한 재적중**, 광역 범위 이벤트의 무한 재귀, 별도 연결 마법을 비의도적으로 다회 발사하는 동작이 생기지 않도록 검증.
7. 정상 수명 만료, 맵 밖 이탈, 게임 중단, 웨이브 전환, 다수 적/4오브 부하, 피격 후 지속 진행을 검증. **무한 관통을 무한 생명/화면 밖 무한 발사/이벤트 폭주로 해석하지 않는다**.
8. 도감/툴팁/강화 비교/시험실/합성 편집 화면의 **1·2·3·4방향 및 4방향·무한 관통·대상 중심 범위 타격 설명**을 최종 코드와 맞춘다.
9. 사용자 핵심 규칙과 다른 동작을 간단한 시각 대체 효과로 축소하지 않는다. **기능 성공, 시각 검증, 실피해, 성능, 체감은 각각 별도 기록**.

## 5. 유의사항 및 범위

- **원작 출처:** 현재 코드 문서에서 '빛나는 창'이 다른 작품의 특정 주문을 원형으로 **직접 차용했다는 증빙은 확인되지 않았다**. 이 보고서는 **우리 합성 레시피와 사용자 개편 지시**만 다룬다. 다른 게임과 비슷한 이름이라는 이유로 원작 수치/효과를 도입하지 않는다.
- **기존 합성 `shining_spear`의 전용 1방향 규칙과 유한 관통**을 바꿔야 한다는 사실은 **현재 코드 정적 열람**에서 확인했으며, 이 문서 자체는 코드나 게임 화면을 바꾸지 않았다.
- **다른 공격 및 보조 구체**의 성장·관통·재연결 규칙, `PROJECT-HANDOFF`, 이전 사용자 확정 문서·테스트는 별도 구현 승인 없이 무단 변경하지 않는다.
- **업로드 범위:** `docs/ai-workspace/reports/`, `decisions/`, `INDEX.md`만 편집. `scripts/`, `tests/`, `assets/`, `scenes/`, CI·엔진 실행은 이 요청에 포함되지 않는다.

**한 줄 결론:** **별빛탄은 1·2·3·4발(2발일 땐 전후방), 빛나는 창은 4발 고정·무한 적 관통, 관통해 명중한 각 적을 중심으로 원형 실피해 1회 발생.** 수치·세부 각도는 추후 확정한다.
