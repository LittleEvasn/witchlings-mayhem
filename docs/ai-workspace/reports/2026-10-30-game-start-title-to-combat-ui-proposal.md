## 4. 타이틀 화면 구성 제안

### 시각적 위계

1. **게임 이름:** `마녀들의 사고현장` 로고를 가장 먼저 읽을 수 있게.
2. **가장 중요한 행동:** `새 실험` 또는 저장이 있을 때 `이어하기`를 분명하게 구별.
3. **캐릭터/세계관:** 네 마녀의 관계 및 마법 실습실 분위기를 정보의 배경으로 전달.
4. **보조 메뉴:** `마법 훈련장`, `발견 도감`, `실험 기록`, `설정`을 한 단계 낮은 시각적 우선순위로 배치.
5. **종료:** 우상단 등 눈에 보이되 시작 동선과 경쟁하지 않는 곳.

### 권장 구성

- 왼쪽: 로고와 게임 시작/이어하기를 묶은 세로 메뉴. 메뉴를 전부 동일한 굵기·색으로 강조하지 않는다.
- 오른쪽: 캐릭터를 크게 보여주는 영역. 장기적으로 네 마녀의 관계를 표현할 수 있으나 **현재 자산·플레이 구현에 맞춰 루미 1명만 보여주는 단계도 유효**하다.
- 배경: 실습실 분위기를 사용하되 글자·버튼 판독을 방해하지 않게 대비 제어.
- 명칭: `새 실험` / `이어하기` / `마법 훈련장`은 서로 다른 기능임을 분명히 한다.
- 배경의 화려함이나 캐릭터 그림이 필수 기능 구현보다 앞서지 않도록 한다.
- **이번 보고서는 새 그림 제작을 요청·승인하는 문서가 아니다.** 기존 아트·구매 가능 GUI 에셋 활용 판단은 별도 논의.

## 5. 게임 시작 흐름 제안

### 신규 실험 — 장기 목표 (구조 제안)

`타이틀 → 마녀 선택 → 시작 마법 선택 → 실험 시작 확정 → 선택적 도입/튜토리얼 → 전투`

- **마녀 선택:** '누구를 플레이하는가' 결정. 네라·루미·모카·세라를 장기 구상으로 반영하지만 현재는 루미 단일 플레이 구현을 보존.
- **시작 마법 선택:** 기존 네 조합의 이름·아이콘·설명·레시피를 이해하기 쉽게 보여준다. 캐릭터별 조합 공유 범위/전용 키트는 미확정.
- **확정:** 메뉴 탐색이나 조합 클릭만으로 전투 시작/자원 지급/기존 저장 삭제를 하지 않는다.
- **선택적 도입:** 첫 플레이 설명과 재도전 속도를 분리한다. 기존 `도입 이야기 보기`·건너뛰기·뒤로 가기 기능을 보존.
- **전투:** 안내 없이 마법 효과를 보여주는 첫 진입 경험을 검토한다.

### 화면 분리 여부는 **미확정**

**A. 한 준비 화면형:** 기존 `prepare()` 안에서 캐릭터·마법 두 영역을 함께 표시. 단계가 짧고 현재 UI에 가깝지만 정보 밀도가 높을 수 있다.

**B. 두 단계형:** 인물 선택 → 마법 선택을 별도 페이지/화면 상태로 전환. 집중도가 높지만 반복 런에서 클릭 수가 늘 수 있다.

**추천 출발점:** 캐릭터를 교체하는 동작과 마법 키트를 고르는 동작은 **논리적으로 구분**, 실제 화면은 1화면 전환/2화면 중 사용자 검토 후 결정. 이번 보고서로 2화면을 확정하지 않는다.

### 현재 구현에 대한 단계적 적용

- **1단계:** 루미·4개 키트 현행 흐름 유지. 타이틀 메뉴의 우선순위와 실험 준비의 가독성부터 개선.
- **2단계:** 실제 마녀별 플레이가 구현되면 네 명 선택 UI를 연결. 능력/해금 조건을 임의로 만들어 표시하지 않는다.
- **3단계:** 필요 시 실습실 분위기의 짧은 전환을 붙이고 실제 플레이 입력·해상도로 검사.

- 첫 진입 튜토리얼과 반복 플레이 흐름은 구분하되, 스토리 채팅에서 논의된 `스토리1 → 튜토리얼 → 프롤로그 → 스토리2/3`의 서사적 순서는 함부로 변경하지 않는다. UI 배치와 스토리 구조의 정확한 결합은 별도 확정이 필요하다.
- 첫 30초의 몬스터 생성/성장 간격/난도는 **이 문서에서 숫자를 새로 정하지 않는다**.

## 8. 이어하기·재도전 예외 경로

- 이어하기는 **저장된 실험 상태로 복귀**해야 한다. 새로운 마녀/키트를 고르는 단계로 되돌리면 안 된다.
- 체크포인트를 보유한 사용자가 새 실험을 확정할 때는 **기존 저장 대체 경고**를 유지한다.
- `실험 시작` 버튼과 `선택 강조` 상태는 별개의 입력.
- 결과 화면의 **같은 조합 즉시 재도전 / 다른 조합 고르기 / 타이틀** 구분을 유지하고, 반복 튜토리얼 강제를 피한다.
- 일시정지 중 메뉴 복귀·도입 뒤로 가기·ESC·저장 파일 오류 등도 상태 전이의 회귀 검증 대상이다.

## 10. 승인 후 확인해야 할 완료 조건 — 이번에 테스트하지 않음

1. 새 실험 버튼에서 선택/확정을 완료한 뒤, 기존 `begin_lumi_run` 흐름 또는 승인된 대체 런 진입으로 정상 이동한다.
2. 선택만으로 기존 실험 삭제·전투 시작·마법 지급이 발생하지 않는다.
3. 루미 + 4개 시작 조합의 실제 지급 레시피와 화면 정보가 일치한다.
4. 이어하기를 선택하면 새로운 마녀/마법 결정을 요구하지 않으며 저장 상태를 유지한다.
5. 중복 클릭·뒤로 가기·ESC·Tab/화살표·Enter·마우스의 입력 경로가 정확히 작동한다.
6. 실험 시작/도입 진행/건너뛰기/전투 직전에 일시정지·타이머·적 생성 상태가 맞다.
7. `1280×720`, `1600×900`, `1920×1080`에서 메뉴와 키트 카드, 버튼이 잘리지 않는다.
8. 기존 훈련장/발견 도감/실험 기록/설정/종료 및 결과·재도전 경로에 회귀가 없다.
9. 신규 마법 전환 연출이 있다면 스킵/복귀 중 재입장·이중 전투 실행을 막는다.
10. 검사 결과는 **정적 소스 확인 / 자동 테스트 / 실제 Godot 화면·입력 / 사용자 디자인 승인·재미 평가**로 별도 기록한다.

## 11. 미결정 사항

- 타이틀을 기존 루미 중심으로 유지할지, 최종적으로 네 마녀를 함께 보여줄지.
- 캐릭터와 시작 키트를 **한 화면**에서 선택할지 **두 단계**로 분리할지.
- 미구현 마녀의 노출/선택 불가 표시 여부.
- 첫 플레이용 스토리·튜토리얼과 도입 이야기 보기 토글의 관계.
- 실험 시작 시 즉시 전투 또는 짧은 전환 연출.
- 전투 첫 30초에 조작/마법 편집 안내를 얼마나, 언제 보여줄지.
