## 0. 핵심 결론

**전투 UI는 상황을 말로 중계하지 않는다.** 위협은 적과 실제 움직임으로 보여주고, 플레이어가 선택하거나 확인해야 하는 내용만 짧게 표시한다. 기본은 **무문구**, 문구가 필요하면 **명사형 레이블 + 대상 이름/수치**로 제한한다.

- 일반 적/적 무리/포위/박쥐 횡단에 캐릭터 같은 설명이나 감탄 금지.
- 상자 1·3·5개 보상 차이는 **보상 공개 방식과 실제 개수**로 보여주고 ‘대박’, ‘행운’ 문구 금지.
- 마법·유물·합성은 **획득**과 영구 프로필의 **첫 발견**을 구분한다. 알림 중복 금지.
- 최종 보스는 **실제 등장 확정 시 이름을 보여주는 것**을 기본으로 한다. 보스 등장 상황을 해설하지 않는다.
- 게임 오버/일반 엔딩은 기존 확정 세계관 문구를 유지한다.

## 1. 레퍼런스 — 《뱀파이어 서바이버즈》에서 참고할 점

**참고하는 것은 문구 하나하나의 공식 한국어 번역이 아니라 화면의 정보 전달 방식이다.** 이전 HUD 조사에 기록된 원작의 레벨업·보물·결과 UI를 근거로 사용한다. 이번 문서에서 최신 게임 버전 원문/공식 한국어 문자열을 재실측한 것은 아니다.

- 적의 수와 패턴, 이동 방향이 전투 경험을 구성한다. 모든 위협을 음성/텍스트로 ‘설명’하지 않는다.
- 보상은 **발견/레벨업/열기/획득**처럼 짧은 상태와 이름을 통해 이해한다.
- 상자 개봉의 강도는 **애니메이션과 보상 숫자·아이콘·시퀀스**가 담당한다. ‘대박!’ 같은 말이 도파민 연출의 대체물이 아니다.
- UI 문구는 게임의 톤을 결정하는 동시에 화면을 점유한다. 침묵도 의도된 연출 선택지다.
- 원작과 우리 게임의 전투 이벤트·상자 수량·보스 시스템은 같지 않다. **원작 사실**과 **우리 적용 제안**을 혼동하지 않는다.

### 출력 문체 기준

| 구분 | 잘못된 방식 — 폐기 | 채택할 방식 |
|---|---|---|
| 어조 | “~했어!”, “~할까?”, “~해봐”, “좋아!”, “이제 시작이야!” | 명사형/표제형, 짧은 명령형 버튼, 핵심 정보 |
| 전투 위험 | 적이 하는 일을 캐릭터가 해설 | **대개 문구 없음**. 필요하면 실제 적 위치/방향을 근거로 한 시각 경고 |
| 보상 | “축하해!”, “대박!”, “행운이 함께했어!” | **열기, 획득, 신규 마법, 합성, 보상명, 수량** |
| 안내 | “조합을 바꿔볼까?”, “다른 방법을 찾아보자!” | **조합 편집, 장착, 전투 재개, 공격 구체 없음** |
| 결과 | 임의 위로·격려·농담 대사 | **GAME OVER, 사고 수습 완료**, 실제 기록과 확정 스토리 문구 |
| 짧은 캐릭터 대사 | 반복 시스템 알림 대신 루미/모카가 계속 말함 | 전투 UI에서는 사용하지 않음. 실제 연출 대본과 분리 |

**주의:** 기능적 접근성/실패 원인을 알아야 할 때는 짧은 설명 문장이 필요할 수 있다. 이를 유치하다고 기계적으로 전부 삭제하는 것이 아니라 **중립적이고 정확한 설명**으로 고친다. UI에서 필요한 동작을 숨기지 않는다.

## 2. 게임 화면별 최종 문구 방향 (대체안)

아래 표는 **이번 보고서에서 채택 후보로 정리한 전체 UI 카피**다. **표현 원칙은 확정**, **개별 문구의 픽셀 배치/표시 시점/영문 병기/최종 선택은 제안**이다.

| 화면·상황 | 화면에 표시할 문구 | 출력 조건 및 비고 |
|---|---|---|
| 보통 적 생성 | **없음** | 스폰마다 공지 금지 |
| 박쥐 떼 횡단 | **없음** | 실제 진입·횡단 궤적, 위협 이펙트 우선. 접근성 요구가 있다면 근거 있는 방향 마커만 별도 검토 |
| 포위 이벤트 | **없음** | 포위 고리 자체로 전달. 가상의 탈출구/돌파법을 말로 약속하지 않음 |
| 일반 무리 출현 | **없음** | 반복 팝업 없음 |
| 정예 등장 | **기본 없음** | 실제 정예 생성과 식별성 검증 후 필요하면 작은 아이콘/HP바. 정예가 없는데 ‘정예 등장’ 금지 |
| 운반자 출현 | **기본 없음** / 선택적 아이콘 | 실제 운반자에 눈에 띄는 표시, 남은 시간·위치 등 실전 정보 우선 |
| 운반자 재료 드롭 | **재료 회수** | 실제 회수 가능한 아이템에 작은 라벨/아이콘. 아직 받지 않았으면 ‘획득’ 표시 금지 |
| 운반자 도주 | **기본 없음** / 필요 시 **운반자 이탈** | 누락 처리·보상 기회 등 정확한 상태만 |
| 웨이브 시작 | **WAVE 01 / 05** … **WAVE 05 / 05** | 짧은 배너가 필요하다면 5개 큰 웨이브 시작에만; 1분 내부 단계마다 뜨지 않음 |
| 웨이브 완료·준비 | **WAVE COMPLETE** 또는 **실습 완료** | 둘 중 하나의 표현 체계 채택. 획득/회복 수치가 있다면 실제 수치만 추가 |
| 웨이브 다음 단계 | **다음 웨이브 02 / 05** | 제작 준비 화면에서 필요한 정보만 |
| 최종 보스 실제 등장 | **끝없는 모범답안** / **FINAL BOSS**(보조) | 실제 보스 엔티티 출현을 확인한 이후. 보스명·체력바가 핵심 |
| 최종 보스 대기 HUD | **최종 보스 · 00:00**(카운트다운 중) | 실제 남은 시간/단계 기준으로만. ‘처치하면 승리야!’ 불필요 |
| 레벨업 선택 | **LEVEL UP** 또는 **레벨 업** / **선택** | 기존 3~4택 카드 구조 유지. ‘하나를 골라요’ 제거 |
| 보물상자 진입 | **보물 발견** 또는 **보물상자** | **개봉 전 1·3·5개 보상 개수 미리 알리지 않음** |
| 보물상자 버튼 | **열기** | 기능 버튼. ‘상자를 열어볼까?’ 금지 |
| 상자 개봉 중 | **문구 없음** | 상자 애니메이션 및 시각 효과 우선. 필요하면 스킵 버튼만 |
| 상자 보상 1개 | **획득 아이템명 + 수량** | 별도 감탄문 없음 |
| 상자 보상 3개 | **아이템명 ×3건** | 실제 결과를 순차 공개. 가짜 ‘잭팟’ 텍스트 없음 |
| 상자 보상 5개 | **아이템명 ×5건** | 특별한 시각 연출만 강화, 과장 문구 없음 |
| 일반 마법 획득 | **[마법명] 획득** | 이번 런의 획득 결과. 영구 최초 발견과 구분 |

| 마석 지급 | **마석 +N** | 실제 지급량 |
| HP 회복 | **체력 +N** | 실제 회복량, 최대체력 초과 분 제외 |

| 제작 실패/재료 부족 | **재료 부족**, **마석 부족**, **빈 공격 슬롯** 등 | 구체적 사유는 필요한 만큼 툴팁에 명확히 설명 |

| 전투 재개 | **전투 재개** | 클릭 이후 실제로 재개되는 기능에만 |
| 게임 오버 | **GAME OVER** / **교수님에게 혼났다.** | 사용자 확정 스토리 문구 유지. 교수님 캐릭터 등장/대사 금지 |
| 일반 클리어 | **사고 수습 완료** | 이야기/단서 해금과 실제 결과 분리 |
| 진엔딩 클리어 | **사고 수습 완료** / 실제 진엔딩 대본 | 진엔딩 조건 확정 시 해당 컷신·대사 연결. 임의의 새로운 결말 문구를 만들지 않음 |
| 결과 통계 | **전투 시간 / 처치 / 획득 마석 / 도달 웨이브** | 저장된 실제 수치만. 없는 DPS 수치 표시 금지 |
| 다시 플레이 | **재도전 / 다른 시작 조합 / 타이틀** | 기능 이름만 표시 |
| 최초 플레이 조작 안내 | **이동 WASD · 회피 Space · 조합 Tab · 자동 공격** | 튜토리얼/첫 진입에 한정. 반복 전투 안내 금지 |

### 별도 유의사항

- 상자 5개 결과는 **'대박!' 문구로 대신할 수 없다**. 진짜 5개 보상 공개 연출 및 결과 정확성이 중요.
- ‘신규’는 **이번 런에 처음 소지함**과 **프로필 전체에서 처음 발견함**의 의미가 다르므로 별도 조건으로 처리한다.
- 영어 표기 `WAVE / LEVEL UP / GAME OVER`와 한국어 `실습 완료 / 레벨 업`의 최종 혼용 정책은 UI 시안 확정 시 선택. 중구난방으로 같은 화면에서 여러 스타일 혼용 금지.
- 일부 정예/특수 이벤트 경고는 이전 UI 보고서에서 제안됐지만 **이번 사용자 피드백 이후 기본값은 무문구로 변경**. 예외적인 접근성 경고는 실제 정보가 필요하다는 근거부터 제시할 것.

## 4. 기존 보고서와의 우선순위

본 보고서는 **문구 방향과 톤**에 관해 다음 기존 UI 보고서의 예시를 갱신한다. 이전 문서의 UX 구조·보상 경제·위험 이벤트의 실제 행동 규칙까지 무효화하는 것은 아니다.

- [UI-2026-10-30-01 전투 HUD·보물상자](2026-10-30-combat-hud-reward-chest-ui-proposal.md): 보상 1/3/5 공개 연출의 방향과 자동 획득 계약은 유지. 감탄형 문구는 채택하지 않음.
- [UI-2026-10-30-12 새로운 발견 알림](2026-10-30-new-discovery-notification-ui-research-proposal.md): 영구 첫 발견과 보통 획득의 판정·중복 방지는 유지. 알림 텍스트는 **신규 마법 / 신규 합성 / 신규 유물**로 간소화.
- [UI-2026-10-30-10 웨이브·위험 경고](2026-10-30-wave-transition-boss-intro-ui-research-proposal.md): **일반 포위·횡단 설명형 경고는 폐기**, 웨이브 배너·최종 보스명만 남기는 방향. 정예 출현도 기본 무문구로 재검토.
- [UI-2026-10-30-06 승리·패배 결과](2026-10-30-victory-defeat-results-ui-research-proposal.md): 결과 기록 구조는 유지, 확정된 교수님 GAME OVER 문구와 스토리 결말 정책을 우선.

**이전 문서의 예시 텍스트를 원문 그대로 재사용하지 말 것.** 관련 보고서는 이 문서로 넘어오는 상단 안내를 달아 기록 자체는 보존한다.

## 5. 구현 승인 후 완료 기준 (현재 실행·검증하지 않음)

1. **전투 중 알림 금지 확인:** 포위/박쥐/일반 무리/정예 발생 중 불필요한 구어체 토스트가 뜨지 않는다. 해당 적·경고 효과의 실제 동작은 유지한다.
2. **위협 인지성:** 문구 제거만으로 숨겨진 위험이 되는지 실제 Godot 화면에서 확인. 인지 불가능하면 **사실에 근거한 시각 신호**만 추가 검토한다.
3. **상자 개봉:** 1/3/5개 실제 보상·수량과 공개 강도가 정확히 일치, 사전 결과 스포일러가 없다. ‘대박!’ 문구가 5개 연출 대체물이 되지 않는다.
4. **발견 알림:** 일반 획득 / 영구 첫 발견을 명확히 분리, 저장 실패·복원 재발견·다중 보상에 거짓/중복 축하를 띄우지 않는다.
5. **결과/서사:** 교수님 직접 등장/실패 개입 대사 제거, GAME OVER에 확정 문구, 일반·진엔딩은 최신 대본 적용.
6. **유효 안내 보존:** 마법 비작동·상쇄, 조작법, 미수령 보상·재개 조건 등 필요한 정보는 간결하지만 정확하다.
7. **전역 톤 검사:** 상점·제작·메뉴·보상·전투·발견·결과의 플레이어 노출 문자열에서 ‘~했어!’, ‘~해봐’, ‘~할까?’, ‘좋아!’, ‘대박!’ 등 설명형 친근 반말 제거. **스토리 대본과 유물 문학 텍스트는 구별**한다.
8. **검증 경계:** 텍스트 정적 검사, Godot 실제 렌더, 이벤트 실제 발생, 플레이어 체감은 서로 다른 검사로 기록. 이번 보고서는 문서 작성과 코드 정적 확인만 수행했다.

## 6. 추가로 결정되지 않은 것

- 영문 `LEVEL UP / WAVE COMPLETE` 또는 한국어 `레벨 업 / 실습 완료` 중 어떤 최종 UI 스타일을 쓸지.
- 화면별 배너 애니메이션 길이·색·위치·VFX·음향, 접근성 예외 경고의 세부 형태.
- 몬스터 도감 내용: **나중으로 보류**.
- 서브 스토리: **가장 마지막 작업**. 별도 지시 없이 본 문구 보고서를 계기로 진행하지 않는다.

**작업 결과:** 문구 목록과 명시 금지 말투를 정리한 설계 문서. **Godot 소스 코드·실제 텍스트 UI·아트·사운드는 이 작업에서 수정하지 않음.**
