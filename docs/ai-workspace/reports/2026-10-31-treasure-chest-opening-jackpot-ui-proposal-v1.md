## 1. 문제와 목표

기존 상자는 열기 이후 기다림과 단순 결과 표시가 중심이어서 **상자 개봉이 보상 이벤트로 체감되지 않는 것**이 핵심 문제다. 사용자가 요구한 것은 상자 보상을 받았다는 확인을 넘어서, 기대 → 공개 → 특히 희귀한 다중 보상에서의 강한 성취감을 느끼게 하는 연출이다.

**핵심 목표:** 평범한 상자도 짧고 만족스럽게 열리되, **1개/3개/5개 보상** 사이에 공개 방식과 시각 강도의 확실한 차이가 있다. 5개는 단순히 아이템 다섯 줄을 보여주는 것이 아니라 별도의 **잭팟 순간**으로 연출한다.

시스템 텍스트는 감탄이나 유치한 대사로 감정을 대신하지 않는다. 축하의 강도는 **모션·크기·빛·리듬·보상 공개 순서**로 전달한다.

## 2. 참고 게임과 차용 범위

| 레퍼런스 | 참고할 부분 | 우리 게임에서의 사용 | 그대로 복제하지 않는 부분 |
|---|---|---|---|
| **Vampire Survivors** | 상자 발견-열기-릴/룰렛-공개, 보상 수에 따른 시각·리듬 강약 | **보상 공개 구조 및 5개 잭팟의 전환 순간**을 주참고로 사용 | 원작 UI 아트·코드·음원·보상 확률 |
| **HoloCure** | 상자 자체의 흔들림/터지는 개봉 움직임, 특별 상자 개봉의 차별화 | 개봉 직전 상자의 움직임과 개봉 반응 참고 | 원작 상자 형태·애니메이션·전용 자산 |
| **Megabonk** | 보상/장비 상태를 확인하는 흐름의 보조 참고 | 결과 이후 정보 가독성 및 확인 흐름에만 제한적으로 참고 | 게임의 실제 인벤토리 양식·장비 구조 |

**제안 핵심 조합:** `Vampire Survivors의 릴/잭팟 구조 + HoloCure의 상자 개봉 움직임`을 2D 카툰·마법 실습 콘셉트에 맞게 재해석한다. 마법진과 주문 에너지 표현은 **자체적인 아트 제안**이며, 최종 PNG가 승인된 상태가 아니다.

## 3. 기존 시스템과 보존해야 할 계약

1. **1/3/5는 획득하는 보상 개수**다. 레벨업의 **3중 1택**과 혼동 금지.
2. 선행 2026-10-30 코드 조사에서는 보상 수 확률이 **80%/17%/3%**였고 `combat_rewards.gd`가 해당 규칙을 갖고 있었다. 이 수치는 **당시 코드 근거값이며 현재 최종 게임 밸런스 확정이라는 뜻이 아니다**. 본 UI 제안은 확률을 변경하지 않는다.
3. 기존 `combat_rewards.gd`의 보상 `stage` 및 후보 계산·지급 순서는 게임 데이터의 진실 원천이다. 연출 때문에 이미 확정/지급된 보상이 다시 계산·복제되면 안 된다.
4. 특히 선행 보고서가 확인한 `reveal_chest()`의 **획득 순서에 따른 다음 후보 재계산**, 합성 재료 소비·강화/획득 분기를 보존해야 한다. **시각적 릴은 결과를 바꾸는 진짜 랜덤 추첨기가 아니다.**
5. 개봉 전에는 **1/3/5개의 실제 보상 수를 미리 표시하지 않음**. 다만 실제 시스템이 결과를 이미 알고 있더라도 UI는 단계적으로 공개할 수 있다.
6. 개봉·보상 정리 중 전투는 정지; **플레이어가 직접 '전투 재개'를 선택하기 전에는 자동 진행하지 않음**.
7. HUD의 가방·오브·HP 등은 **상자 개봉 연출 동안 임시로 숨길 수 있지만**, 결과 확인 후에는 최신 승인된 **가방 한 줄 + 실제 오브별 슬롯** 편집으로 돌아간다. 새 가짜 인벤/격자형 슬롯 제작 금지.

## 4. 개봉 화면 흐름 — 제안

### ① 상자 발견 · 개봉 준비

- 전투 일시정지.
- 일반 HUD는 개봉 연출 동안 숨기고, 실제 전투 장면은 배경으로 남겨 어둡게 처리한다.
- 화면 중앙에 큰 상자를 배치하고 **'열기'** 버튼만 분명하게 표시한다.
- **보상 수량·희귀 결과를 미리 표기하지 않는다.**
- 전투 중 화면 크기/입력 상태를 고려한 오작동·연타 방지는 기존 입력 가드를 활용.

### ② 상자 흔들림 · 봉인 해제 · 릴 공개

- 열기 이후 상자가 짧게 흔들리고, 상자 틈에서 빛/마법 에너지가 새어 나온다.
- 개봉과 함께 **마법진 또는 리본형 릴/슬롯이 회전**하며 보상을 가리는 시각적 기대 단계를 만든다.
- 릴이 멈추는 것과 실제 보상 지급 로직은 **분리**하고, 실제 판정에 없던 아이템이 얻어진 것처럼 보이게 하지 않는다.
- 스킵 가능하며 스킵하더라도 최종 획득 결과와 지급 횟수는 변하지 않는다.

### ③ 결과 공개 · 보상 수별 강약

| 실제 보상 | 공개 방식 | 시각적 강도 | 의도 |
|---|---|---|---|
| **1개** | 짧은 회전과 단일 빛 효과 후 즉시 보상 1개 표시 | 낮음·빠름 | 평소에도 개봉 만족감을 주되 반복 플레이를 방해하지 않음 |
| **3개** | 릴이 확장되거나 3개 슬롯이 차례로 확정; 순차 보상 공개 | 중간 | 예상보다 풍부한 보상을 받았다는 인지 |
| **5개** | 일반 상자처럼 시작 → 종료 직전 **마법진/릴이 추가 확장** → 5개 연속 공개, 강한 광채/시각 폭죽 | 최고·잭팟 | **미리 알려주지 않았던 반전**과 특별한 획득 순간 |

- **핵심 제안:** 5개 보상은 처음부터 다섯 칸을 보여주지 않는다. 일반 개봉처럼 시작해서, 끝나는 줄 알았을 때 슬롯이 추가 개방되는 **2차 확장/반전 연출**을 검토한다.
- 외형은 금속·목재의 사실적 표현보다 **2D 카툰/마법진/주문 에너지**를 지향한다.
- 보상 수에 따라 과장하되, **잦은 번쩍임·성능 악화·강제 긴 연출**은 피한다. 반복 플레이를 위한 빠른 진행/스킵을 둔다.
- 선행 보고서의 **1개 약 1초 / 3개 약 1.5초 / 5개 약 2.5초**는 테스트용 예시일 뿐 **고정 시간 승인안이 아니다**.

### ④ 결과 확정 · 인벤토리 확인 · 전투 재개

- 실제 획득한 **아이콘·마법/유물명·수량·합성 여부** 등 확인 가능한 정보만 명료히 표시한다.
- 1/3/5 보상은 **전부 획득하는 구조**다. 별도의 선택 카드 3중 1택으로 바꾸지 않는다.
- 일반 지급과 영구 첫 발견 알림은 구분하고, 같은 물품에서 큰 축하 효과가 이중으로 터지지 않게 중복을 합치거나 순서를 미룬다.
- 보상 완료 후 최신 승인된 **보상 획득 후 편집** 화면으로 이동. Tab 인벤토리/오브 편집이 필요한 시점에는 실제 `CompactInventory`를 사용한다.
- 인벤/오브 정리 후 **'전투 재개'** 직접 선택으로만 진행한다. 편집 시간 제한 없음.

## 5. 실제 화면 문구 원칙

문구 정책 [DEC-2026-10-31-02](../decisions/2026-10-31-battle-ui-copy-tone-no-cutesy-dialogue.md)에 따라 **'보물상자' / '열기' / '획득' / '전투 재개' / 실제 아이템 이름·수량** 같은 짧은 기능 라벨을 사용한다.

- '보물상자 발견!', '보물 획득!', '대박!', '축하해!' 같은 과장된 감탄형 문구는 **이전 설명용 도식에 사용됐더라도 실제 게임 UI 채택 금지**.
- 대신 3개/5개에 대한 축하 감정은 **릴의 변형·속도 변화·보상 수·시각 효과**에서 나오게 한다.
- 보상 릴이 보여주는 무작위 아이콘은 실제 획득 결과와 혼동되거나 가짜 신규 발견으로 보이지 않게 한다.

## 6. 구현 시 안전장치 및 검증 기준 (이번 작업에서는 미구현)

1. 1/3/5 보상 획득 수량과 슬롯 공개 개수가 실제 상태에 일치.
2. 결과 사전 노출 없음. 특히 **5개 전용 2차 확장**이 실제 5개에만 발생.
3. 스킵, ESC, 중복 클릭, 화면 크기 변경, 연속 개봉에서 중복 지급·결과 변경·보상 유실 없음.
4. `combat_rewards.gd`의 순차 후보 계산·무료 합성·부모 소비·최대 강화/재고 등 실 데이터 계약 유지.
5. 개봉 애니메이션이 전투 정지를 해제하지 않으며 '전투 재개' 전까지 시간·적·마법이 진행되지 않음.
