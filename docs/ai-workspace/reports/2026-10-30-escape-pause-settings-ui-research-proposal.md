## 1. ESC 메뉴와 설정 메뉴의 역할 구분

- **ESC 메뉴**는 전투를 멈춘 상태에서 **계속하기 / 설정 / 재시작 / 타이틀 복귀**를 쉽고 안전하게 선택하는 빠른 화면이다.
- **설정 화면**은 효과음·보상 연출·피해 숫자 등 플레이 편의/시각 요소를 실제 옵션에 맞춰 조정하는 화면이다.
- ESC는 기본적으로 **작고 명확한 팝업**, 설정은 항목 수가 늘어도 읽기 쉬운 **분류형 정보 화면**으로 구분한다.
- 지금 이미 `Tab`으로 가방·조합을 다루므로, ESC를 또 하나의 큰 장비/인벤토리 편집 화면으로 만들 필요는 없다.

### 실제로 개선할 필요가 있는 지점

1. **파괴적 행동 확인:** 전투 중 `처음부터 다시` 또는 `타이틀로`를 누르면 런이 정리되지만, 현재 ESC 버튼 경로에 별도의 확인 단계가 보이지 않는다. 전투 중 저장이 없으므로 **실수로 누를 위험**이 있다.
2. **버튼의 시각적 위계:** 현재 `계속하기` / `설정` / `처음부터 다시` / `타이틀로`가 동일한 작은 창에 있으며, 종료 성격의 두 행동을 명확하게 분리할 여지가 있다.
3. **ESC 안내 문구:** 현재 팝업에는 `주문이 복잡해졌다면 Tab으로 정리해봐. 전투 시간만 진행돼. 제작은 서두르지 않아도 돼.`라고 쓰여 있다. **일시정지 팝업에서 읽는 설명**으로는 '지금도 시간이 진행 중인지' 오해를 부를 수 있으므로 상황에 맞게 조정하는 것이 좋다. 이는 사용자 이해도에 대한 가설이며 실제 오인 사례를 측정한 결과는 아니다.
4. **설정의 공간 대비 정보량:** 현재 약 `1120×700`의 큰 패널 안에 실제 토글 3개와 비활성 음악 버튼 1개가 배치되어 있다. 정보 밀도/그룹화가 완성형 옵션 화면보다 임시 버튼 모음에 가깝다.
5. **실제 지원하지 않는 옵션:** 효과음 음량 슬라이더·화면 모드/해상도 선택·화면 흔들림·마법 투명도·키 재설정은 **현재 설정 UI에서 확인되지 않는다**. 단순 UI를 예쁘게 만든다고 작동하는 것처럼 표시하면 안 된다.

이 비교는 앞선 대화에서 검토한 UI 이미지·자료에 근거한다. **이번 문서 업로드 시 참고작 실행, 최신 버전 UI 재실측, 라이선스 이미지 반입은 하지 않았다.**

> 이전 조사에서 Brotato에 **런 이벤트 타임라인**이 2026년 2월 업데이트로 추가된 사례도 참고했으나, 이는 다른 게임의 기능이며 우리 게임에 타임라인 기능을 구현하자는 뜻은 아니다.

### ESC 공통 시사점

- 기본 목적은 **안전한 전투 복귀**이므로 가장 큰·가장 뚜렷한 버튼은 `계속하기`.
- 설정 및 조작법은 2차 작업.
- `처음부터 다시`, `타이틀로`는 런 진행을 종료하는 **위험성 있는 행동**이므로 주요 버튼과 분리.
- 현재 웨이브·전투 시간 등은 작은 요약만 있어도 충분하며 오브 상세 편집은 기존 `Tab` 시스템에 맡긴다.

### 설정 레이아웃 원칙

- 옵션 이름은 왼쪽, 실제 상태/슬라이더/토글은 오른쪽에 정렬한다.
- 선택/비활성/켜짐/꺼짐은 색뿐만 아니라 텍스트·컨트롤 상태로 구별한다.
- 설명 문구는 각 항목 아래 1줄 정도에 배치해 긴 설명으로 패널을 채우지 않는다.
- 기능이 없는 음량 슬라이더·화면 흔들림/마법 투명도 컨트롤을 이번 UI 개편만으로 **실행 가능한 옵션이라고 제시하지 않는다**.

## 5. 추천 ESC 구조 — 작은 중앙 팝업 유지

권장 조합: **Hades II의 중앙 메뉴 구조 + Brotato식 작은 현재 상태 요약 + Enter the Gungeon의 테마 장식**.

```text
┌─────────────────────── 잠시 쉬는 시간! ───────────────────────┐
│                                            Esc · 돌아가기     │
│ 루미의 실험                      현재 웨이브 · 전투 시간       │
│                                                              │
│                 [  계속하기  ]     ← 기본 강조               │
│                                                              │
│          [  설정  ]           [  조작법  ]                  │
│                                                              │
│──────────────────────────────────────────────────────────────│
│          [처음부터 다시]       [타이틀로]  ← 종료 계열        │
└──────────────────────────────────────────────────────────────┘
```

- 위는 **시각적 우선순위와 행동 구분을 보여주는 구조도**, 실제 Godot 좌표/확정 아트가 아니다.
- 현재 `500×370` 팝업을 기본으로 사용하되, 안전 문구/요약/확인 절차로 공간이 부족하면 최소 폭·높이만 증대 검토.
- **`조작법`**은 현재 ESC 메뉴에 없는 기능이다. 구현 승인 전에는 비활성으로 두거나 별도 제안으로 남긴다. 키 안내만이라면 별도 화면 대신 툴팁/짧은 도움말로도 가능.
- 종료/타이틀 버튼은 기본 선택이 아니라 보조·위험 영역에 배치.

### 5.1 위험 행동 확인창 — 높은 우선순위

```text
┌────── 현재 실험을 끝낼까요? ──────┐
│ 전투 중인 진행 상황은 저장되지 않아요. │
│                                   │
│ [ 계속하기 / 취소 ]  [ 종료 확정 ]  │
└───────────────────────────────────┘
```

- `처음부터 다시`와 `타이틀로`에서 **실행 전 확인**을 제안한다.
- 기본 포커스는 **취소/계속하기**로.
- 실제로 저장 가능한 범위를 코드와 맞게 안내: **제작 준비 체크포인트만 저장되며 전투 중 진척은 저장되지 않는다**.
- 재시작/타이틀 시 어떤 체크포인트가 남거나 소멸하는지까지 임의 추정하지 않고 실제 경로를 검증한 후 정확한 문구 확정.
- 해당 확인창이 **데이터 삭제/전투 정지·재개/키보드 포커스**에 오류를 만들지 않는지 승인 후 테스트 필요.
- 현행 `show_kits()` 및 `return_title()`의 상태 전이를 확인 후 연결해야 한다.

## 6. 추천 설정 구조 — 3개 그룹부터

현행 설정 수가 적으므로, **`일반 / 소리 / 화면·조작`** 정도의 세 그룹을 초기 설계 대안으로 권고한다. 현재 4개 버튼을 억지로 모든 카테고리에 나누기보다는 항목 수와 화면 밀도에 따라 **한 화면의 소제목 구획**도 비교 가능하다.

```text
┌───────────────────────── 환경 설정 ───────────────────────────┐
│ [  일반  ]    [  소리  ]    [ 화면·조작 ]                     │
├──────────────────────────────────────────────────────────────│
│  현재 선택한 분류                                             │
│  항목 이름 / 짧은 설명          [On/Off 또는 실제 작동 컨트롤] │
│  항목 이름 / 짧은 설명          [On/Off 또는 실제 작동 컨트롤] │
│  ...                                                         │
│                                                  [ 돌아가기 ] │
└──────────────────────────────────────────────────────────────┘
```

### 6.1 기존 옵션과 추가 제안의 구분

| 분류 | 항목 | 구현 상태 | 제안 |
|---|---|---|---|
| 일반 | 상자 개봉 생략 | **현재 구현됨** | 큰 버튼 대신 명시적인 토글 |
| 일반 또는 화면 | 피해 숫자 표시 | **현재 구현됨** | 현재 상태가 바로 보이는 토글 |
| 소리 | 효과음 켜기·끄기 | **현재 구현됨** | 라벨과 On/Off 상태를 분리 |
| 소리 | 배경 음악 | **현재 음원 없음·비활성** | 원본 음악 없이 BGM 설정을 활성화하지 말 것 |
| 소리 | 효과음 음량 슬라이더 | **현재 설정 UI 없음** | 별도 기능 구현·저장 계약 후 도입 |
| 화면·조작 | 화면/창 모드·해상도 | **현재 설정 UI 없음** | 렌더·창 모드·해상도 회귀 검증을 포함한 후속 과제 |
| 화면·조작 | 마법 이펙트 투명도/화면 흔들림 | **현재 설정 UI 없음** | VFX 가시성·성능 정책과 함께 후속 검토 |
| 화면·조작 | WASD/Space/Tab/Esc 조작 안내 | **메뉴형 도움말 없음** | 실제 키맵을 읽는 짧은 도움말 우선 |
| 화면·조작 | 키 재설정 | **현재 설정 UI 없음** | 입력 충돌·프로필 저장·컨트롤러 포커스 검증 후 별도 과제 |

- 새 설정을 만들더라도 플레이어가 **변경 후 그 결과를 즉시 이해할 수 있어야** 한다.
- 임시로 빈 탭과 작동하지 않는 슬라이더만 넣으면 설정 화면이 더 촌스러워질 가능성이 있다.
- 실제 옵션이 현재 3개뿐이므로 구현 1단계에서는 **기존 토글만 보기 좋게 배치**하고 분류형은 옵션 추가 시 확장하는 방법도 가능.

## 7. ESC/설정 복귀·입력 상태

```text
[전투]
   ├─ ESC → [일시정지]
   │             ├─ 계속하기 → [전투]
   │             ├─ 설정 → [설정(일시정지 출처)]
   │             │               └─ Esc/돌아가기 → [일시정지]
   │             ├─ 처음부터 다시 → [확인창 제안] → [시작 조합 준비]
   │             └─ 타이틀로 → [확인창 제안] → [타이틀]
   ├─ 개인 가방 중 ESC → [가방 닫기], 이후 ESC → [일시정지]
   └─ 마법 드래그 중 ESC → [드래그 취소], 이후 ESC → [일시정지]

[타이틀] → [설정(타이틀 출처)] → Esc/돌아가기 → [타이틀]
[시험 발사] → Esc → [제작 준비]
```

주의:
- `설정(일시정지 출처)`에서 돌아올 때 전투가 **자동 재개되면 안 됨**. 현행 `settings_pause` 분기는 일시정지 메뉴로 복귀하도록 작성되어 있다.
- ESC의 현재 상태 우선순위: 전면 화면(설정 등) → 드래그 → 개인창 → 전투 일시정지/재개 → 편집/시험 복귀. 새 확인창 추가 때 이 입력 분기를 무너뜨리지 않는다.
- 보상 선택으로 전투가 멈춘 경우와 일반 ESC 일시정지의 우선순위도 별도 확인 필요. 기존 `combat_rewards.paused()` 분기가 있다.
- 전투 시간·적 발사·카메라·이펙트 업데이트가 **실제 일시정지 상태에서 멈추는지**는 단순 함수 확인으로 완료 판정하지 않는다.
- **타이틀에서 설정을 열었을 때만 타이틀로 복귀**, 일시정지에서 열었을 때는 전투가 아닌 일시정지로 복귀하도록 보존.

## 9. 권장 작업 우선순위 (사용자 승인 후)

1. **런 종료 위험 행동 확인창**: 다시 시작 / 타이틀 진입 전 안전 안내·취소 기본 선택.
2. **ESC 버튼 위계 재배치**: 계속하기 최상위, 설정/조작법 보조, 런 종료 행동 하단.
3. **설정 화면 재배치**: 실제 있는 토글 3개를 의미 있는 행으로 정리하고 관련 항목을 그룹화.
4. **화면·음량 옵션 추가 검토**: 기능/저장/해상도/성능 구현은 별도 승인·검증이 필요.
5. **미술 마감**: 기존 프로젝트의 둥근 카툰 스킨과 톤을 맞추고 구매 GUI 적용 여부는 별도 판단.

### 9.1 Godot 검증 체크리스트 — 이 보고서에서는 실행하지 않음

- `1280×720`, `1600×900`, `1920×1080` 실렌더에서 메뉴/토글/확인창의 겹침 및 가독성 확인.
- 전투 중 ESC → 설정 → ESC → 일시정지 → 계속하기 순서에서 **타이머·적·마법 상태**가 올바르게 유지.
- 타이틀 설정 → ESC가 타이틀로 돌아가는지, 설정을 닫는 것만으로 새 런이 시작되지 않는지.
- 드래그 중 ESC, 개인 가방 열린 상태 ESC, 보상 일시정지 중 ESC, 시험장 ESC 경로가 기존처럼 작동하는지.
- 재시작/타이틀 확인 창에서 취소/확정·연속 클릭/키보드 Enter/ESC 및 GUI 포커스가 정상 동작하는지.
- 선택한 옵션이 즉시 반영되고 프로필에 보존되며, 기존 저장이 손상되지 않는지.
- 실제 음악이 없을 때 음악 버튼은 비활성이며 음원이 나오는 것처럼 표시하지 않는지.
- 전투 중 새 저장 기능을 암시하지 않으며, 종료 경고가 실제 체크포인트 정책과 일치하는지.
- UI 변경 후 전투 HUD·보상·타이틀·도감·실험 기록 등 다른 메뉴에 입력 충돌이 없는지.
- **정적 분석 / 자동 테스트 / Godot 실제 입력·화면 검사 / 사용자 미관 평가**를 서로 구분해 기록.

## 11. 미확정 사항 및 이번 작업 결과

### 사용자 검토가 필요한 선택
- ESC 메뉴에 **현재 웨이브/빌드 요약을 얼마나 넣을지**.
- `조작법` 버튼을 별도 추가할지, 짧은 키 가이드만 노출할지.
- 확인창 대상 문구/저장 관련 설명과 취소·확정 행동.
- 설정을 **3탭 분류형**으로 할지, 적은 옵션에 맞춰 **한 페이지 3개 구역형**으로 시작할지.
- 새 음량·그래픽·VFX 조절을 후속 범위에 넣을지.
- 최종 카툰 스타일의 장식/캐릭터 삽화 범위.
