## 1. 플레이어 관점의 결과와 독립적 완료 기준

- **유효하지만 상쇄된 조합:** 장착 상태 그대로 자동 발사 가능. 효과를 잃는 **해당 보조 구체의 슬롯 모서리에 노란 경고**를 표시하고, 마우스를 올리면 `추적이 공전에 의해 무효화됩니다. 공전 이동은 정상 발동합니다.`처럼 **원인·상쇄된 효과·실제 적용되는 효과**를 보여준다.
- **실행 불가능한 조합:** 발동 불가능한 연결/보조/공격 슬롯에 **빨간 경고**를 표시한다. `연결 뒤에 공격 구체가 없어 이 연결이 발동하지 않습니다.`처럼 수정할 수 있는 설명을 제공한다. **정상 구성의 다른 공격·오브는 그대로 발동**한다.
- **상쇄 없음:** 아이콘을 나타내지 않는다. 조합이 특이하거나 위력이 약하거나 현재 주변에 적이 없다는 사유만으로 경고를 만들지 않는다.
- 4오브, 독립 루트, 연결 앞뒤 범위, 강화 0~3, 합성 보조, 중복 보조, 슬롯 이동·교환·제거·초기화·저장/복원·훈련장에 모두 같은 규칙을 사용한다.

## 2. 우선순위와 판정 의미

| 구분 | UI | 판정 기준 | 차단 여부 |
|---|---|---|---|
| `ERROR / INACTIVE` | **빨간 느낌표/경고 삼각형** | 해당 슬롯의 주문 또는 연결이 **구조적으로 실행 불가**. 예: 연결 앞 공격 없음, 연결 뒤 공격 없음, 공격 없이 보조만 남음, 연속 연결, 알 수 없는 ID | 해당 부분은 원래 불발. **다른 정상 경로는 차단 금지** |
| `SUPPRESSED` | **노란 느낌표/경고 삼각형** | 문법적으로 유효하나 같은 공격 단계에서 **다른 보조가 우선해 한 보조의 핵심 이동·방출·파생 행동이 사라짐**. 실질적 무효/부분 무효를 모두 이유와 함께 명시 | **경고만**, 조합/시전 차단 없음 |
| `NONE` | 아이콘 없음 | 정상 조합 또는 아직 근거가 부족한 상호작용 | 없음 |

**동일 슬롯에 빨강·노랑이 동시에 발생하면 빨강 아이콘을 보여주고 툴팁에 두 근거 모두 남긴다.** 경고 색상만으로 구분하지 말고 아이콘 모양과 `상쇄됨`/`작동 안 함` 텍스트를 제공한다. 밝은 UI·어두운 UI 모두 가독성 검사.

검사 불가능한 경우는 `미검증`으로 남겨야 하며 **임의로 빨강 경고를 띄우지 않는다**. 현재 적이 멀리 있거나 적이 없어 도탄하지 못하는 등 **전투 상황 의존성**은 정적 조합 불가와 구분한다.

## 3. 구현 기준 소스 — 이미 존재하는 진단 재사용

- [`scripts/spells.gd`](../../../scripts/spells.gd): `compile(recipe)`가 `diagnostics[{slot,code,reason,severity}]`와 `slot_diagnostic`를 생성한다. 현재 `unknown`, `missing_source`, `missing_payload`, `broken_chain`, `inactive_source`, `blocked_payload`, `unused_modifier` 등이 있음. **현재 상쇄 검사는 없음**.
- [`scripts/prep_board.gd`](../../../scripts/prep_board.gd): `cell()`의 `orb>=0` 분기에서 `Spells.compile(orb_drafts[orb])` 결과를 슬롯별로 읽고 `!` 아이콘과 툴팁을 표시한다. 현재 `severity=="inactive"`는 별도 메타만 주고 나머지는 분홍색 경고로 그려서 **노랑/빨강 분리 미구현**.
- [`scripts/prep_slot.gd`](../../../scripts/prep_slot.gd): `invalid`, `inactive`, `affected` 메타를 기준으로 슬롯 테두리·배경을 그린다. 색을 넣을 때 실제 가방과 슬롯 공통 스타일을 확인할 것.
- [`scripts/training_room.gd`](../../../scripts/training_room.gd): 편집 가능한 4오브 슬롯이 `Board.cell()`을 재사용하므로 **공통 진단으로 훈련장에도 표시**한다.
- [`scripts/magic_extensions.gd`](../../../scripts/magic_extensions.gd) `motion()`: `seek`, `orbit`, 합성 추격/공전의 이동 방식을 순서대로 훑어 **나중 등장한 방식이 최종 선택**된다.
- [`scripts/spell_runtime.gd`](../../../scripts/spell_runtime.gd): 직선/유도 이동 후 공전 이동일 때 좌표를 원 위로 강제하며, 도탄 경로 변경도 이어지는 프레임의 공전으로 덮일 수 있다.
- [`scripts/modifier_effects.gd`](../../../scripts/modifier_effects.gd): 갈래·관통·거대화·분열 등에 실제 수치 효과가 남아 있을 수 있어, **상쇄와 부분 상쇄를 구분**해야 한다.

마법공예 참고 근거: [Magicraft SteamDB 2025-02-10 패치](https://steamdb.info/patchnotes/17290567/)는 `Spell disable UI fine tuning`을 기록한다. 이는 **비활성 UI가 있었다는 제한된 근거**일 뿐 빨간색 아이콘의 정확한 형태나 위치를 검증한 화면 자료는 아니다. 원작 경고 그림을 복사하지 말고 기능적 역할만 참고한다.

## 4. 대표 조합과 기대 진단 — 별빛탄

**여기에 실린 동작은 코드 검토에 따른 기대 결과**이며 이번 문서 작성 단계에서 새 Godot 재현을 수행하지 않았다.

| 구체 순서 (왼쪽 → 오른쪽) | 현재 런타임 근거/기대 | 경고 대상 | 표시 |
|---|---|---|---|
| `추적 → 공전 → 별빛탄` | 공전이 최종 이동 모드. 적 방향으로 꺾는 추적 기능은 실행되지 않음 | **추적 슬롯** | **노랑** |
| `공전 → 추적 → 별빛탄` | 추적이 최종 이동 모드. 별빛탄의 원형 공전 행동이 실행되지 않음 | **공전 슬롯** | **노랑** |
| `갈래 → 공전 → 별빛탄` | 3발은 생성되지만 개별 출발 방향이 공전 위치 갱신에 의해 덮임. **발사 수 증가 자체는 남음** | **갈래 슬롯** (`갈래 궤적 상쇄 · 3발 생성은 유지`) | **노랑/부분** |
| `도탄 → 공전 → 별빛탄` | 도탄 경로 변경을 해도 공전 좌표 갱신이 진행 방향을 덮음. 다음 적이 있어야 도탄 이벤트 자체는 발생 | **도탄 슬롯** (`방향 전환 부분 무효`) | **노랑/부분** |
| `분열 → 공전 → 별빛탄` | 자식 별빛탄의 개수는 늘지만 분산 방향은 자식이 물려받은 공전 이동에 덮일 수 있음 | **분열 슬롯** (`분산 궤적 무효`) | **노랑/부분**, 실제 자식 궤도 테스트로 확정 |
| `복제 궤적 → 궤도 잔영 → 별빛탄` | 두 복제 계열이 같은 이동거리 이벤트에 걸려 중복/대체 가능. **실제 상쇄량 미검증** | 정적 확정 경고 보류 | **미확정** |
| `갈래 → 추적 → 별빛탄` | 3발이 같은 적 쪽으로 모일 수 있으나 **갈래 발사와 추적 모두 정상 작동** | 없음 | 없음 |
| `관통 → 도탄 → 별빛탄` | 관통 잔여 횟수를 소모한 뒤 도탄. **효과가 지연될 뿐 두 보조가 발동 가능한 조합** | 없음 | 없음 |
| `메아리 → 분열 → 별빛탄` | 메아리 파생탄은 재분열하지 않도록 제한되지만 원본에서 메아리·분열이 각각 작동함. **무한 재귀 방지 규칙** | 없음 | 없음 |
| `갈래 → 관통 → 거대화 → 별빛탄` | 3발·관통·크기 증가가 실제 발사 구조에 반영 | 없음 | 없음 |
| `갈래` 단독 | 적용할 공격이 없어 미사용 | 갈래 슬롯 | **빨강** |
| `명중 후 → 별빛탄` | 연결 앞 공격이 없음 | 명중 후 슬롯 | **빨강** |
| `별빛탄 → 시간 트리거` | 뒤쪽 후속 공격이 없음 | 시간 트리거 슬롯 | **빨강** |
| `별빛탄 → 명중 후 → 소멸 후 → 꽃폭탄` | 공격 없는 연속 연결: 후속이 비활성화될 수 있음 | 관련 연결/후속 슬롯 | **빨강** |
| `별빛탄` 단독 | 정상 탄환 | 없음 | 없음 |

**유의:** `갈래/분열/도탄 + 공전`의 '일부 상쇄'는 **수량/피해는 남는 부분 상쇄**다. 빨간 '완전 작동 안 함'으로 처리하면 안 된다. 특히 `분열`은 자식 생성·앵커 등을 엔진으로 재현해 최종 조건을 고정한다. '다른 적을 추적하지 못한 갈래' 같은 환경 의존 상황은 경고가 아니다.

## 5. 진단 데이터 모델 권고 (게임 규칙이 아닌 UI 구현 선택)

현재 컴파일 오류가 `ok=diagnostics.is_empty()`로 결정되는 구조이므로 노란 `SUPPRESSED`를 **기존 `compile().diagnostics`에 무조건 끼워 넣지 않는다**. 그러면 유효한 경고 조합도 `ok=false`가 되어 시전·편집·구매가 막힐 위험이 있음.

권장 분리 구조:
- `compile().diagnostics`: 기존 실행/구문 문제만, 현행 부분 실행 의미 유지.
- `analyze_suppression(recipe,compiled)` 또는 별도 `advisories`: `[{slot,other_slot,attack_slot,code:"motion_overridden",severity:"suppressed",extent:"full|partial",reason:"...",effect_lost:"...",effect_kept:"..."}]`.
- UI: `slot_diagnostic`의 빨간 항목과 `advisories`의 노란 항목을 **슬롯별 병합**해 심각도 우선순위 **빨강 > 노랑 > 없음**으로 렌더링. 단일 아이콘 + 클릭/호버 툴팁에 모든 원인과 보조 영향을 표시.
- 코드는 모든 20종 보조 쌍을 수동 열거할 필요 없이 우선 **이동모드(추적/공전/추격 관통/궤도 잔영)**, **방향 우선권(갈래/분열/도탄 vs 공전)** 등 원인별 룰 그룹을 둔다. 유사한 합성 보조에도 자동 적용.
- 루트가 둘 이상이면 **보조가 실제로 적용되는 각 공격 단계별로 검사**한다. 한 공격에선 상쇄되고 다른 공격에선 유효하면 `일부 공격에서만 상쇄`라고 안내한다. 다른 오브에 있는 보조끼리는 상쇄 경고를 만들지 않는다.
- 저장에는 경고 결과를 지속 저장하지 말고 레시피 수정·강화·복원에 따라 **컴파일에서 재계산**하는 방식 권장.
- 렌더링은 기호/색이 깨지지 않는 아이콘(예: 삼각형 + !)을 기존 슬롯 모서리에 중첩. 색맹·작은 슬롯 대응을 위해 툴팁 제목 `[상쇄됨]`/`[작동 안 함]` 병기. 제안 색상값은 노랑 `#F6C453`, 빨강 `#F07886`이며 **정확한 HEX는 사용자 미확정**.
- 정적 분석의 한계: 타격 후 도탄 대상이 없는 일시적 상황, 시전 지연으로 인한 미명중, CPU 상한으로 인한 런타임 차단 등은 정적 '상쇄' 판정 대상이 아니다. 런타임 진단은 별도 기록/검증.

## 6. 검증 목록 (Codex에게 전달할 수 있는 수용 조건)

1. 대표 3조합 `추적-공전-별빛탄`, `공전-추적-별빛탄`, `갈래-공전-별빛탄`: 해당 보조 슬롯에 **노란 아이콘만**, 원인과 살아 있는 효과의 명시, 장착·시전 성공.
2. `갈래` 단독, `명중 후-별빛탄`, `별빛탄-시간 트리거`: 해당 슬롯에 **빨간 아이콘**, 원인 안내, 구조적으로 유효한 다른 루트는 정상 발사.
3. `갈래-관통-거대화-별빛탄`, `갈래-추적-별빛탄`, `관통-도탄-별빛탄`: **오탐 노란 경고 0**.
4. `추적-공전`과 `공전-추적`은 **각각 다른 슬롯**에 경고가 붙는다. 순서가 바뀌면 판정도 동적으로 갱신한다.
5. 경고 슬롯이 강화/선택/드래그/교환/해제/리셋/저장/불러오기 되었을 때 stale 아이콘이 남지 않는다. 4오브를 각각 독립 검사한다.
6. 기존 적색 진단과 노란 진단이 같은 슬롯에서 만나면 **빨강 하나**로 표시하되 원인은 툴팁에 보존한다.
7. 공통 UI 슬롯 **편집창·훈련장** 및 축소 UI에서 아이콘이 슬롯 텍스트/강화표시를 가리지 않고 올바른 색상으로 보이는지 실제 **Godot 화면/마우스 입력** 검사.
8. 기존 **부분 실행**/시전 가능 여부, 최대 8칸, 보조의 오른쪽 범위/연결 경계, 저장 호환, 경제·밸런스가 그대로 유지되는지 검증.
9. 컴파일 정적 검사뿐 아니라 실제 엔진에서 공전과 추적 우선권·갈래 생성 수·분열 이동을 관찰하며 진단 문자열의 사실 여부 대조.
10. 이 보고서의 사례는 **초기 회귀 집합일 뿐 190개의 모든 보조 쌍 실측 완료가 아니다**. 향후 자동화에서 20종 기본 단계 쌍과 대표 3종을 스캔해 누락/오탐을 보고서로 축적.

## 7. 미확정/미실행과 개발 인계 기준

- **확정:** 노랑 = 상쇄, 빨강 = 작동 불가, 마법공예 UI의 비활성 안내는 참고, 노란 안내는 우리 기능.
- **제안:** 정확한 경고 조건, 부위별 강조, 경고 아이콘 위치, 세부 문구/HEX, 분석 API.
- **검증 안 됨:** 이 작업에서 새 Godot 테스트·시각 확인·190쌍 전수 검사·브라우저 검사·실제 구현은 수행하지 않음.
- **금지:** 상쇄 효과를 새로 설계하거나, 발사 동작을 바꾸거나, 단순히 무피해인 조합을 '비작동'으로 판정하거나, 노란 경고 때문에 `valid_draft()`를 false로 만드는 변경. 마법 자체를 고치는 것은 별도 승인 및 테스트가 필요하다.
