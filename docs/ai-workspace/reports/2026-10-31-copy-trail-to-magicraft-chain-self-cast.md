## 1. 핵심 결정 — '연쇄의 발동 방식'은 사용하되 '발사 대상'을 교체

현 보조 **복제 궤적** (`trail`)을 현재의 “일정 이동 거리마다 약한 잔상 복제” 기능에서 **마법공예 연쇄식 이동 중 추가 시전**으로 교체한다.

| 구분 | 마법공예 원작 「연쇄」 (3203) | 우리 게임 교체 목표 |
|---|---|---|
| 발동 시점 | **부모 주문이 이동하는 동안** 조건 충족 | **부모 주문이 이동하는 동안** 조건 충족 |
| 발사 주체·위치 | 움직이는 **부모 주문 자체**의 현 위치 | 움직이는 **부모 마법 자체**의 현 위치 |
| 발사 대상 | 뒤에 연결된 **하위 주문(SubGroup)** | **바로 그 부모 마법의 공격형태·속성을 복제한 자식 주문** |
| 본질 | `A —[연쇄]→ B` | **`A —[연쇄]→ A′`** |
| 기존 궤적 복제 | 이동 거리 90마다 총량 제한 복제, 약한 잔상 | **그 방식으로 대체 구현하지 않는다. 새 주문 발사 이벤트로 취급** |
| 후속 연결 | 원작에서는 연결된 하위 주문을 쏜다 | **별도의 후속 슬롯이 없어도 자체 복제가 가능해야 함** |

**중요:** “연쇄”를 적 A→B→C로 피해가 전달되는 도탄/감전 연쇄로 구현하는 것이 아니다. **부모 주문에서 또 하나의 동일 계열 주문이 실제 발사되는 구조**다. “자신을 다시 발사”는 시전자(플레이어)의 위치에서 다시 시전한다는 뜻이 아니라 **움직이는 부모의 위치에서 별도 주문체를 방출**한다는 뜻이다.

현재 카드의 사용자 표시 이름은 **「연쇄」**로 교체하는 방향이며, 내부 식별자 `trail`은 기존 카드·강화·저장 호환을 위해 우선 보존하는 구현 권고다. 새 내부 ID 변경은 별도 마이그레이션 필요 시에만 한다.

## 2. 원작 구현 확인 — 사실과 우리 변경안을 구분

원작 PC 역컴파일 자료에서 「연쇄」는 `SpellAbilityType.OnMoveTrigger = 3203`이며, 원작 구성 단계는 **3레벨**: `32031/32032/32033`.

- **원작 발동 조건:** `SpellMoveTriggerSystem.OnUpdate`에서 마법이 움직인 **속도 × Δt**를 `DistanceCounter`에 누적한다. **Rotation 이동 타입은 이 누적에서 제외**한다. 부모에 유효한 하위 그룹(`SubGroupEntity`)이 있어야 하며, 화면 범위·지팡이 마나 조건도 검사한다. 일반적으로 실제 적 명중이나 부모 소멸이 아닌 **이동 도중의 거리 조건**이다.
- **원작 간격:** `ShootSpellUtils.SipToSSP`에서 `TriggerDistanceRatio = 같은 그룹 OnMoveTrigger.float1 합계`, `SubGroupMpCost = 하위 그룹 최종 마나 비용 × (같은 종류 트리거 int1 최솟값 / 100)`. 필요한 이동 거리는 **`SubGroupMpCost / TriggerDistanceRatio`**. 3203의 `float1`은 레벨별 **4 / 6 / 9**, `int1`은 **70 / 55 / 40**. **이를 우리 게임의 '4/6/9발' 또는 '70/55/40px'로 오해하지 말 것.** 조건 달성 시 마나를 실제로 소모하고 다음 하위 주문을 발사한다.
- **원작 발사 방향:** 부모 진행 방향에서 **좌우 90°로 번갈아**, 시작 편향은 임의 선택. 부모 현재 위치에서 `ShootSpellBuffer.ShootByTrigger()`로 하위 그룹을 발사한다. 이 동작은 원작의 핵심 특징이므로 우리 자체 복제에서도 방향 계약의 **우선 기준**으로 삼는다.
- **원작 개수:** 이동량·하위 그룹 마나 비용·남은 마나·기타 조건에 따라 결정된다. 레벨별 고정 2/3/4/5회로 단정할 수 없다.
- **원작 근거 출처:** [SpellMoveTriggerSystem.cs (발동과 ±90°)](https://github.com/kav1982/_reverse_engineering/blob/main/decompiled/Assembly-CSharp/SpellMoveTriggerSystem.cs), [SpellMoveTriggerComponentData.cs](https://github.com/kav1982/_reverse_engineering/blob/main/decompiled/Assembly-CSharp/SpellMoveTriggerComponentData.cs), [ShootSpellUtils.cs (마나·거리비율 구성)](https://github.com/kav1982/_reverse_engineering/blob/main/decompiled/Assembly-CSharp/ShootSpellUtils.cs), [ShootSpellBuffer.cs](https://github.com/kav1982/_reverse_engineering/blob/main/decompiled/Assembly-CSharp/ShootSpellBuffer.cs), [SpellAbilityType.cs](https://github.com/kav1982/_reverse_engineering/blob/main/decompiled/Assembly-CSharp/SpellAbilityType.cs), [SpellConfig 수치표](https://github.com/kav1982/_reverse_engineering/blob/main/%E6%B3%95%E6%9C%AF%E6%95%B0%E5%80%BC%E6%80%BB%E8%A1%A8.md).
- 이 코드는 **제3자 역컴파일**로, 공식 엔진 소스·우리 게임 실행 실험이 아니다. 기계적 작동 원리를 참고하되 원작 코드·에셋을 그대로 반입하지 않는다.

### 우리 게임으로 바꿀 때 원작과 달라지는 계약

1. **후속 그룹 필수 조건을 제거.** `A+연쇄`만으로 `A′`가 나와야 한다. `A→연결→B` 같은 별개의 사용자 연결은 **A의 복제 대상이 아니며, 그 연결 체인 자체를 복사하면 안 된다**.
2. **자체 공격 복제 생성.** 실제로 부모와 같은 공격 종류·현재 적용된 유효 보조 속성을 가진 **새로운 공격체**가 부모 현 위치에서 출발한다. 단순 VFX/장판 도장찍기/피해 숫자만 생성하는 가짜 복제를 금지한다.
3. **좌우 교대 발사**(원작 `±90°`)를 기본 제안. 나가는 방향은 부모의 현재 진행·접선 벡터를 기준으로 하고, 시작쪽은 난수 또는 결정적 시드로 재현 가능하도록 한다.
4. **재귀적 복제 금지**를 안전 기본안으로 제안한다. 자식은 `연쇄`를 다시 발동하지 않으며, 메아리·분열·후속 연결 등 추가 생성권한을 어디까지 승계할지 별도 충돌 검증 후 확정한다. 현행 `derived()`가 원소·연결·복제 등을 제거한다는 사실과 "원본의 복제" 요구를 혼동하지 말 것.
5. **이동 중 거리 조건 유지.** 기존 90px 고정, 일정 횟수 후 반드시 정지라는 **옛 복제 궤적 규칙을 그대로 유지하면 안 된다**. 원작은 비용/거리비율 모델이므로 **우리 게임에 없는 지팡이 마나 비용의 대체 요소와 강화별 발동 밀도**는 별도 밸런스 제안·검토 항목이다.
6. **부모의 충돌·죽음과 무관하게** 이동 중 조건에 도달하면 새 자식을 발사한다. 실제 부모가 사라지면 더 이상 부모 기준의 후속 방출은 일어나지 않는다. 비정상 취소·세대 종료 후 예약 방출도 없어야 한다.

## 4. 구현 담당자가 지킬 구체적 완료 기준

1. **기본 대표 사례:** `연쇄 + 별빛탄(bolt)`. 부모가 이동하는 도중 발사 지점이 부모와 함께 이동하며, 자식은 **같은 별빛탄**으로 실제 비행·적 충돌·피해를 준다. 별도의 후속 공격 카드가 없어도 동작한다.
2. **진행 방향:** 부모가 오른쪽으로 날면 자식은 원작식으로 위쪽/아래쪽(진행 방향 기준 `±90°`)으로 번갈아 나가는지 시각·탄도·실제 피격을 확인한다.
3. **이동/정지:** 부모가 실제로 이동하지 않으면 정해진 거리 누적이 없어야 한다. 작은 프레임/큰 프레임, 30/60/120Hz에서 일정 **이동량** 대비 발동 횟수가 같은지 확인한다.
4. **자체 주문 복제:** 화염구·광선·관통·추적·화상·분열 등의 대표 보조와 결합해 **그 공격의 본래 성질**이 살아 있는지 확인한다. 재복제·동일 프레임 폭발적 발사·후속 연결의 중복 실행은 경계한다.
5. **특수 공격:** 공전·위성·서리 계열·잔불 발자국·레이저·화염방사기·낙하처럼 이동/시작 위치가 다른 공격은 "모든 마법에서 그대로 동작"이라고 미리 선언하지 않는다. 실제 발사 위치/동작/피해를 개별 확인하고 불가능한 경우 사용자에게 예외를 보고한다.
6. **합성 유지:** `mirror_trail`·`orbit_afterimage`의 레시피 표시·완성 마법 성질이 기존 `trail` 교체 후 조용히 사라지거나 잘못 중복 발동하지 않아야 한다.
7. **종료/성능:** 부모 파괴·웨이브 종료·게임오버·장면 전환 시 지연 예약 0. 생성 상한·초당 생성량·300적 4오브에서 **실제 자식 누락/피해량/프레임** 확인. 제한을 걸어 기능이 조용히 안 나가면 미완료.
8. **증거 수준:** 소스 수정/구문 통과/자동 테스트/실제 전투 피격/화면 VFX/성능/체감 각각 따로 기록.

## 5. 아직 확정하지 않은 사항 (임의로 수치 확정 금지)

- **강화 0~3단계의 발동 거리·빈도·회수 제한.** 원작은 3단계이고 마나 비용으로 간격을 결정하므로 우리 4단계에 숫자를 그냥 복제할 수 없다.
- **자식별 피해 배율·반경·수명·중복 적용 시 계산 규칙.** 기존 20%/2~5개는 **기존 코드의 현상**이지 새 연쇄의 승인 수치가 아니다.
- **원작식 ±90°를 최종 고정할지, 최초 각도·방향 난수 정책.** 기본 구현 방향은 원작 재현이지만 UI/사용자 직접 시험 후 확정 가능하다.
- **위성/공전 Rotation, 레이저 등 비일반 이동 마법의 적용 범위.** 원작의 비적용 동작을 우리 게임에 그대로 가져올지 별도 판단.
- **복제본이 다른 공격형태의 고유 합성 능력까지 상속하는 범위**와 기존 완성 합성 2종의 신규 행동.

## 6. 명시적 작업 금지·인계

- 이 보고서는 **사용자 승인한 기능 방향**을 코드 담당에게 전달하는 문서이고 **코드 구현 요청이나 구현 완료 기록이 아니다**.
- **지금은 리포트·인덱스만 업데이트**한다. 사용자가 별도 **“코드 수정해/구현해”**라고 지시할 때까지 게임 파일·테스트·VFX·배포 파이프라인은 보존한다.
- 기존 메아리(`echo`), 분열(`split`), 소멸 후(`expire`), 연쇄라는 말이 붙은 다른 합성/연결과 혼동하여 교체하지 않는다.
- 원본 역컴파일 저작권/저장소 라이선스를 존중한다. 동작 원리만 참고하고 소스 원문이나 추출 아트를 복제하지 않는다.

**결론:** 마법공예의 연쇄를 **단순 이동 중 잔상 복제가 아닌 '이동 트리거 기반 후속 주문 발사'로 재현**하되, **후속 주문 대신 부모 자신을 복제해 독립 발사**하는 방향을 확정. 세부 수치는 **미확정**이다.
