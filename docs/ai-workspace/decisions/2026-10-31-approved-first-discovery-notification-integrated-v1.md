## 채용된 12번 디자인·동작 범위

1. **영구 첫 발견만** 식별한다. 현재 플레이에서 처음 소지한 것과 영구 프로필의 `discovered_spells`, `discovered_fusions`, `discovered_relics`에 한 번도 등록되지 않았던 것은 다르다. 같은 종류 재획득, +1~+3 강화, 획득 전 미리보기, 실패한 합성, 체크포인트 복원/과거 기록 이관/훈련 측정에 신규 발견 연출 금지.
2. **기본 마법 첫 발견:** 이미 승인된 보상/획득 카드 안에 작은 **`신규 마법`** 표식과 실제 마법 아이콘/이름. 기본적으로 별도 토스트·새 모달·전투 강제 정지를 추가하지 않는다.
3. **유물 첫 발견:** 유물 획득 화면에 **`신규 유물`** 표식, 실제 아이콘/이름. 지급이 확정된 다음에만 출력하고 유물 후보 카드 탐색을 발견으로 오인하지 않는다.
4. **완성 합성 첫 발견:** 기존 합성 완료/상자 획득 연출 안에서 **`신규 합성`** 표식, 일반 마법보다 큰 실제 아이콘과 짧고 절제된 반짝임/강조. 원래 보상/합성 연출이 있는데 별도 전체화면 컷신·두 번째 장황한 축하 토스트를 중복 추가하지 않는다.
5. **문구:** 기존 사용자 확정 시스템 UI 정책에 따라 짧은 사실형 라벨(`신규 마법`, `신규 합성`, `신규 유물`, 실제 이름) 사용. `도감에 기록 완료`는 실제 저장 성공을 확인하지 않은 채 표시하지 않는다.
6. **여러 건 동시 획득:** 정확히 새로 발견한 ID를 기준으로 묶음/짧은 대기 처리하여 중복·소실·전투 가림 방지. 각각의 종류·이름은 나중에 확인 가능해야 하나, 정확한 큐/시간은 미확정.
7. **발견 도감 `NEW` 읽음/안읽음 배지:** **후순위·이번 1차 채용 범위 밖**. 현재 프로필에는 `discovered_*`만 있고 미열람 상태가 없으므로 임의로 NEW 개수/영구 유지 UI를 만들지 않는다. 추후 구현 시 저장 필드/마이그레이션/읽음 처리 별도 설계·승인.
8. **기존 시스템 보존:** 발견/획득 UI 변경만으로 드롭, 합성 경제, 영구 마법 해금, 유물 수치, 게임 진행·일시정지, BGM 정책을 변경하지 않는다.

## 구현 전에 확인할 사항

- `scripts/player_profile.gd::discover(parts,relic_ids)`는 현재 bool만 반환하므로 **전후 영구 발견 목록의 차이 또는 신규 ID 반환**으로 정확한 최초 발견 ID를 전달할 필요가 있다. 유일 ID/기본 ID 정규화 및 프로필 저장 오류를 별개로 처리한다.
- `scripts/game.gd::claim_fusion()`의 성공 경로, `scripts/combat_rewards.gd::finish_award()`, 일반 `receipt()`, 유물 `acquire_relic()` 등이 서로 다른 타이밍·문구를 가지므로 실제 획득 **확정 뒤에만** 통합 강조하고 중복 축하 금지.
- 화면 가림·전투 입력·보상 선택 정지·상자 공개와 경합, 1280×720/1600×900/1920×1080, 재실행·복원 후 재축하 방지를 Godot 실제 실행으로 검증. **이번 결정 작업에서 테스트 수행하지 않음**.
- **10번 웨이브·보스 등장 추가 UI는 사용자 보류(DEFERRED)**이며, 12번 알림을 위해 재도입하지 않는다.

**결론:** 별도의 발견 전용 화면 프로젝트를 만들지 않고, **기존 획득/합성/유물 카드에 영구 첫 발견 여부를 작은 배지로 붙인다. 완성 합성만 시각적으로 조금 더 강조한다.**
