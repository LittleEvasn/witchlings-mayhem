## 사용자 확정

1. 기존 완성 합성 **천둥 인장(`thunder_seal`)**의 **낙뢰 지점에 설치되어 접촉 시 터지는 인장** 기능을 **체인 라이트닝(Chain Lightning / 연쇄 번개)**으로 교체한다.
2. 재료는 지시가 없으므로 **벼락(`thunder`) + 명중 후(`impact`)**를 유지한다. 내부 합성 ID `thunder_seal`은 세이브/도감 호환상 유지 권고, 최종 ID 변경 지시 없음.
3. **벼락에 최초로 맞은 적**을 기점으로 번개가 **새로운 주변 적에게 순차적으로** 전이한다. **최초 1명 이외 추가 전이 대상 4~5명**, 최대 **서로 다른 적 총 5~6명**이다. 직전 제안의 “주변 적 4~5명”을 사용자가 승인한 것으로 기록한다.
4. 번개 줄기는 적→다음 적→그다음 적으로 **실제 경로와 순서에 맞춰 연결**, 각 적에게 실제 피해를 준다. 최초 중심에서 여러 갈래를 동시에 긋고 동시 AoE를 적용하는 방식으로 대체하지 않는다.
5. **동일 체인의 이미 타격한 적에게 다시 전이하지 않는다.** 유효한 주변 적이 부족하면 가능한 만큼만 맞히고 종료한다.
6. 일반 **번개 원소(`element_lightning`)의 감전/주기적 방전**과 독립적인 일회성 **연쇄 공격**이다. 원소 전파 제한을 임의로 해제하거나, 연쇄 단계마다 별도의 외부 명중 연결을 무제한 재발동하지 않는다.
7. **명중 후(`impact`)를 마법공예 메아리식 쿨다운 후속 재발동으로 교체하는 기존 승인**과 충돌해서는 안 된다. 체인 자체의 내부 명중을 별도 `impact` 후속 주문 발사로 혼동하지 않는다.

## 미확정 · 다음 구현에서 별도 정책 필요

- **추가 대상 4명 또는 5명**을 어떤 기준으로 선택하는지(확률/강화/다른 조건), 최초 벼락이 다수 적에게 명중 시 체인 생성 수, 탐색거리/타겟 우선순위, 다음 타깃 부재/사망/보스의 처리.
- 각 전이 피해·감쇠율 유무·전이 속도/시각 효과·원소 상태 중복, 다른 보조·연결과의 합성 및 성능 상한.
- 기존 `thunder_seal` ID, 발견 기록, 보상/훈련장/도감 이관 방식 및 설명문.
- **코드 현재 상태:** `scripts/magic_catalog.gd`에는 여전히 구형 천둥 인장 이름/설명이, `scripts/magic_extensions.gd` `impact()`에는 `cloud(...,"seal")` 분기가 존재한다. **설계 문서만 갱신**, 실제 삭제/연쇄 구현·테스트는 별도 요청에서 수행.

## 최소 구현 완료 조건 (이번에는 수행하지 않음)

- 구형 인장 장판 제거, 다른 `thunder`·`impact`·`element_lightning`·`judgement` 등에 불필요한 영향 없음.
