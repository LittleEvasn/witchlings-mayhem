## 사용자 채용안

1. **Magicraft(마법공예)를 1순위 디자인 레퍼런스로 채용.** 큰 아이콘·이름 → 역할(공격/보조/연결/완성형/유물)·현재 강화 단계 → 실제 핵심 효과/수치 → 발동·적용 조건/예외 → 필요한 보충 설명의 **공통 정보 카드** 구조. 원작 마나·희귀도·점유 슬롯·원본 이미지/문구/판정 규칙 등은 복제하지 않음.
2. **같은 정보 모델을 작은 호버와 큰 상세 패널에 공유.** 전투 중 가방/오브는 화면을 방해하지 않는 짧은 툴팁. 작업대에서는 고정 상세(실제 강화 전후와 가격·조건 포함), 보상에서는 선택 결과·차이, 도감에서는 발견 정책·단계별 비교, 실험 기록에서는 저장된 내용만 읽기 전용으로 제공.
3. **마법 역할별 내용 분화.** 공격: 실제 타격·피해·반복·지속/조건. 보조: 실제로 바꾸는 효과와 적용 공격·경계/예외. 연결: 앞 공격의 어떤 사건으로 후속 공격을 발동하는지. 완성형 합성: 효과 및 추가 강화 불가. 유물: 발동 조건·수치·예외, 장단점 분리.
4. **보조 참고 레퍼런스의 역할:** Backpack Battles = 실제 영향을 받는 슬롯/조합의 시각적 연계 강조, Brotato = 줄 단위 수치 가독성·이득/손해 대비, Slay the Spire = 유물 설명 간결화, Noita = 실제 존재하는 시전/효과 수치의 명료한 표기.
5. **정확한 동작과 숫자 우선.** `Spells.definition()`, `Spells.modifier_token_text()`, 조합 컴파일/진단 결과, 마법 단계, `Relics.definition()` 및 실제 현재 런 수치를 근거로 표시. 강화는 기본~+3을 지키고 완성형에는 추가 강화가 없음을 정확히 표기. 유물 등급은 원본 게임 코드에서 별도 확정되지 않았으므로 임의 생성 금지.
6. **실제 적용 슬롯 하이라이트**는 채용 방향이지만 **1차 필수 구현으로 확정하지 않음**. 향후 실제 컴파일·진단이 적용한다고 판정한 공격/연결 슬롯만 강조. 단순히 오른쪽에 있는 모든 슬롯을 강조하거나 효과가 적용된다고 주장하는 행위 금지.
7. **상쇄/비작동 경고 연계:** [기존 사용자 확정 노랑(상쇄)/빨강(작동 불가) 규칙](2026-10-30-magic-warning-severity.md)을 존중. 각 툴팁에서 일반 마법 정보와 해당 슬롯의 실제 경고 사유·유지되는 효과를 함께 볼 수 있게 설계. 노랑 경고로 정상 동작/장착을 차단하지 않음. 세부 진단·복합 경고 처리는 구현/검증 단계에서 실제 판정에 맞출 것.
8. **기존 05 작업대 / 04 발견 도감 / 06 결과 / 08 실험 기록 / 11 유물 상세**에서 동일한 아이콘·정보 해석 규칙 활용. 화면별 정보량은 달라도 동일한 마법·유물의 기본 사실은 일치.
9. **유물 플레이버 텍스트와 효과를 구분.** [28종 유물 설명문 초안](../reports/2026-10-31-relic-flavor-texts-28-draft.md)은 아직 선택·게임 데이터 연계가 확정된 콘텐츠가 아니므로 현재 구현된 유물 효과나 획득 자산으로 오인하지 않음. 장식/서사는 실제 승인 문구만 사용.

## 구현 및 검증 경계

- **이번 승인에 포함되지 않음:** 툴팁별 정확한 픽셀 크기·아이콘·텍스처·최종 색상, 1차부터의 적용 슬롯 하이라이트 필수화, 유물 새 희귀도 규칙, 새 마법 효과/계산식/경제 변경, 미발견 도감 세부 공개, 새 상용 에셋 구매·원본 그래픽 이식.
- **미실시:** 신규 Godot 카드 컴포넌트 작성·테스트, 마우스/키보드 포커스·드래그 비간섭 점검, 화면 경계 보정/1280×720·1600×900·1920×1080 렌더, 원작 최신판 직접 실행.
- 구현 시 반드시 **유물의 현재 런 동적값**(보유 마석·시전 횟수·보호막 등)을 도감의 일반 정보 또는 과거 런 기록에 당시 값처럼 표시하지 않을 것. 원본 조사 보고서의 P1~P5 작업 순서와 검증 체크리스트를 유지.
- **이번 결론은 UI 설계 승인**이며, 코드 적용 및 사용자 최종 시각 검수 완료가 아님.
