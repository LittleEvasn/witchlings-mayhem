# Magic60 검증 보고서

## 범위와 결과

- 검증 기준: 작업 시작 HEAD `b5a8530b0be72707d7c9ddd0c12e028d4c6b21c2`, Godot `4.6.2.stable.official.71f334935`. 총괄이 작업 중 `.gd.uid` 메타데이터만 담긴 HEAD `71f9ec5`로 이동했다고 알렸으며 게임 소스는 동일하다고 확인했다.
- 사용자의 최신 요청은 **실측과 수정 위치 진단**이다. 제품 코드는 수정하지 않았다. 하네스와 결과 JSON/로그는 `artifacts/`에만 기록했다.
- 현역 목록 60종은 36공격·20보조·4연결로 카탈로그 수가 일치했다. `magic60_test` 808/0, `connector_scope_test` 181/0.
- Godot 실제 컴파일 입력 835,520개: 순서쌍 3,600, 공격×보조 기본/강화 1,440, 공격×보조×보조 기본/강화 28,800, 공격×연결×공격 5,184, 3단 체인 746,496, 시드 고정 8칸 50,000. 이 입력 합계는 전투 성공 수가 아니다.
- 공격×보조 1,440개를 고정 60Hz에서 각 10초 자연 진행했다: 모두 컴파일·발사, 1,384개에서 유효 피해 관찰, 1,022개에서 정상 종료 표식, 0개 해석 불가. 발자국 공격 표적을 경로에 두지 않은 55개와 냉기 조준 범위를 벗어난 1개는 `no_damage`로 분리했다. 표적 재배치 검증에서는 발자국 80개 중 일반 경로 68개가 실제 피해, 공전/궤도잔영 8개가 P0 결함, 낙하 4개는 뒤따른 별도 4/4 착지 검증에서 모두 피해를 냈다.
- 연결 5,184개는 실제 런타임 `trigger`에 합성 사건 6,480개를 넣어 6,480회 관측했다. 이는 이벤트 주입 검증이고 자연 충돌/만료가 5,184개 모두 일어났다는 뜻이 아니다.
- 4오브 스트레스는 300 적, 240프레임, 9배치, 공격 36종 전체를 포함했다. 기능 계측 실패는 0, `*_blocked` / `zones_evicted`는 0이었다. 성능 기준은 별도 판정: 60fps에 해당하는 CPU 16.667ms 목표 대비 최악 batch p95 189.331ms, 최대 315.961ms, 같은 네 레시피 반복 p95 125.285/148.539ms로 `fail_observed`. 실제 렌더 FPS나 GPU 비용으로 환산할 수 없다.

## 성능 이상 징후

최악 배치 4개 레시피는 `clock_satellite`, `cold_flame`, `collapse_vortex`, `disintegration`이며 각 오브에 `echo@3 + split@3`이 붙었다. 300 stationary enemies, 240 measured frames에서 9-batch 2번의 p95는 189.331ms, max315.961ms였다. 같은 네 레시피 2회 반복은 mean/p95/max 각각 61.61/125.285/233.338ms, 72.47/148.539/323.647ms였고 프레임의 208–222/240이 16.667ms를 넘었다. 반복에서도 높아 초기 로딩 단발 스파이크로만 설명되지 않는다. 이는 headless CPU 기준이며 GPU 렌더 FPS는 측정하지 않았다.
