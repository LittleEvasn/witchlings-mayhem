## 1. 지금의 문제와 목표

현재는 '마법 조합 전투가 작동하는 시제품'을 지나 '한 게임으로 이어지는 제품 경험'을 만들 차례다. 사용자는 조합의 재미를 확인했지만, 제작이 전장을 가리는 별도 페이지처럼 느껴진다고 평가했다. 기능을 추가하는 것과 게임 경험을 완성하는 것을 구분한다.

권고하는 중심은 **한 실습장에서 사고를 수습하며, 그 자리에서 주문을 고치는 게임**이다. 타이틀·캐릭터 준비·전투·제작·결과의 화면 문법을 통일한다. 새 맵·기본 주문 대량 추가·Cubism 재개를 이 작업에 섞지 않는다.

### 코드에서 확인한 현재 상태

| 영역 | 실제 상태 | 아직 없는 것 또는 문제 |
|---|---|---|
| 마법 | 공격9·보조7·연결2, 수동0~3강, 공격 완성합성9 | 보조·연결 최종합성은 없음 |
| 제작 | `crafting_board.gd`의 좌/중/우 3영역, 1392×846 창 | 논리1600×900에서 약87% 폭/94% 높이. HUD 숨김·전역 음영 때문에 전장과 단절 |

| Live2D | 내보낸 루미 모델/모션 확인, 플러그인 소스만 준비 | 사용자가 공부 후 진행하기로 보류. 게임 연동 없음 |

전투 시간은 최신 코드의 60/75/90/105초, 보스 목표120초·상한150초다. 제작 시간은 무제한이다. 이 문서에서 시간을 다시 바꾸지 않는다.

## 2. 에셋 때문에 마법을 폐기하지 않는 제작 순서

'에셋을 보면서 디자인'은 제작 가능성을 확인하는 데 유효하다. 그러나 상품에 있는 불꽃·폭발만 골라 마법의 행동까지 결정하면 다른 역할을 가진 주문이 줄어든다.

권고 순서:
1. 플레이 역할/판정/움직임을 짧게 정의한다. 예: 느린 탄의 접촉 폭발, 돌아오는 호형 공격, 적을 모으는 지속 영역.
2. 발사·이동·명중·지속·종료에 어떤 그림이 필요한지 나눈다.
3. 기존 무료 팩·구매 후보의 공개 예시로 충족 여부를 확인한다.
4. 크기·색·회전·재생속도·중첩으로 맞출 수 있으면 원본 부품을 재활용한다. 식별성은 실제 게임 크기에서 판단한다.
5. 핵심 모양이 없는 경우 별도 에셋을 찾거나 외형을 조정한다. 역할이 재미있는데 정확히 같은 이름의 그림이 없다는 이유만으로 폐기하지 않는다.

보조 구체는 대부분 공격의 생성 패턴/표적/반복을 바꾸므로, 보조마다 전용 전투 애니메이션을 새로 살 필요는 없다. 대신 UI 아이콘과 결과를 구별하는 짧은 피드백이 필요하다.

## 3. CartoonCoffee의 세 형식과 구매 판단

2026-10-27 판매 페이지 확인. USD 표시이며 환율·세금·결제 단계 가격은 별도다.

| 스크린샷 상품 | 형식 | 우리 프로젝트 판단 |
|---|---|---|
| 왼쪽 Spritesheets | 여러 애니메이션 프레임을 한 장 PNG에 배치 | **Godot용 구매 형식으로 추천**. 현재 무료판 처리 방식과 이어짐 |
| 가운데 Unity Prefabs | Unity 파티클/머티리얼/설정을 포함한 Prefab | 우리 Godot에서 그대로 재생 불가. 이 형식은 구매하지 않는 쪽 권고 |
| 오른쪽 PNG Sequences | 한 프레임씩 PNG, 상품에 MOV도 포함 | Godot에서 사용 가능. 영상 작업·프레임 편집에는 유용하지만 현재 파이프라인에서는 우선순위 낮음 |

세 개를 모두 살 필요가 없다. 같은 대분류 효과가 다른 작업 형식으로 제공되는 상품군이며, 개별 변형 파일까지 완전히 같은지는 보장하지 않는다. 판매 페이지도 일부 변형 미포함을 경고한다.

- 최종 라이브러리로 하나를 산다면 **Ultimate Cartoon VFX MEGA PACK — Spritesheets** 권고. 현재 할인 표시 $98(정가 $200). Essentials/검 베기/불/번개/물/바람의6개 묶음이 다운로드 목록에 있다. https://cartooncoffee.itch.io/megapack-spritesheets
- **Cartoon VFX Essentials — Spritesheets**는 별도 상품 $59.99이며 검 베기 보너스가 있다. Mega Pack과 같은 상품이 아니다. https://cartooncoffee.itch.io/deluxe-spritesheets
- 예를 들어 Essentials($59.99)+번개팩($24.99)은 $84.98다. Mega와 차이는 $13.02지만, 예산을 늘리라고 강제하는 근거는 아니다. 예산이 Essentials 수준이면 무료판과 함께 범위를 제한하는 쪽이 낫다. https://cartooncoffee.itch.io/lightning-spritesheets
- **구매 시점은 아래 대조표를 채운 뒤**로 권고한다. Mega에도 서리·가시·꽃 마법의 최종 외형이 모두 있다는 증거는 없다. 큰 팩을 샀다고 모든 주문의 시각 문제를 해결했다고 판단하지 않는다.

### 사기 전에 무엇을 볼 수 있나

Essentials와 번개 제품 페이지에는 공개 WebGL 미리보기, 스크린샷/GIF가 있다. 공개 GIF는 실제로 프레임을 열어 별빛/폭발 등 모양을 확인했다. 브라우저 데모 존재와 주소는 확인했지만 실행·조작하지 않았다.

- Essentials: https://cartooncoffee.itch.io/deluxe-spritesheets (페이지 안 미리보기)
- 직접 데모 주소: https://html-classic.itch.zone/html/9809859/Deluxe/index.html
- 번개: https://cartooncoffee.itch.io/lightning-spritesheets
- 직접 데모 주소: https://html-classic.itch.zone/html/9125677/Lightning/index.html

구매 후 파일 목록에 GIF/MP4 ZIP이 나오는 것은 그 ZIP이 구매 전 무료 다운로드된다는 뜻이 아니다. 공개 예시로 분위기·일부 행동은 판단할 수 있지만, 전체 파일명/모든 변형/탑다운 방향 적합성/우리 게임 성능까지 확인한 것은 아니다. 문의가 필요하면 제작자에게 물을 항목을 정리하고, 사용자 허락 없이 연락하지 않는다.

## 4. 제작 UI: 전장 위의 도구함

현재 창은 폭1392/논리1600=87%를 덮는다. 창을 조금 투명하게 하는 것만으로는 해결되지 않는다. 게임 화면을 보여주면서 도구를 꺼내는 형태로 바꾼다.

- 논리1600×900 기준 오른쪽 **520폭, 약32.5%**를 첫 시안으로 사용한다. 기존416폭보다 넓혀 슬롯을 지나치게 줄이지 않는다. 남는 전장 폭은 약65% 이상이다.
- 전역 어두운 막을 제거하고 체력/웨이브 HUD를 유지한다. 패널 배경만 불투명에 가깝게 해서 글자 가독성을 확보한다.
- 상단에 두 오브×6칸을 고정한다. 슬롯은 논리64~70px 이상을 시작값으로 하고, 이름은 축약/툴팁, 강화는 작은 배지로 표시한다.
- 중앙은 **가방 / 제작 / 합성 도감** 탭. 전체 목록·상세·가방을 동시에 다 펼치지 않는다. 분류/선택/스크롤은 탭을 오가도 유지한다.
- 하단은 선택한 구체의 '현재 행동 → 강화 후 행동', 소비량, 실행 버튼만 보여준다. 긴 설명은 접거나 툴팁으로.
- 준비 상태에서만 마석 강화·합성·시험·준비완료를 제공한다. 전투 때는 같은 외형의 개인 창에서 비정지 조합 편집을 유지한다. 창 열림과 세계 진행 상태를 다시 섞지 않는다.
- 시험은 기존 시간·경제 분리를 유지하면서 왼쪽 전장에 표적/발사를 보여준다. 시험 때문에 제작 시간을 소비하거나 적 웨이브를 진행하지 않는다.
- 창 위 입력은 공격/이동 판정으로 새지 않게 하되 이동·회피 키는 기존 결정을 따른다. 드래그 중 회피/위협 대응도 검수한다. 카메라나 적 예고가 패널에 가려지면 레이아웃을 수정한다.

정적 배치 시안: `artifacts/crafting-drawer-proposal.png`. 기존 게임 캡처에 배치만 합성한 설명 그림이며, 게임 반영/입력 검증/최종 GUI 아트가 아니다. 글리프·이름은 기존 아이콘을 유지하기 위한 자리 표시다.

### GUI 에셋도 꼭 사야 하나

필수는 아니다. 현재 답답함은 화면 점유·정보 우선순위·화면 전환 문제이며 패널 그림을 사는 것만으로 해결되지 않는다. Godot Control/Container/Theme로 배치와 반응을 정한 뒤, 같은 화풍의 패널/버튼/아이콘을 한 세트로 입히는 순서가 낫다. 우선순위는 주문/유물 식별 아이콘, 캐릭터 초상, 적 실루엣, 전투 VFX다. GUI 상품은 배치 확정 전 구매하지 않는 쪽을 권고한다.

## 5. 보조·연결 완성합성 제안: 9종

전부 **신규 제안/미구현**이다. 기존 일반 보조의 오른쪽 적용 범위, 연결 후속 독립시전 금지, 첫 유효 명중1회, 강제 정리 시 연결 미발동은 유지한다. 아래 합성 하나가 여러 슬롯을 요구하지 않으며 결과도 한 칸이다.

재료는 기존 공격합성과 맞춰 서로 다른 두 +3 실물과12마석을 첫 시험값으로 사용한다. 결과는 완성형이므로 추가 강화하지 않는다. 부모의 모든 수치를 합산한 것이 아니라 새로운 행동으로 완성된다. 일반 보조 중복과도 구별한다. 가격/효율은 미측정 제안이다.

### 모든 공격에 붙일 때의 공통 의미

- 갈래·반복은 **원래 공격 패턴의 생성/재생**을 나누고, 원래 공격을 전혀 다른 공격으로 바꾸지 않는다. 별빛탄의 기본6방향·위성의 고유개수에 무조건 다시3×3을 곱하지 않는다.
- 추적 계열은 **발사 방향/새로 놓는 위치/기존에 움직이는 공격의 목표**를 바꾼다. 이미 고정된 불장판을 이동 투사체로 만들거나 무조건 화면 끝까지 따라가게 하지 않는다.
- 관통·연쇄 계열은 **진행 경로의 추가 적/타격 뒤 주변 파급**이다. 단일 적만 남아도 기본 주문은 정상 동작한다.
- 크기·응축은 **실제 판정과 보이는 외형**을 함께 키운다. 느린 공격·짧은 틈을 남기는 대가는 명확하게 보여준다.
- 이중 사건은 '각 사건1회'라는 새 연결의 명시된 성질이다. 일반 명중 후가 여러 번 발동하도록 몰래 바꾸는 것이 아니다. 후속에 또 연결이 있으면 각 후속 가지에 예산이 상속되어 같은 배율을 재곱하지 않는다.
- 영역형 추격 관통은 단계별 새 설치만 바뀐다. 불장판처럼 한곳에 고정되는 공격은 기존 위치를 유지하고, 다음 설치 위치가 실제로 바뀌는지 설명/시험에서 드러나야 한다. 공통 의미를 지킬 수 없으면 새 합성을 재설계하며 조용히 무효화하지 않는다.

### 지금 코드에 바로 레시피만 넣으면 안 되는 이유

`spell_progression.gd:FUSIONS`, `spells.gd:definition`, `fusion_effects.gd`는 기존 합성을 공격으로 다룬다. 보조를 여기에 이름만 추가하면 공격 판정·기본효과·강화표가 꼬인다.

구현 때는 합성 결과에 attack/modifier/connector 종류를 명시하고, 보조 해석과 사건 연결 실행을 별도로 확장한다. `modifier_effects.gd`의 스냅샷에서 합성 기여를 한 번만 계산한다. 순차 루트/연결 자식/일반 보조 상속을 구분하며, 기록 경로·지연 예약은 웨이브/시험 정리에 함께 지운다. 장착/실물 소비/되돌리기/시험 저장은 기존 경로를 사용한다.

먼저 파상 분열·압축 거성·이중 사건3개로 기본 공격9형태를 확인한다. 이후 나머지6개를 확장한다. 첫 출시 목록의 목표로는9종을 제시하되, 테스트에서 기본 구체2칸을 완전히 무의미하게 만드는 합성은 수정한다. 코드 생성 상한으로 밸런스 문제를 숨기지 않는다.

### 기존 공격합성9개 (이미 구현)

뇌광창=별빛탄+벼락 / 초신성 정원=꽃폭탄+소용돌이 / 귀환의 달고리=부메랑+위성 / 빙결화=서리숨결+가시꽃 / 불꽃 행진=잔불+꽃폭탄 / 별서리 관문=별빛탄+서리숨결 / 천둥꽃 덫=벼락+가시꽃 / 달무리 소용돌이=소용돌이+위성 / 꽃잎 귀환=부메랑+꽃폭탄. 재료는 모두+3.

## 6. 시작·캐릭터 선택·재도전의 제품 흐름

권고 흐름:
`선택적 짧은 로고 → 타이틀 → 새 실험(캐릭터+시작 부품) → 실습장 도입 → 전투 ↔ 보상/제작 → 보스 → 결말을 포함한 결과 → 재실험/타이틀`

- **게임사 로고:** 실제 팀/브랜드가 정해졌다면 약1초, 건너뛰기 가능. 로고가 있어야 게임이 되는 것은 아니며 허구 회사/불필요한 로딩 페이지를 만들지 않는다.
- **타이틀:** 실습장·인물·제목·짧은 분위기. 새 실험 / 이어하기(유효 저장이 있을 때) / 도감 / 설정 / 종료. 긴 개발 설명은 도움말로 옮긴다.
- **새 실험:** 캐릭터와 시작 부품을 한 화면에서 정한다. 현재 실제 사용 가능한 캐릭터는 루미1명이고, 기존4꾸러미를 네 캐릭터인 것처럼 표시하지 않는다. 다른 마녀는 추가 구현 후 선택 가능하게 한다.
- **도입:** 첫 실행은 짧게, 반복은 건너뛰기. 정적인 글 페이지를 매번 하나 더 통과시키지 않고 같은 실습장 위 짧은 대사/조작 안내로 연결한다.
- **결과:** 결말/새 단서/이번 오브·유물/재시작 버튼을 한 흐름으로 합친다. 같은 시작/다른 시작을 쉽게 다시 고른다.
- **도감:** 주문/합성/유물의 발견·효과·관련 레시피와 마녀 단서를 기록한다. 기록 화면과 처음부터 분리된 방대한 백과사전을 만들지 않는다.
- **이어하기:** 현재 없으므로 별도 저장 기능을 먼저 구현한다. 초기 권고는 제작 구간 체크포인트 저장/복원이다. 두 오브, 강화 실물, 재고/제작안, 마석, 유물, 웨이브, 랜덤 상태를 같이 저장한다. 전투 도중 정확한 프레임 복원은 후순위이며 저장 경계를 UI에 알린다. 경제 중복 소비/리롤 재추첨/기록 중복 반영을 검증한다.

큰 별도 허브맵/상점 NPC/시설 이동을 지금 먼저 만드는 것은 권고하지 않는다. 같은 실습장이라는 일관성은 화면/카메라/패널/대사만으로 먼저 만들 수 있다.

## 7. 이야기 담당과 정본

원작 `../마녀들의 사고현장.md`에 이미 네 친구의 성격·사고 원인·각 결말·교정 장치/진엔딩 방향이 있다. 설정이 없는 상태가 아니라 게임의 행동/해금/화면에 연결된 분량이 적은 상태다.

지금 상시 스토리 직원을 추가하지 않는 쪽을 권고한다. 기존 아이디어 담당에게 한 번의 한정 작업으로 **장면 목록·짧은 대사·해금 기록**을 맡기고, 총괄이 구현과 연결한다. 네 캐릭터 분기·진엔딩 집필을 시작할 때 별도 읽기/집필 담당이 필요해지면 그때 역할을 추가한다. 매 수정마다 둘이 중복 회의하지 않는다.

정본에는 다음5개만 먼저 고정한다.
1. 네 명이 무엇을 대신하려고 조수를 만들었는가: 숙제.
2. 각자가 무엇을 빠뜨렸으며 왜 폭주했는가: 원작의 네 결함을 유지.
3. 왜 전투 사이에 제작하는가: 실패작 마석으로 즉석 대응.
4. 왜 실험을 중단하면 구체/유물이 사라지는가: 실험/실패작에 종속된 마석이라는 현재 설정.
5. 무엇이 다음 판에 남는가: 단서·도감·설계도/캐릭터 해금. 영구 화력 인플레이션을 자동 추가하지 않는다.

원작의 마나·소환형 캐릭터 액티브는 현재 마나/소환 금지와 충돌하는 미구현 구상이다. 캐릭터 차별화 작업 때 별도 조정하고 이번 계획을 근거로 그대로 구현하지 않는다. 교수님은 실패 시 직접 수습하고 혼내며, 성공 시 '너희가 치워'라고 한다는 원작 톤을 지킨다.
