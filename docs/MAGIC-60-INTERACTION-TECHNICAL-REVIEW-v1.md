### D. Magicraft 확인 한계
공개 검색에서 해당 상용게임의 공식 엔진 소스는 확인하지 못했다. 따라서 '마법공예의 공전+낙하 우선순위가 코드상 이렇게다'라고 확정할 수 없다. 같은 이름의 Minecraft/Bukkit 프로젝트는 이 게임의 소스가 아니다.
보고서의 위키·가이드는 원작 플레이 설명을 보조하는 자료이며 공식 소스와 구분한다. 이번 권고 규칙은 아래 우리 게임용 설계다. 원작을 실행하지 않았다.
참고 검색의 [제작자 공지 목록](https://steamcommunity.com/app/2103140/announcements/)도 발견했으나 특정 복합 마법의 내부 처리 순서를 증명하지 못했다.

## 2. 현 코드에서 재사용할 것과 그대로 쓰면 안 되는 것
- spells.gd::compile: 빈칸/부분진단/연결 범위/순차 roots 재사용. 그러나 modifier/connector 이외 kind를 공격으로 처리한다. element를 새 kind로 추가만 하면 잘못 공격 분기로 들어간다. UI 분류는 원소로 나누되 실행은 modifier 하위 원소 연산자로 연결하는 안 권고.
- modifier_effects.gd::resolve와 spell_runtime.gd::PROFILE: 고정7보조·5이동탄 대응. 새 원소/낙하/공전/분열/궤적은 정의만 추가해도 실행되지 않는다.
- spell_runtime.gd::emit/trigger: 위력 스냅샷·연결 위력·후속 데이터·실제 생성 경로 재사용. 특정 공격 전용 분기는 어댑터로 분리할 것.
- spell_runtime.gd::update_projectiles: 현재 부메랑은 별도 호형 경로, 나머지는 유도+직진. 일반 이동모드 합성기는 없다.
- spell_behaviors.gd::special/update_orbits/update_strikes: 서리는 즉발 부채꼴, 위성만 자체 공전, 낙뢰는 예약 지점. 이것을 모든 공격용 공전·지속 광선·낙하로 취급하면 안 됨.
- spell_behaviors.gd::hit/state_for: 현재 냉기·파쇄·적별상태 기반은 있지만 화상/독/방전 전파와 동등하지 않음.
- fusion_effects.gd::intrinsic는 현재 자식의 fusion/echo/fan/bounce/next 등을 제거해 재귀를 막는다. 전부 상속으로 뒤집으면 위험. 단순 bool 제거 대신 출처와 파생 권한으로 명시할 것.
- generation은 런타임 초기화/취소 세대(epoch)다. 분열 자손의 세대수와 다르다. _depth는 연결 깊이. lineage/cast_id는 원인 추적. 이 세 개를 하나로 합치면 안 된다.
- game.gd::nearby/nearest_enemy는 이미 공간 그리드를 사용한다. 새 부착효과가 매번 모든 enemies를 순회하지 않게 유지.
- economy::fusion_quote/게임 fusion_placement·claim_fusion의 수량 트랜잭션/양오브 정리·가방 정책 재사용. PRICES/도감/강화표/설명/시험/체크포인트 검증도 새 ID목록과 함께 옮겨야 함.

### 생략하면 안 되는 세부사항
- 정상 종료에는 수명 만료뿐 아니라 관통소진/정상착탄·귀환 등 공격별 자연종료가 들어간다. 현재 update_projectiles는 소진에도 expire를 보낸다. '정상 만료'라는 문구로 수명끝에만 제한하면 현동작이 바뀜.
- clear/런종료/시험초기화/장착재컴파일/예산퇴출/화면밖제거는 별도의 취소. 현재 장판퇴출은 evict_zone, 잔불 end_path(false), 일반탄 bounds제거에는 expire가 없다. 이 분리를 유지.
- 시간연결의 소스가 시간도래 전에 정상소멸하면 '남은 예약취소'를 권고, 같은프레임은 정해진 사건순서에 따라 하나만 실행. 이중사건 같은 명시복합은 별도권한. 발사즉시·명중·종료 중 어느시점부터 시간재는지 UI에 표시.
- 무조건 효과가 안 먹는 공격에 조용히 끼우게 하지 않는다. 기하·위치·방향·접촉수의 공통 의미로 변환한 결과를 설명하고, 불가시 해당칸에 이유. 좁은 공격종류 전용 예외 남발은 피한다.
- 보조는 기존 확정대로 다음 연결에서 범위가 끝남. 원소도 이 범위를 따른다. 후속에 붙이려면 연결 뒤에 장착한다. 부모속성을 자동으로 후속에 부여하는 것은 현재 사용자규칙과 다름.
- 보조 배치 순서가 의미를 갖는 경우와 없는 경우를 명시: 범위/연결·공격순서는 유의미, 같은 노드의 낙하(생성단계)+공전(평면궤도)은 단계가 달라 좌우를 바꿔도 동일. 원작과 동일하다는 주장 아님.

## 4. 최소 공통 구조 권고
거대한 범용 프레임워크/원작 엔진 전면 복제는 필요 없다.
1. SpellProgram: 고정슬롯→root/후속트리·연결지역 보조·진단. 기존 compile 확장.
2. SpawnPlan: 위치/낙하예고/앵커/착지시점. 속도와별개.
3. MotionState: native(직진·호형·고유위성), anchor모드, orbit로컬오프셋, steering표적. 위치를 쓰는 업데이트는 한곳.
4. HitPolicy: point/segment/cone/area/beam + 고유 간격·visited. 모양 판정은 공격별 작은 어댑터.
5. CastContext: epoch,cast_id,instance_id,owner_orb,source_slot,depth,parent_id,spawn_kind,damage_factor,proc_mass,flags. epoch와파편세대 분리.
6. EventQueue: impact/end/timer를 한번소비, 취소시예약폐기, 연결후속은 컴파일된트리만 실행.
7. StatusRuntime: 적별상태·시간예약·공간그리드 검색. 피해/상태전파/사용자트리거를 구분.
동일공격체의 위치를 공전·추적·부메랑 코드가 번갈아 덮지 않게 한다. 관통·도탄 판정도 동일 명중해결 경로에서 처리한다.
새 파일은 motion/status/event 정도만 분리하고 기존 runtime/behaviors를 전부 폐기하지 않는 최소변경안 권고.

## 7. 증식·성능·가시성
현재확인 상한: projectile180, zone256, echo96, emit/tick64, depth6, strike128, orbit전체128/프로그램32, support예약96, fusion예약128.
