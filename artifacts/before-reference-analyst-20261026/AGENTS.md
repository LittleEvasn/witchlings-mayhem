# Witchlings’ Mayhem — 개발 운영 규칙

이 파일은 이 프로젝트에만 적용한다. 사용자의 최신 지시가 우선한다.
프로젝트: `C:/Users/user/Desktop/Witchlings' Mayhem/witchlings' mayhem`.
DuckGame, MageGame 및 다른 프로젝트는 수정하지 않는다.

## 기본 작업
- 기존 변경을 먼저 확인하고 보존한다. Git이 없으면 편집 대상 기존 파일을 `artifacts/`에 백업한다.
- `docs/PROJECT-HANDOFF.md`의 현재 상태부터 읽고, 작업에 관련된 코드·문서만 추가로 읽는다. 문서와 코드가 다르면 둘을 구분한다.
- 확정 규칙을 임의로 바꾸지 않는다. 일반적인 구현 선택은 스스로 진행하고, 재미·경제·조합 규칙 변경은 제안으로 분리한다.
- Godot API/엔진 동작이 불확실하면 설치 버전의 공식 문서를 확인한다. 모든 작업에서 문서 전체를 읽지는 않는다.
- 이번 변경의 관련 검사만 수행한다. 자동 검사·성능 측정·실제 화면 확인·재미 평가는 구분한다.
- 사용자가 중단한 작업을 새로운 작업을 핑계로 재개하지 않는다.

## 비용을 제한한 에이전트 사용
사용자는 총괄이 출시까지 작업을 배정하고 결과를 검토하는 운영을 승인했다. 업무 요청마다 사용자에게 모델을 고르거나 지시문을 옮기게 하지 않는다.
- 게임 개발 업무는 시작 전에 Claw-Empire 업무 카드에 등록한다. 도구: `python C:/Users/user/Tools/claw-empire/local-run/codex-work.py`; 사용법은 그 폴더의 `WORKFLOW.md`를 읽는다. 일반 질의응답은 업무 카드를 만들 필요 없다.
- 위임 전 담당 역할과 요청 모델을 기록하고, 호출 후 실제 세션 ID를 연결한다. 실행 모델은 관찰 DB에서 확인한 값만 보고한다. 요청 모델과 실행 성공을 혼동하지 않는다.
- 완료·검토·보류·실패 및 결과 파일을 카드에 남긴다. 사용량 제한은 보류와 사유로 기록하고 불필요하게 반복 호출하지 않는다. 보드 연결이 실패하면 등록 성공으로 보고하지 않는다.
- 최종 보고에는 응답자(총괄), 실제 참여한 담당자, 작업/결과/미완료 이유를 간단히 표시한다. 현재 채팅은 관찰 연결에서 개발책임 직원에 매핑된다. 별도의 상시 총괄 AI를 중복 생성하지 않는다.
사용자는 이 프로젝트에서 아래 조건에 맞는 보조 에이전트 위임을 승인했다.
- 기본 담당자가 직접 구현과 관련 검증을 한다. 작은 수정은 에이전트를 호출하지 않는다.
- 분리 가능한 조사/재현이 충분히 크면 `wm_scout`에게 좁은 질문을 위임한다.
- 수량 소비·다단계 연결·상태 복원 같은 위험한 변경에 독립 검토가 필요하면 `wm_reviewer`에게 사용자 기준과 변경 코드를 함께 전달한다. 조사·리뷰·QA를 매번 전부 호출하지 않는다.
- 구체적인 설계 충돌 또는 근거 있는 수정 두 차례 후에도 같은 문제가 반복되면 `wm_architect`에게 원인/설계 질문 하나만 맡긴다. 단순 오류에는 호출하지 않는다.
- 기본 모델: 책임자 Sol 6.1 low (필요 시 medium/high), 조사 Luna high, 검토 Sol 6.1 high, 자문 Astra low. 모델 변경은 실제 도구/세션에서 지원될 때만 적용했다고 보고한다.
- 동시에 보조 한 명까지만 실행한다. 완료된 보조가 슬롯을 점유하면 지원 도구로 종료하고 다음을 호출한다. 종료 기능이 없으면 가능할 때 기존 보조를 재사용하거나 담당자가 처리하며 동시 제한을 우회하지 않는다.
- 보조의 재위임은 금지한다. 보조는 기본적으로 읽고 보고한다. 책임자가 유일한 코드 편집자다.
- 새 보조에 전체 대화를 복제하지 않는다. 목표, 확정 규칙, 관련 파일, 질문, 완료 조건, 허용 검사만 전달한다. fresh/no-history 호출을 사용한다.
- 사용자 정의 역할 호출 기능이 없으면 `.codex/agents/<역할>.toml`을 읽고 해당 모델·추론·지침을 명시하여 일반 subagent를 호출한다. 자동 로드로 가장하지 않는다.
- 조사/리뷰의 읽기 전용은 지침이며 별도 보안 샌드박스를 뜻하지 않는다. 시험 실행·에디터 제어는 책임자가 맡고, 명시적으로 넘긴 검사만 보조가 실행한다.
- 보조의 반환은 결론, 파일/줄 근거, 수행한 검사, 미확인 사항으로 제한한다. 반복 회의와 원문 로그 전달을 피한다.
- 사용량·시간·재작업을 `docs/AGENT-OPERATIONS.md`의 간단한 기록에 남긴다. 토큰 정보가 없으면 미제공으로 기록하고 추정치를 실측처럼 쓰지 않는다.

## 현재 게임의 주요 불변 조건
- 1인 플레이, 마우스 조준·자동 시전. 오브 2개 × 6칸.
- 독립 공격은 좌→우 순차 시전. 일반 보조는 같은 오브의 오른쪽 공격들에 적용. 다단계 사건 연결·중복 보조 허용, 이중 적용 금지.
- 강화 0~4. 둘 다 강화면 합산; 하나 이상 기본이면 높은 쪽+1. +4 초과는 소비 없이 차단. 연결 구체는 강화하지 않는다.
- 웨이브→유물 보상→마석 제작→다음 웨이브. 시험 발사는 전투 시간·경제·임시 상태와 분리한다.
- 마나·소환·멀티를 임의로 추가하지 않는다. 기존 마법·합성·드래그·되돌리기·유물 기능 보존.
- 최신 상세 수치는 구현 코드 및 handoff에서 연결하는 최신 문서로 확인한다. MageGame의 옛 규칙을 가져오지 않는다.
